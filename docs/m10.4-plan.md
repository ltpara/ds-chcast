# M10.4 — 管理通道、打洞审计与注册防滥用

RustDesk 开源 hbbs 除注册/会合/中继外，还有一组运维面能力：注册请求按 IP
计数并在异常时拒绝（`check_ip_blocker`）、记录打洞请求供事后排查
（`record_punch_req`）、运行时可切换 `ALWAYS_USE_RELAY`
（`always-use-relay`），以及只接受回环连接的明文管理命令通道
（`check_cmd`/`listen_console`）。chast 的启动参数已覆盖等价开关，但缺少
运行期管理、审计与注册防滥用。本阶段对齐这四项，协议仍为 v23。

## 1. 缺口

| hbbs | chast（本阶段前） | 本阶段 |
| --- | --- | --- |
| 注册按 IP 计数，超过 30 次/窗口或 300 个不同 ID/天拒绝 | 仅 HTTP 令牌桶（面向所有路径） | `internal/abuse` 注册阻断，按观察 IP 计数并区分速率与 ID 洪泛 |
| 打洞请求环形日志，60 s 去重，可在管理通道分页查看/清空 | 只有 debug 日志，无法回看 | `internal/punchlog` 环形日志，管理通道与指标暴露 |
| `ALWAYS_USE_RELAY` 可运行时切换 | 启动参数 `--relay-only`，改配置需重启 | 原子开关，管理通道 `relay-only Y/N` 即时生效 |
| 回环管理通道（明文命令） | 只有带 server-key 的 HTTP 统计 | `--admin-listen` 只绑定回环，命令覆盖统计、主机、打洞日志、阻断表、强制中继 |

不做：不实现 hbbs 的 protobuf 管理协议；管理通道不做鉴权以外的加密（仅回环、
明文，与 hbbs 一致）；不实现 `ip-changes` 与地理中继选择；不引入外部中继
服务器进程。

## 2. 注册防滥用

`internal/abuse.Blocker` 在 `POST /v1/hosts` 的 server-key 校验、JSON 解码与
ID 合法性检查之后、公钥解析与签名验证之前执行，因此无效公钥也要先过计数，
签名错误的洪泛同样会被限速。

- 每 IP 状态：固定窗口计数与最近窗口内见过的 ID 集合。
- 速率：同一 IP 在 `--register-window`（默认 60 s）内最多
  `--register-max`（默认 30）次注册尝试，第 31 次返回 `429` 与
  `Retry-After: 1`。
- ID 洪泛：同一 IP 在 `--register-id-window`（默认 24 h）内最多出现
  `--register-max-ids`（默认 300）个不同 ID；超过后新 ID 被拒绝，已见过的
  ID 仍可续约，避免误伤共用出口 NAT 的既有部署。
- 内存上限 65536 个 IP 条目，超出时淘汰窗口最旧的条目；每次允许尝试顺带
  清理过期窗口。
- `--register-max 0` 关闭速率检查，`--register-max-ids 0` 关闭 ID 检查，
  两者都关时不创建 Blocker。
- 计数在 `/v1/stats`、`/metrics` 与管理通道可见；被拒绝时记录 warn 日志，
  但不在响应里暴露具体阈值。

## 3. 打洞请求日志

`internal/punchlog.Log` 是固定容量的环形缓冲：

- 记录字段：时间、发起方观察 IP、目标 ID、目标观察 IP。
- 与 hbbs 一致：同一 `from_ip + to_id` 在 60 s 内只记一条；检查只扫描最近
  30 条，避免大日志下的全表扫描。
- 容量 `--punch-log-max`（默认 100000，按需增长，写满后覆盖最旧），`0`
  关闭记录。`/metrics` 暴露当前条数、总记录数与去重数。
- 只在目标主机在线、会合服务准备回复双方时记录，与 hbbs 的记录点一致；
  被限速、目标离线或没有可用地址的请求不进入日志。
- 管理通道 `punch-requests`/`pr [start] [count]` 分页输出，
  `pr -` 清空。

## 4. 运行时强制中继

- `api.Config.RelayOnly` 改为 `*atomic.Bool`（nil 视为 false），
  `lookup`、`/v1/server`、`/v1/stats`、`/metrics` 都读取当前值。
- `chast-server --relay-only` 只设置初值；管理通道
  `relay-only Y|N` 立即改变后续查询的候选下发与 `nat_type`，无需重启。
- 已有连接不受影响：已完成的查询与已建立的中继/载体链路保持原状。

## 5. 管理通道

`chast-server --admin-listen 127.0.0.1:8446`（默认；空值禁用）。只接受
回环绑定，启动时校验监听地址，连接来源不是回环时直接关闭。握手与 hbbs
一致：一行文本命令（上限 1 KiB），处理后在 5 s 内写回纯文本并关闭。

| 命令 | 说明 |
| --- | --- |
| `h` | 命令帮助 |
| `stats` | 主机/身份、中继端口、UDP/TCP/共享载体流量、阻断与打洞日志计数 |
| `hosts [count]` | 当前租约（默认 20），含在线、候选、中继端口、载体链路、最近 keepalive |
| `punch-requests`/`pr [start] [count]`、`pr -` | 分页查看/清空打洞日志 |
| `ip-blocker`/`ib`、`ib <ip>`、`ib -` | 阻断表摘要、单 IP 计数、清空跟踪 |
| `relay-only`/`aur [Y\|N]` | 查看或切换强制中继 |

未知命令返回一行 `unknown command`，不返回帮助以免刷屏。

## 6. 测试与验收

自动化：

- `internal/punchlog`：记录顺序、60 s 去重、去重过期、容量覆盖、清空、
  分页边界。
- `internal/abuse`：窗口内第 31 次拒绝与窗口滚动恢复、不同 ID 洪泛只拒绝
  新 ID、ID 窗口滚动、条目上限淘汰、清空与统计。
- `internal/admin`：回环绑定校验、`h`/`stats`/`hosts` 输出、`pr` 分页与
  清空、`ib` 摘要与单 IP、`aur` 切换共享原子开关、未知命令、非回环来源
  拒绝（用可注入的 `RemoteAddr` 或监听校验）。
- `internal/api`：第 31 次注册得到 429 + `Retry-After`；已见 ID 在 ID
  洪泛后仍可续约；`/v1/stats` 含阻断与打洞计数；`RelayOnly` 原子切换后
  lookup 立即隐藏候选。
- `internal/rendezvous`/`internal/agent`：查看者请求打洞后日志出现
  `from_ip -> id@host_ip`，重复请求 60 s 内去重。
- `go vet ./...`、`go build ./...`、`go test ./... -count=1`。

### 验收标准

1. 注册洪泛在同一 IP 上被 `429` 拒绝，正常低频注册不受影响；被拒绝后窗口
   滚动可恢复。
2. 一次真实查看者打洞后，管理通道 `pr` 能看到对应条目，`pr -` 清空。
3. `aur Y` 后新查询不再返回直连候选，`aur N` 恢复，无需重启。
4. 管理通道无法从非回环地址访问；默认只监听 `127.0.0.1`。
5. 现有 M10.1–M10.3 测试与回环摘要不回归，文档记录验证结果。

## 7. 验证记录（2026-10-25，单机回环）

环境：服务器 `--http-listen 127.0.0.1:18443 --punch-listen 127.0.0.1:18444
--carrier-listen 127.0.0.1:18445 --admin-listen 127.0.0.1:18446
--relay-listen 127.0.0.1 --relay-ports 41100-41109 --advertise 127.0.0.1
--server-key testkey --offline-after 5s --register-max 3 --register-window 60s
--register-max-ids 5 --register-id-window 1m --punch-log-max 100`；主机
`chast-tunnel host --id devbox --key host-secret-123 --local 127.0.0.1:19433
--listen 127.0.0.1:19434 --keepalive 2s`；查看者 `chast-tunnel viewer --id
devbox --listen 127.0.0.1:19435 --mode auto`。

1. 注册速率：用 `regflood` 在同一 IP 上连续发起 4 次签名注册，得到
   `200,200,200,429`，第 4 次响应体为
   `too many registration attempts; retry later`。管理通道 `ib 127.0.0.1`
   返回 `127.0.0.1 count=4 window_age=0s ids=3 ids_age=0s`，摘要为
   `tracked=1 rate_blocked=1 id_blocked=0`；`/v1/stats` 的
   `registration_blocked` 为
   `{"tracked_ips":1,"rate_blocked":1,"id_blocked":0}`，`/metrics` 中
   `chast_register_blocked_total{reason="rate"} 1`、
   `chast_registration_tracked_ips 1`。`ib -` 返回 `cleared 1`。
2. ID 洪泛：`--register-max-ids 5` 的边界与“已见 ID 仍可续约”由
   `internal/abuse` 与 `internal/api` 的自动化测试覆盖；本次回环因速率上限
   先触发，未单独构造真实 ID 洪泛。
3. 打洞审计：查看者建立直连后，管理通道 `pr` 输出
   `2026-10-24T16:33:12Z 127.0.0.1 -> devbox@127.0.0.1`，`stats` 显示
   `punch_log stored=1 total=1 deduped=0`。`pr 0 1` 分页只返回该条；
   `pr -` 返回 `cleared`，`pr` 变为 `no punch requests`。重启查看者产生
   新打洞后 `stored=1 total=2`，确认清空只删除条目、保留累计计数。
4. 运行时强制中继：`aur` 返回 `relay_only=false`，`aur Y` 后
   `GET /v1/hosts/devbox` 返回 `relay_only:true`、`transport:"relay"`、
   `nat_type:"symmetric"`，无 `candidate`/`candidates`/`local_addrs`；
   `/v1/server` 同步 `"relay_only":true`。`aur N` 后同一查询恢复
   `transport:"direct"`、候选 `127.0.0.1:19434`，`/v1/server` 恢复
   `false`，服务器未重启。
5. 管理通道边界：`h` 列出全部命令，未知命令返回单行
   `unknown command`；`stats` 同时输出 UDP/TCP/共享载体、打洞日志与注册
   阻断计数；`hosts` 显示 `devbox online=true candidate=127.0.0.1:19434
   relay=41100`。用 `--admin-listen 0.0.0.0:18456` 启动第二个实例，进程以
   `admin listen "0.0.0.0:18456" must be a loopback address` 退出。
6. 自动化：`go vet ./...`、`go build ./...`、`go test ./... -count=1`
   通过；`internal/punchlog` 1.214 s、`internal/abuse` 0.039 s、
   `internal/admin` 0.109 s、`internal/api` 1.297 s、`internal/agent`
   7.825 s。协议仍为 v23，C++/Flutter 未改动。
