# M5.3 — 远端指针（原生光标）

状态：已完成（2026-10-22）
上一阶段：M5.2 系统声音单向传输已完成。
下一阶段：M5 其余体验扩展（文件传输、分辨率/帧率自适应等）。

## 目标

Desktop Duplication 从不把指针画进桌面纹理，捕获侧早已解码并缓存了指针
形状，但没有任何东西把它送到查看者，而查看者在远程控制时又把本地指针
隐藏了——结果远程指针完全不可见。本阶段把它补齐：

1. **协议 v11**：新增 `CursorUpdate` 控制消息（服务端 → 客户端），携带
   可见性、帧空间坐标、热点、53 位形状 id 与可选的预乘 BGRA 精灵。
2. **形状只发一次**：同一 `shape_id` 后续更新只有 26 字节头；位置或可见性
   没变则完全不发。
3. **传输不挡视频**：指针更新走控制流，队列满时丢弃并计数，绝不阻塞编码
   与发送循环。
4. **查看者用系统光标**：原生侧把精灵安装成 Windows 光标（`CreateDIBSection`
   + 按 alpha 生成的 AND 掩码 + `CreateIconIndirect`），经 `WM_SETCURSOR`
   生效；OS 在硬件光标频率合成，不落后、不漂移。
5. **按显示比例缩放**：按“视频在窗口中的绘制比例 × 设备像素比”缩放精灵，
   四分之一步进量化并缓存每个 (形状, 比例) 的句柄。
6. **可重复验证**：协议单元测试覆盖编解码与畸形拒绝；新增
   `chast-remote-cursor-test` 覆盖校验、句柄缓存、越界缩放与容量上界。

## 非目标

- 指针动画的时间轴平滑（只做“最新状态覆盖”，不做运动插值）。
- 指针拖影、点击涟漪等视觉效果。
- 硬件光标叠加（D3D12 元数据）路径；目前是“安装系统光标”。

## 架构

```
主机                                        查看者
DxgiCapturer
  └─ CursorDecoder: 位置/可见性/形状/热点/content_id
        │
        ▼
HostServer::publish_cursor
  ├─ 无变化 → 不发
  ├─ 新形状 → 头 + 精灵
  └─ 仅移动 → 26 字节头
        │
        ▼  QuicSession::send_cursor（非阻塞）
   控制流（与输入/剪贴板/延迟探针共用）
        │
        ▼
ViewerEngine::receive_cursor → 最新覆盖槽
        │  （精灵不进 Dart）
        ▼
ViewerBridge::ApplyCursor（平台线程，200 ms 轮询）
  ├─ RemoteCursor::Register(每个附带精灵)
  ├─ 依据 enabled/scaleMilli 激活并缓存句柄
  └─ ::SetCursor + WM_SETCURSOR 接管 HTCLIENT
```

关键决策：

- **原生安装系统光标，而不是在画面里画箭头**：远程控制时指针由本地手驱动，
  用户看到的位置必须是系统光标位置。安装成系统光标后由 OS 合成，天然与
  手的移动同频；如果在视频上叠加精灵，延迟与坐标漂移都无法避免。
- **精灵不经过 Dart**：`ViewerStatus` 只暴露 `cursorUpdates`/`cursorPending`
  两个计数。若让精灵走 MethodChannel，5 Hz 轮询每次最多要拷 256 KB，
  并且会在 UI 线程上制造无谓的分配。原生侧直接从 `ViewerEngine` 取。
- **掩码来自 alpha，而不是黑色像素**：Flutter 引擎自带的
  `createCustomCursor/windows` 把纯黑当作透明，会把描边指针的黑边抠掉；
  我们自行按 alpha==0 生成 AND 掩码。（`flutter_custom_cursor` 0.0.4 的
  Windows 实现是硬编码示例 PNG 的桩，同样不可用。）
- **最新覆盖而不是排队**：指针状态只有“当前”有意义，`QuicSession` 保存
  `std::optional<CursorUpdate>`，读取即取最新，慢一拍的更新直接丢弃。
- **比例量化**：`<2×` 按 1/4 步进、`≥2×` 按整数步进；缩放点采样（指针本就
  是抗锯齿小图，滤波没有收益），超过 OS 256 px 上限时等比缩小而不是失败。
- **句柄释放用 `DestroyCursor`**：RustDesk 的引擎实践显示
  `CreateIconIndirect` 造出的光标用 `DeleteObject` 不会真正释放；先
  `DestroyCursor`，失败再 `DeleteObject`。
- **容量上界**：形状表上限 64（真实桌面只会用到几十个），每个形状的句柄表
  上限 12；超出按注册顺序淘汰最旧的。若淘汰的正是当前激活形状，同时
  撤销覆盖，避免光标指向已释放的句柄。

## 协议 v11

控制消息 `CursorUpdate = 13`，固定头 26 字节，其后是可选精灵：

| 偏移 | 字段 | 说明 |
| --- | --- | --- |
| 0 | flags | bit0 = visible |
| 1 | shape flags | bit0 = 携带精灵 |
| 2 | x (i32) | 帧空间坐标 |
| 6 | y (i32) | 帧空间坐标 |
| 10 | hotspot_x (u16) | 精灵内热点 |
| 12 | hotspot_y (u16) | 精灵内热点 |
| 14 | shape_id (u64) | 53 位内容 id |
| 22 | width (u16) | 精灵宽（≤256） |
| 24 | height (u16) | 精灵高（≤256） |

解析拒绝：截断、形状超过 256 px、未知 flags 位、携带精灵但尺寸为零或长度
与宽高不符、尾随字节、热点落在非零尺寸精灵之外。

## 验证（2026-10-22，单机）

- **协议**：`chast-protocol-test` 新增约 10 项 CursorUpdate 断言（头长、
  控制类型字节、全量往返、仅位置 26 字节、隐藏态、尺寸不匹配 / 无 id 的
  精灵 / 超大精灵 / 截断 / 尾随字节 / 未知 flags / 热点越界均被拒绝）。
- **查看者安装器**：新增 `chast-remote-cursor-test`（ctest `remote_cursor`）
  通过——缩放量化、注册校验、同形状同比例复用句柄、跨形状切换、越界缩放
  缩小、`Clear()` 后不可再激活、超出 64 个形状后淘汰最旧。
- **构建**：`ctest --test-dir build -C Release` 8/8；`flutter analyze` 无
  问题；`flutter test` 59 项全过（新增 `cursor_status_test.dart` 2 项）；
  `flutter build windows` 成功。
- **端到端（回环 + 真实指针）**：本机默认没有可见指针，`GetCursorInfo` 为
  `flags=0, hCursor=0`，DXGI 因此不报告 `PointerPosition.Visible`。用
  `ShowCursor(TRUE)` 让指针可见后：
  - `chast-capture --cursor` 首帧即导出 `32x32, color, content id
    1309952101266445`，10 s 内 435 个 pointer-only 帧；
  - `chast-quic serve` 14 s 内发送 `cursor sent=257 shapes=15 bytes=64080
    dropped=0 errors=0`，`chast-quic connect` 收到 `cursor updates=229
    shapes=11 visible=1 at=1428,164`——精灵只随形状变化携带，位置更新为
    26 字节，且一次都没有因控制队列满而丢弃。
  - `chast_viewer.exe` Release 构建可正常启动（冒烟）。
- **仍未覆盖**：查看者窗口内“肉眼看到主机指针形状”这一步。原生安装器由
  `chast-remote-cursor-test` 验证到句柄层（`GetIconInfo` 确认 2× 缩放后为
  64×64、热点随之变为 (6,10)），但 `WM_SETCURSOR` 与 Flutter 的
  `MouseRegion` 交互只能在有物理鼠标的机器上人工确认。

## 已知限制

- 有物理鼠标的机器上尚未做人工复核：本机默认没有可见指针，验证时用
  `ShowCursor` 强制显示，`WM_SETCURSOR` 与 Flutter `MouseRegion` 的实际
  叠加效果需要肉眼确认。
- 仅在 Windows 查看者侧实现；其他平台需要各自的系统光标安装路径。
- 隐藏指针（`DXGI_OUTDUPL_POINTER_POSITION.Visible == false`）走本地箭头，
  与 RustDesk 的行为一致；不尝试复现主机的“无指针”状态。
- 指针形状的动画序列按 content_id 去重，但更新频率受查看者 200 ms 轮询
  限制；不影响位置（系统光标由手驱动），只影响形状切换的及时性。
