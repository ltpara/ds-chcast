# M10.3 — 载体在线、强制中继与查看者回退

RustDesk 的 hbbs 允许客户端用 TCP/WebSocket 完成注册与心跳，因此 UDP 被封的
网络里主机仍然在线，查看者可以走 relay；`ALWAYS_USE_RELAY` 又能在运维侧强制
放弃直连。chast 目前的在线判定只看 UDP keepalive 与观察地址，主机一旦发不出
UDP 就会被查询报告为离线，即使共享载体链路仍通。本阶段补齐这两类行为，协议
仍为 v23，不改 chast 线协议。

## 1. 缺口

| RustDesk hbbs | chast（本阶段前） | 本阶段 |
| --- | --- | --- |
| TCP/WS 心跳维持在线 | 仅 UDP keepalive；载荷链路已支持 TCP/WS 载体 | 共享载体主机链路也计入在线，查询返回载体与令牌 |
| relay-only 由服务器决定 | 查看者本地 `--mode relay` | `--relay-only` 隐藏直连候选并把 `nat_type` 报为 `symmetric` |
| 查询返回 relay 与地址 | 有 `relay`/`carrier`，但无路径提示 | 新增 `transport`：`direct`/`relay`/`carrier` |
| 客户端在 UDP 失败时用 relay | C++ 查看者已支持 carrier；Go 查看者代理只能 UDP | Go 查看者代理新增 `carrier` 模式与 TCP 转发 |

不做：不实现 hbbs 的 protobuf/WS 会合报文；不做多查看者；不引入远程 hbbr
进程。共享载体仍是“一个主机链路 + 一个查看者”。

## 2. 在线判定

- `relay.Manager.HostLinked(id)` 查询共享载体是否保存着该主机已认证的链路；
  `HostLoop` 的读超时（90 s，主机每 20 s 回一次空帧）会移除死链路。
- 查询在线 = 原有 UDP 租约判定 **或** 共享载体链路存在。后者不要求
  `candidate`，因此 UDP 被封时仍可返回 `online:true`。
- 载体链路只证明主机到服务端的 TCP 可用；`carrier_token` 仍要求租约有效，
  主机代理通过 HTTP 注册续租，所以令牌会随 `expires_in_ms` 正常轮换。
- `transport` 由服务器计算：
  - 有直连候选 → `direct`（除非 `--relay-only`）；
  - 无候选且载体在线 → `carrier`；
  - 无候选但中继端口已分配 → `relay`。
- `/v1/server` 与 `/v1/stats` 增加 `relay_only`；`/metrics` 增加
  `chast_server_relay_only` 与 `chast_carrier_hosts`（已有）便于告警。

## 3. 强制中继

- `chast-server --relay-only`：查询不返回 `candidate`/`candidates`/
  `local_addrs`，`nat_type` 固定为 `symmetric`，`relay_only:true`；中继地址与
  共享载体照常返回。
- 查看者代理：
  - `auto` 按 `transport` 选择载体或中继，不再尝试打洞；
  - `direct` 在 `relay_only` 下直接报错，避免“以为直连成功”的假象；
  - `relay` 优先 UDP 中继，主机只报告 `transport=carrier` 时改用载体。
- 主机代理行为不变：仍上报候选与 NAT 信息，由服务器决定是否下发。

## 4. 查看者载体回退（Go 代理）

`chast-tunnel viewer` 新增：

- `--mode carrier`：显式要求共享载体；`auto` 在 `transport=carrier` 时自动
  选择。
- TLS 之外的载体传输仍是明文 TCP（与 C++ 载体一致），协议为
  `CHASTT-V2\n` + `{host_id,token}` + `u32le` 帧。
- 本地 UDP 数据报 → 载体帧；载体帧 → 最近一次本地 QUIC 客户端地址。链路
  断开后按 0.5 s→5 s 退避重连，路径事件保持 `carrier`；空闲 30 s 发送空帧
  防止查看者 180 s 超时。
- 载波连接不参与打洞/直连计时：`--direct-timeout` 与 `--mode auto` 的直连
  探针只在存在直连候选且未被 `--relay-only` 禁止时启用。

## 5. 测试与验收

自动化：

- `internal/relay`：`HostLinked` 在认证链路建立/断开时正确翻转。
- `internal/agent`：
  - 主机 UDP keepalive 停止后，HTTP 查询仍因载体链路返回 `online`、
    `transport=carrier`、`carrier_token`，且无候选；
  - 查看者 `auto` 在 `transport=carrier` 时走载体，UDP 本地回环完成一次
    帧往返，路径事件为 `carrier`；
  - `--relay-only` 服务器下查询无候选、`nat_type=symmetric`，查看者 `auto`
    选 UDP 中继完成往返，`direct` 模式启动报错。
- `go vet ./...`、`go test ./...`；`flutter`/C++ 不受影响，不重跑全量。

### 验收标准

1. 主机只保留 HTTP 注册与共享载体链路（无 UDP keepalive）时，`GET
   /v1/hosts/{id}` 返回 `online:true`、`transport:"carrier"` 和有效令牌。
2. `--relay-only` 下查询不泄露直连候选，`chast-tunnel viewer --mode auto`
   走中继；`--mode direct` 明确失败。
3. 查看者代理在载体路径上可完成真实 UDP 数据报往返，断开后能自动重连。
4. 现有 M10.1/M10.2 测试与回环摘要不回归，文档记录验证结果。

## 6. 验证记录（2026-10-25）

- **自动化**：`go vet ./...`、`go build ./...`、`go test ./...` 全部通过。
  - `internal/relay`：`HostLinked` 在握手后为真、链路关闭后为假；查看者空帧
    收到空帧应答（共享载体）。
  - `internal/api`：`--relay-only` 查询无 `candidate`/`candidates`/
    `local_addrs`、`nat_type=symmetric`、`relay_only:true`、
    `transport=relay`；普通查询在线时为 `transport=direct`。
  - `internal/agent`：`--mode carrier` 完成数据报往返，主动断开 TCP 后自动
    重连并继续往返；停止会合后等待 `Registry.Online` 变假，HTTP 查询仍为
    `online:true`、`transport:carrier`、无候选，`auto` 经载体往返；强制中继
    下 `auto` 走 UDP 中继、`direct` 报 `server forces relay`。
- **真实二进制回环**：`chast-server --relay-only` + 两个主机（`devbox` 带本地
  载体、`relaybox` 不带）+ `chast-tunnel viewer`。
  - `GET /v1/hosts/devbox`：`online:true`、`relay_only:true`、
    `nat_type:"symmetric"`、`transport:"carrier"`、令牌有效、无候选；
    `GET /v1/hosts/relaybox`：`transport:"relay"`。
  - `viewer --mode carrier`（127.0.0.1:19200）与 `--mode auto`
    （relaybox，127.0.0.1:19210）均完成 UDP 数据报往返；`--mode direct`
    以退出码 1 打印 `server forces relay; direct mode is unavailable`。
  - 仅载体在线：服务器 `--offline-after 1s`、主机 keepalive 5 s，3 s 后查询
    `last_seen_ms=2957` 已过期但 `online:true`、`transport:"carrier"`，
    载体往返成功。
- **环境边界**：单机回环无法模拟真实 UDP 全封锁、运营商 NAT 超时与程序崩溃后
  的 90 s 链路回收，这些留待双机人工验收；C++/Flutter 未改动，不重跑全量。
