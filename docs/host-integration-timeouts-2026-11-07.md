# 主机集成测试超时排查（2026-11-07）

`host_control`、`host_login`、`block_input` 的响应超时已修复，原有单次请求 5 秒等待上限保持不变。

## 根因与对照

三个测试模拟了锁屏、重启、阻止输入及登录注入，却仍使用真实 Windows 剪贴板。主机在宣布会话后、进入控制请求循环前同步读取剪贴板基线，之后又在同一循环中轮询。当前机器上 `GetClipboardData(CF_UNICODETEXT)` 一次读取阻塞约 10 秒，期间控制请求只能排队。

临时诊断只记录阶段、格式编号和耗时，没有记录剪贴板内容或密码：

- 握手约在进程启动后 0.85 秒完成，同时开始读取剪贴板基线。
- 第一次锁屏请求约在 1.46 秒发出，在 6.47 秒触发 5 秒断言超时。
- 剪贴板读取约在 10.85 秒返回；随后首帧处理约 6 毫秒，排队的锁屏与重启立即执行。
- 首次登录回复迟到后被后续用例消费，造成计数、状态和模拟注入结果的连锁断言失败。

保留生产代码、仅给测试注入空剪贴板时，三个测试分别在 2.21 / 2.24 / 3.34 秒通过。这与此前替换回旧键盘注入实现后仍复现 2 / 9 / 8 个失败的结果一致：超时来源是剪贴板访问。

诊断日志：`build/review/host-control-diagnostic.log`、`build/review/host-control-clipboard-diagnostic.log`。临时诊断代码已移除。

## 修复

- 主机基线读取、周期读取和剪贴板文件目录展开移入后台线程；每个会话工作对象最多存在一次未完成读取。控制、权限更新和视频循环只消费已完成快照。
- 用版本号使会话结束、撤权、恢复权限和远端写入之前开始的读取失效。首次有效结果只建立基线，不发送历史内容；写入后的旧快照不能覆盖回显抑制状态。
- 会话退出先释放本地输入和连接。共享主机的后台读取收尾由原工作线程等待，监听线程可以继续接受连接。最终停止会等待读回调返回，避免线程访问已销毁对象。
- 三个测试采用内存剪贴板。`host_control` 进一步用可控制的阻塞读模拟延迟，并覆盖基线不外发、撤权期间的副本不外发、远端写入不回显、恢复后正常复制、断线释放及跨会话旧结果丢弃。
- 扩展文件传输验证发现 `viewer_probe` 仅模拟了文件剪贴板，文本读取仍访问真实系统。新增 `ViewerEngine::SetClipboardSource` 测试入口，并在探针启动前设置空源；真实查看器的默认读行为保持原样。

## 验证

- 定向 CTest：`protocol`、`keyboard`、`protocol_fuzz`、`host_multi`、`host_control`、`host_login`、`block_input`、`viewer_clipboard_files`、`viewer_clipboard_files_up`，9/9 通过，总计 55.24 秒。日志：`build/review/host-timeout-regression-9.log`。
- 补充跨会话断言后，三个主机测试各连续运行 3 次，9 次全部通过，总计 38.50 秒：`host_control` 7.23–7.43 秒（含受控阻塞、恢复和重连场景），`host_login` 2.21–2.25 秒，`block_input` 3.19–3.31 秒。日志：`build/review/host-timeout-repeat.log`。
- 主机及 Flutter Windows 查看器 Release 构建通过。仍有已有的权限窄化、宏重定义和链接库告警。
- `git -c core.whitespace=cr-at-eol -c core.safecrlf=false diff --check` 通过。

以上记录为首次修复时的实现与验证。当时查看器仍同步读取、主机最终关闭仍等待后台读回调；这两项边界已在随后修复中处理，并补齐了失败基线、串行写入和有界重试，见 `docs/clipboard-async-fix-2026-11-07.md`。Windows 原生调用本身仍可能等待，应用通过独立执行器隔离。上述验证不代表整个 CTest 套件或双机物理键盘验证完成。
