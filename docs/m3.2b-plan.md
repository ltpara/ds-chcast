# M3.2b — Windows 服务主机

状态：已完成（2026-10-22）
上一阶段：M4.2 已完成，托盘主机自动注册连接服务。
下一阶段：M5 体验扩展（自适应码率、剪贴板、音频等）。

## 目标

让 chast 主机在无人登录托盘、用户锁定或切换会话时仍由 Windows 服务托管：

1. `chast-service.exe` 作为自启动 Windows 服务（LocalSystem）常驻，安装/卸载/查询走 SCM；
2. 服务在活动控制台会话内启动工作进程，由它运行 `HostServer` 与 `chast-tunnel host`，采集/编码/输入仍在用户会话；
3. 服务使用 `%ProgramData%\chast\host.ini` 与 `LocalMachine` 证书身份，跨用户、跨重启保持设备指纹；
4. 服务停止、用户注销或切换会话时清理工作进程；工作进程异常退出由服务重启；
5. 安装时写入机器级默认设置并应用主机/隧道两条防火墙规则，卸载时删除规则。

## 关键边界（本阶段不做）

- **安全桌面画面**：锁屏、登录界面和 UAC 提示位于 Winlogon 安全桌面，
  DXGI 桌面复制无法读取，`SendInput` 也不能跨桌面注入。本阶段保证服务常驻、
  工作进程在锁屏期间存活并在解锁后恢复串流；锁屏/登录界面本身的画面采集
  需要安全桌面采集器（GDI/DWM 或桌面切换），留给后续阶段。
- **未登录时的画面**：登录前没有用户桌面可采集；服务保持运行并在用户登录后
  自动拉起工作进程，但登录界面不提供画面。
- 多用户同时使用：同一时刻只服务活动控制台会话。
- 账号体系、设备 ACL、远程唤醒、服务自动更新。

## 架构

```
SCM
 └─ chast-service.exe --run            LocalSystem, session 0
      ├─ 读取 %ProgramData%\chast\host.ini，初始化机器级默认值
      ├─ 刷新防火墙规则（chast-service.exe 主机端口 + chast-tunnel.exe 隧道端口）
      ├─ 监管循环：WTS 活动控制台会话 → 创建 job/stop event
      └─ CreateProcessAsUser(winlogon token, session N)
            └─ chast-service.exe --worker                   SYSTEM, session N
                 ├─ HostServer（该会话的桌面采集/编码，输入注入）
                 │    └─ LocalMachine 证书身份；审批关闭，仅令牌准入
                 ├─ chast-tunnel.exe host（随 HostServer 启停）
                 └─ %ProgramData%\chast\worker.log
```

关键决策：

- **工作进程放用户会话，而不是服务进程直接采集**：Windows 服务在 session 0，
  DXGI 桌面复制和 `SendInput` 都只对交互会话有效。服务负责生命周期，工作进程
  负责真正的桌面临近操作。
- **工作进程以 SYSTEM 运行在用户会话**：从该会话的 `winlogon.exe` 复制主令牌
  （需要 `SeDebugPrivilege`），`CreateProcessAsUser` 指定 `winsta0\default`。
  这样能访问 `LocalMachine` 私钥、写机器级设置，并保持跨用户一致的机器身份；
  代价是工作进程权限较高，服务本身已是 LocalSystem，边界不变。
- **服务与工作进程用命名事件和 job 对象协作**：停止事件让工作进程先停隧道
  再停 `HostServer`，并放在 `Global\` 命名空间（`Local\` 只对单个会话可见）；
  服务级 job 的 `KILL_ON_JOB_CLOSE` 保证服务崩溃时不会留下孤儿工作进程；
  工作进程再为 `chast-tunnel` 建一个 `KILL_ON_JOB_CLOSE` 子作业，工作进程
  被强杀时隧道随之退出。隧道以句柄白名单（`PROC_THREAD_ATTRIBUTE_HANDLE_LIST`）
  启动，只继承两根输出管道，不再继承主机的 QUIC 套接字——否则崩溃后的残留
  隧道会一直占着 4433 端口，新工作进程无法重新监听。
- **会话内失败不限次数重试**：锁屏时采集会失败，解锁后要能自动恢复。
  `HostServerConfig::max_consecutive_failures = 0` 表示无限重试；托盘仍沿用
  5 次的默认值，避免坏配置下无限弹错。
- **服务模式没有审批对话框**：工作进程无人值守，`require_approval` 被忽略并
  写日志；准入仍由访问令牌负责。服务默认一次性令牌，操作者从机器设置读取当前值。
- **托盘让位**：检测到服务正在运行时，托盘提示后退出，避免两个监听器争同一
  端口；安装服务时移除当前用户的 HKCU 开机启动项。
- **沿用现有 HostServer 与 Go 隧道代理**：服务/工作进程只提供生命周期、
  日志和身份作用域，不复制采集/编码/打洞逻辑。

## 身份与设置

- 机器身份：`NCrypt` 机器密钥容器 `chast-quic-key`（`NCRYPT_MACHINE_KEY_FLAG`）
  + `LocalMachine\My` 自签名证书，指纹跨服务重启、跨登录用户稳定。
- 机器设置：`%ProgramData%\chast\host.ini`，首次安装生成访问令牌、设备 ID、
  设备密钥；工作进程轮换一次性令牌后写回。
- 服务日志：`%ProgramData%\chast\service.log`（监管）与 `worker.log`（会话）；
  超过 5 MB 轮转为 `.old`，不记录令牌。
- 当前令牌：`chast-service.exe --token` 读取机器设置并打印，供操作者连接。

## 命令

```sh
chast-service.exe --install     # 需要管理员；创建服务、机器设置、防火墙
chast-service.exe --uninstall   # 停止/删除服务并移除防火墙规则，保留设置与日志
chast-service.exe --run         # SCM 入口
chast-service.exe --worker      # 内部使用；停止事件名是固定全局对象
chast-service.exe --token       # 打印机器设置中的当前访问令牌
sc query chast-host
```

服务名 `chast-host`，显示名“chast 主机服务”，自动启动（延迟启动），失败后
5 s / 10 s / 30 s 重启。可执行文件路径使用安装时的绝对路径；升级时重新执行
`--install` 会更新路径与配置，不覆盖已有机器设置。

## 验证计划

1. **单元/构建**：`ctest -C Release` 全过；Release 目录三个可执行文件并存；
   机器设置路径位于 `%ProgramData%\chast`；身份作用域默认仍是当前用户。
2. **安装**：管理员执行 `--install`，`sc query chast-host` 为 RUNNING；
   `%ProgramData%\chast\host.ini` 生成；两条防火墙规则存在且程序分别指向
   `chast-service.exe`/`chast-tunnel.exe`。
3. **会话工作进程**：`Get-Process chast-service` 显示一个 session 0 监管进程与
   一个当前控制台会话内的 SYSTEM 工作进程；串流期间工作进程 CPU/日志正常。
4. **身份稳定**：重启服务两次，`worker.log` 中 SHA-256 指纹不变；
   `GET /v1/hosts/{id}` 返回同一指纹。
5. **真实流量**：服务托管下用 `chast-quic connect` 经直连与中继各跑一次，
   核对帧数、CRC、解码错误、序号与摘要；托盘在服务运行时退出并提示。
6. **生命周期**：停止服务后工作进程消失、注册过期下线；重启服务后自动恢复；
   用户注销/切换会话时旧工作进程退出、新会话拉起新进程（注销测试需人工）。
7. **卸载**：`--uninstall` 后服务与防火墙规则消失，工作进程退出，机器设置
   与日志保留。
8. **锁屏边界**：锁屏期间的画面采集不在本阶段验证范围；确认工作进程在锁定
   时不被服务终止、解锁后下一次会话恢复串流。

## 验证结果（2026-10-22）

- **构建与测试**：`cmake --build build --config Release` 全目标通过（仅既有的
  LNK4098/LNK4199 与 `pwsh.exe` 缺失告警）；`ctest -C Release` 5/5
  （`quic_loopback` 15.66 s）；`go test ./...` 全部通过。
- **安装与账户**：`--install` 后服务为 RUNNING，`chast-service.exe` 一个
  session 0 监管进程、一个 session 1 `NT AUTHORITY\SYSTEM` 工作进程；机器证书
  在 `LocalMachine\My`（指纹 `87D5C8F4…5796`），HKCU 的 `chast-host` 自启动
  项被移除；`chast host`/`chast tunnel` 两条 UDP 入站规则分别指向
  `chast-service.exe`/`chast-tunnel.exe`。
- **机器身份**：机器指纹
  `2C:20:52:DC:9F:26:51:04:D1:6A:9E:B8:34:42:6E:AD:B8:23:5E:7A:6F:56:23:90:02:8A:9C:1B:88:25:AD:22`
  在服务重启、工作进程强杀重启前后完全一致，`GET /v1/hosts/svc-host` 返回同一值。
- **真实流量**：服务托管下直连 `653` 帧、中继 `691` 帧，均 CRC/解码错误为 0；
  中继出现的 `gaps=1` 是 M4.2 已知的会话中途接入行为。修复句柄继承后再次
  强杀工作进程并恢复，经中继回放 `703` 帧、0 错误、摘要
  `0C8A67687145D534`。一次性令牌每次会话后轮换并写回机器设置。
- **崩溃恢复（发现并修复缺陷）**：首次强杀工作进程后，隧道线程继承了主机
  的 QUIC 套接字且未随工作进程退出，端口 4433 被残留隧道占用，服务每 3 s
  拉起的新工作进程全部以 `0x80072740`（WSAEADDRINUSE）失败。修复：
  `host/tunnel.cc` 用 `PROC_THREAD_ATTRIBUTE_HANDLE_LIST` 只让隧道继承两根
  输出管道，并给隧道建立 `KILL_ON_JOB_CLOSE` 子作业。再次验证：强杀后 3 s
  新工作进程绑定成功、新隧道上线、指纹不变、串流正常。
- **托盘让位**：服务运行时启动 `chast-host.exe`，弹出“chast 主机”提示框；
  关闭提示框后进程以 0 退出，4433 仍由服务工作进程持有，没有第二个监听器。
- **生命周期**：停止服务后监管/工作/隧道进程与端口全部消失，注册在租约
  55 s 后返回 404；重新启动服务后自动注册上线（同一指纹、同一中继）。
- **卸载**：`--uninstall` 退出码 0；`sc query` 返回 1060（服务不存在），
  进程与端口清零，两条防火墙规则均显示无匹配，`host.ini`、`service.log`、
  `worker.log` 保留，HKCU 自启动项不存在。
- **未覆盖**：注销/切换用户需要人工操作；锁屏期间工作进程存活与解锁后恢复
  串流同样需要人工锁屏验证。代码路径按无限重试设计，本轮未实际锁屏。
