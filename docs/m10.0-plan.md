# M10.0 — TCP/WebSocket 弱网回退

更新时间：2026-10-24
分支：`feat/m7-security`
基线：M9.4 完成（协议 v23；音频设备与 AEC/降噪）。
本阶段**不改变 chast 协议版本**，仍为 v23；新增的是 QUIC 数据报的承载方式。

## 1. 范围与取舍

现状是 UDP 单一路径：QUIC 打洞失败时退回 UDP 中继，但只要网络封掉
UDP（企业防火墙、酒店/校园网、部分移动网络），查看器就连不上主机。
M10.0 增加一条 **TCP/WebSocket 载体（carrier）**：把 QUIC 数据报装进
TCP 或 WebSocket 的消息帧里传输。TLS、证书指纹、令牌、密码、审批、
权限与全部控制/视频/音频流保持原样，仍然端到端只在两端生效。

| 能力 | 行为 |
| --- | --- |
| 主机载体监听 | QUIC 端口 P 旁边监听 TCP `P+1`，同一端口同时接受原始 TCP 与 WebSocket |
| 查看器自动回退 | QUIC 连接失败后依次尝试 TCP、再 WebSocket；成功后本次会话固定使用该载体 |
| 直连 | 查看器直连主机 `P+1`，适用于同网段或已映射端口的机器 |
| 服务中继 | 服务端在每个 UDP 中继端口上同时监听 TCP；主机代理保持认证链路，查看器经服务端 TCP/WS 到达主机 |
| 传输遥测 | 会话浮层与工具输出显示 `UDP`、`TCP 回退`、`WebSocket 回退` |
| 兼容 | 不改变 Hello/AccessDenied/FrameHeader/AudioHeader；旧版主机没有载体端口时查看器仍走原来的 QUIC |

不做的部分：

- **不把协议重新实现一遍。** 载体只搬运 QUIC 数据报，不在 TCP 上重建
  控制流/视频流/音频流。允许令牌、审批、指纹 pin、权限、剪贴板、文件、
  麦克风全部沿用现有代码，也避免两套协议状态机分叉。
- **不在载体层再做认证。** 载体本身不校验令牌或密码；QUIC 的 TLS 与
  Hello 是唯一的准入点。载体只做长度、连接数与空闲限制。
- **不做 TCP 打洞。** 原始 TCP 直连只在主机端口确实可达时工作；否则
  经服务端中继。TCP 打洞在常见 NAT 上不可靠，不投入。
- **不做多查看者。** 与 HostServer 一致，同一时刻一个查看者；第二个
  载体连接被拒绝。
- **不替代 UDP。** 载体是回退：正常网络仍优先 QUIC；载体一旦启用，
  本次会话不来回切换，避免 QUIC 连接迁移与重放问题。

关键语义：

1. **载体是一根透明管道。** 每个 TCP/WS 连接对应主机侧一个独立的
   UDP 套接字和一条 QUIC 连接；主机 QUIC 监听端口不变，服务端无需
   理解 chast。
2. **端口约定。** 主机 QUIC 端口为 `P`，载体端口为 `P+1`（最大 65534；
   `P=65535` 时不能启用）。直连查看器不需要额外配置就能找到。
3. **回退是查看器本地的决定。** 首次 QUIC 连接在 `auto` 模式下只等
   4 秒；失败后尝试 TCP，仍失败再尝试 WebSocket。错误信息保留三条
   路径各自的原因。
4. **经服务时走中继。** 查看器无法直接连到 NAT 后的主机 TCP 端口，
   因此有服务配置时载体端点是服务端中继端口；主机代理维持一条到
   服务端的认证 TCP 链路，服务端把查看者的载体连接与它配对。
5. **安全边界不变。** 载体监听像 QUIC 一样暴露给网络，但没有新的
   明文凭据；主机仍需通过 TLS 指纹、令牌/密码、审批与权限。载体
   只限制握手时间、帧长与并发连接数。

## 2. 载体协议

### 2.1 原始 TCP

```text
client -> server   "CHASTT1\n"
之后双向           u32le length | payload        (length 0..65535)
```

- `length == 0` 是保活帧，接收方丢弃；用于中继主机链路探活。
- 单条连接只承载一条 QUIC 连接。QUIC 数据报原样放入 payload，不重排、
  不合并、不拆分。
- 长度超过 65535、握手魔数不符或 10 秒内没有完整魔数的连接直接关闭。

### 2.2 WebSocket

- 请求：`GET /chast HTTP/1.1`，`Upgrade: websocket`，
  `Sec-WebSocket-Protocol: chast-carrier.v1`。
- 响应：`101 Switching Protocols`，`Sec-WebSocket-Accept` 按 RFC 6455
  的 SHA-1 + GUID 计算，回显子协议。
- 每个 **binary message** 就是一条 QUIC 数据报；不启用扩展、压缩与
  分片（FIN 必须为 1）。客户端帧按 RFC 6455 掩码，服务端不掩码。
- ping 回 pong；close 关闭连接；文本帧与 continuation 帧被拒绝。
- 同一 TCP 端口根据首字节区分：`C` 开头按原始载体魔数，`G` 开头按
  HTTP/WebSocket；其它一律关闭。

### 2.3 中继主机链路

主机代理连到服务端中继 TCP 端口后先发：

```text
"CHASTT-HOST1\n" {"host_id":"…","key_hash":"…"} "\n"
```

服务端用注册表校验主机与密钥摘要，成功回 `"CHASTT-OK1\n"`，之后这条
链路只传 `u32le length | payload` 帧。查看者连接由服务端配对：

- 原始 TCP 查看者：服务端读掉其 `CHASTT1\n` 魔数，把后续帧转发到主机链路。
- WebSocket 查看者：服务端完成握手，把 binary message 转成帧。
- 主机链路断开时关闭当前查看者；查看者离开后主机链路保留，等待下一位。
- 同一中继端口已有查看者时，新连接立即关闭，计数器 `busy` 递增。

## 3. 主机侧

- `HostSettings` 新增 `carrier=0/1`，默认开；端口固定为 `port + 1`，
  不单独配置，避免查看器需要第二个地址。
- `HostServer` 在 QUIC 监听成功后启动 `CarrierServer`；绑定地址跟随
  `bind_address`，UDP 侧固定连到 `127.0.0.1:P`（绑定地址是具体 IP 时
  使用该 IP），因此不依赖外部网卡回环。
- 监听失败（端口被占、地址非法）只记录日志并继续提供 QUIC，不阻止
  主机启动；状态里带 `carrier_listening`、`carrier_port`、`carrier_error`
  以及连接/活跃计数。
- 每个载体连接的本地 UDP 套接字使用 4 MiB 收发缓冲。关键帧是突发到达，
  Windows 默认 64 KiB 缓冲会在载体线程搬运前丢掉尾部，让发送端拥塞控制
  误判成网络丢包；加大缓冲后，清洁链路上的载体对 ABR 透明。
- 每个载体连接：TCP 读线程 → 本地 UDP 套接字；UDP 读线程 → TCP 帧。
  任一方向出错或空闲 180 秒即整体关闭。并发上限 16，超过直接关闭。
- 托盘设置增加“允许 TCP/WebSocket 回退”复选，写入 `host.ini`；
  防火墙按钮同时添加 UDP（QUIC/隧道）与 TCP（载体）规则。
- 服务安装/升级同样添加 TCP 载体规则；卸载删除规则。

## 4. 查看器侧

- `ViewerEngine::Start` 增加载体端点与传输方式：
  - `carrier_host` / `carrier_port`：直连为 `host:P+1`，经服务为
    服务端中继地址；
  - `transport`：`auto`（默认）、`quic`、`tcp`、`ws`；`quic` 只用 UDP。
- 连接顺序：
  1. `auto` 先按现有路径连 QUIC，超时 4 秒；`tcp`/`ws` 跳过这一步。
  2. 失败且载体重试可达：尝试 TCP 载体（`auto`/`tcp`）。
  3. 仍失败且模式允许：尝试 WebSocket 载体（`auto`/`ws`）。
  4. 全部失败时报告三条路径的错误摘要。
- 载体桥在 `127.0.0.1:0` 上开一个 UDP 套接字，QUIC 客户端连这个本地
  端口；桥把数据报装帧后送到载体端点。QUIC 的 SNI、证书指纹与令牌
  不感知载体。
- 会话状态新增 `transport`（`quic`/`tcp`/`ws`）与 `transportError`；
  bridge 透传给 Flutter，浮层显示“传输 · TCP 回退 / WebSocket 回退”。
- 经服务连接时，Dart 从隧道代理的 `path` 事件取中继地址作为载体端点；
  直连时用 `host:(port+1)`。隧道或主机不支持载体时，连接失败信息里
  会包含 TCP/WS 的具体错误，不静默降级成“仅 UDP”。

## 5. 服务端与中继

- 每个中继端口在绑定 UDP 的同时绑定 TCP；TCP 绑定失败只禁用该端口的
  载体能力并记录日志，UDP 中继继续工作。
- TCP 中继沿用“一个端口对应一个主机、同一时刻一个查看者”的语义；
  `relay_hello` 的主机认证复用注册表 `VerifyHost`，不新增密钥。
- 统计新增 `tcp_to_host_bytes`、`tcp_to_viewer_bytes`、`tcp_viewers`、
  `tcp_busy`；HTTP `/v1/stats` 原样暴露。
- 中继不理解 QUIC；TLS 与令牌只在查看器和主机之间生效，服务端无法
  解密或伪造会话。

## 6. 测试与验收

- `chast-carrier-test`：原始帧/WS 帧编解码、掩码、超长与坏帧拒绝、
  SHA-1 accept 向量、UDP 回显经原始 TCP 与 WS 往返、并发上限。
- `chast-quic verify --transport tcp` 与 `--transport ws`：真实
  `HostServer` + 真实 QUIC 会话，断言收到的访问单元、CRC、序号与
  传输方式；默认 UDP 回环保持不变。
- Go：中继 TCP 主机认证、原始查看者与 WS 查看者配对、忙拒绝、
  主机链路断开清理；`go vet ./...`、`go test ./...`。
- Flutter：`transport` 状态解析、浮层文案；`flutter analyze`、
  `flutter test`、Release 构建。
- 主机设置：`carrier=0/1` 默认与往返、`P=65535` 禁用。

手工/环境限制：

- 本机没有第二块网卡与真实 NAT，跨网 UDP 封锁→TCP 回退需要两台机器
  或防火墙规则人工复核；自动化覆盖同机 TCP/WS 全链路。
- WebSocket 不经过真实 HTTP 代理；代理/CDN 行为留待部署环境验证。
- 载体内嵌套 TCP 与 QUIC 两套重传，弱网抖动下的吞吐/延迟需要双机
  弱网演练；本阶段只证明可达性与正确性。

## 7. 验收标准

1. 正常网络仍走 QUIC，默认回环摘要与 M9.4 一致。
2. 强制 TCP 与强制 WebSocket 时，视频、音频、输入、剪贴板、文件中
   至少与默认回环相同的断言全部通过，CRC/解码/序号错误为 0。
3. 直连 QUIC 端口被防火墙挡住时，查看器在 4 秒后自动经 `P+1` TCP
   建立同一会话；WS 亦然。
4. 经服务中继时，主机关闭 UDP 后查看者仍可经服务端 TCP/WS 载体
   连接；服务端统计显示 TCP 字节数。
5. 旧版/禁用载体的主机不受影响；查看器仍能正常 QUIC 连接。
