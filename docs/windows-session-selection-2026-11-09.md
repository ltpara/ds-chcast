# Windows / RDP 会话选择与管理状态

日期：2026-11-09。接续 [服务管理器启动](service-manager-startup-2026-11-09.md)，参考版本仍为本地 RustDesk `7423dced37845c48093b6f71bd82e4a16cc8c79d`。

## 当前行为

服务和工作进程共用 `host/windows_sessions.{h,cc}` 读取活动登录会话。只接受具有用户名和有效登录标识的 `WTSActive` 会话，排除会话 0、保留 ID 和已断开的 RDP 会话。会话选择顺序为：观看者明确选择且仍属于同一次登录的会话、有效物理控制台、仍然有效的当前工作会话、ID 最小的有效活动会话。因此只有 RDP 用户而没有物理控制台用户时也可以启动工作进程；其他 RDP 会话加入时不会仅因枚举顺序改变而替换当前进程。

登录身份使用真实 WTS 用户令牌的 `TokenStatistics.AuthenticationId`。明确选择和工作进程都记录会话 ID 及登录标识；同一个数字 ID 被重新登录复用时，旧选择失效，工作进程也需要替换。登出通知清除管理器的启动记录和旧选择，并停止对应工作进程。

会话快照全部读取成功后才发布。中途失败时保留调用者原有结果；监督线程保留现有工作进程，不消费切换请求，不根据不完整结果猜测新目标。失败和恢复写入服务日志。观看者列表沿用最多 16 项的现有限额，优先包含当前工作会话。

工作进程发出的本机切换文件改为 `1:<worker PID>:<target session ID>:<target logon ID>`。服务校验来源工作进程及目标登录代次，拒绝旧进程请求、已更换用户的目标和旧格式。文件仍使用原子替换及事件唤醒；读取限制为 1–96 字节，删除打开的文件本身，避免误删后来替换的新请求。本次未修改网络协议；服务和工作进程需要使用同一构建版本。

原生管理器现在区分服务停止、启动中、停止中、暂停，以及服务运行但本会话尚无工作进程等状态。页面显示本地 Windows 会话 ID；连接断开时清空设备信息并禁用复制按钮。管理器只管理自己登录会话的端点，不推测另一会话正在运行哪个工作进程。

## 验证

- Release 主机、服务和现有测试目标构建通过，日志 `build/windows-session-selection-build.log`。
- 复用 `host_settings`、`host_parity`、`host_i18n`，全部通过，78.34 秒，日志 `build/windows-session-regression.log`。增加的是既有设置测试内的选择策略、登录代次与严格请求解析断言，没有新增 CMake 测试项目。
- 临时 SYSTEM 服务读取真实 WTS 会话，核对登录标识与用户令牌一致；普通用户模拟身份下查询失败且旧输出保留。原有真实用户进程启动和生命周期验证也通过，日志 `build/windows-session-system-check.log`、`build/service-manager-startup-system.log`。
- 复用原生管理器辅助验证，中英文均通过；覆盖真实管道/QUIC 管理流程以及可控的服务停止、等待本会话工作进程、短暂查询失败和确认服务删除状态。日志 `build/windows-session-ui-zh.log`、`build/windows-session-ui-en.log`，四张状态截图位于 `build/windows-session-{stopped,waiting}-{zh,en}.png`。

## 尚未验收

没有触发真实多用户登录/登出、RDP 断开重连或跨 Windows 会话切换；策略测试和真实令牌查询不能替代这些端到端场景。没有修改正式 `chast-host` 服务或机器配置。界面服务删除场景使用受控状态，不是卸载正式服务的验收。无用户登录时的采集、完整多用户体验及会话内提权仍需继续开发或验证。
