## 1. 目标、依据与执行结论

本方案先保证现有 Windows 远控功能正确，再关闭企业管理主干，随后补齐日常使用与企业协作能力，最后用真实部署、故障注入和同条件性能对照形成发布证据。方案优先解决会导致数据被覆盖、账号状态被旧请求恢复、归档丢失、错误断开或权限越权的问题，再扩大功能范围。

本次整理的主依据只有两份：

1. [当前项目功能审核及修复记录](functional-audit-2026-11-16.md)：承接 F1–F4 的复现、修复和剩余验收边界。
2. [ds-chcast 与 RustDesk 总体功能及性能审核](rustdesk-overall-audit-2026-11-15.md)：承接发射端、接收端、服务器与性能差距。

补充材料只在主报告没有展开企业服务器能力时使用：[服务器端与 RustDesk 功能差异审核](rustdesk-server-audit-2026-11-16.md)和 [G19 产品决定](g19-decision-2026-11-14.md)。服务器差异报告没有改变主方案顺序；G19 只用于冻结暂缓、不实施和条件启动项。

优先级规则：

- **P1**：数据丢失、账号隔离、错误断开、越权、核心连接不可用，以及已承诺发布能力的完整闭环。
- **P2**：影响企业部署、连续性或重要体验，但不阻断当前 Windows 核心能力修复的补齐项。
- **P3**：产品体验完善，可在主干稳定后推进。
- **条件 P0**：仅在目标明确变化时成立。例如要求官方 RustDesk 客户端无修改接入，hbbs/hbbr 协议兼容才成为阻断项。

### 1.1 执行结论

当前产品是较完整的 Windows 远控实现，核心连接链路接近 RustDesk，服务器相对 RustDesk OSS 有更丰富的账号、策略、审计和录制能力；它尚未通过“全面功能与性能对齐 RustDesk”验收。原因不是单一功能缺失，而是以下三类证据同时不足：

1. F1–F3 的代码修复已经存在，但仍缺真实双客户端、慢网络、长会话和旧数据升级证据。
2. S01/S02/S03 代表的企业管理主干尚未全部完成验收。S02 不能把“收到命令”误显示为“连接已由目标主机确认断开”；S03 已修复权限缺陷。本地 PostgreSQL 与主要管理台浏览器流程已有证据，当前仍缺全管理台覆盖、S01/S02 双机、原生重启/断网和生产部署证据。
3. 性能只有本机回环和内部基准，尚无双机、跨 NAT、真实代理/CDN、生产 PostgreSQL、多实例容量及 RustDesk 同条件 A/B。

### 1.2 执行顺序

1. 固定 Windows、自有协议、自建服务器为当前范围；跨平台和官方 RustDesk 协议兼容保持条件项目。
2. 保留并验证 F1–F4，不重做已关闭的代码问题；实机环境未就绪时记录“待验收”，不把自动化写成生产通过。
3. S01/S02 外部验收与 S03 外部验收并行推进；S03 服务端与管理台代码已闭环，不再重复建设。
4. S02 必须先修复“已投递但无回执”的重投递缺口，再实现代理、Windows 原生、管理台和双向回执。错误顺序会让后续客户端建立在不可恢复的协议语义上。
5. S03 本轮先修复审核确认的权限缺陷并通过回归；继续完成外部越权与作用域验收后再推进 C01 和 P2 能力。
6. V01–V04 从 W0 开始积累环境、版本、命令和原始日志，到 W5 汇总发布结论。

### 1.3 证据分层

每项任务分别记录四类证据：

1. **源码/契约**：DTO、迁移、状态机、接口和客户端路径存在。
2. **自动化**：定向回归、全量测试、静态检查和构建。
3. **实机**：至少两个 Windows 实例、真实进程、真实重启和真实网络。
4. **生产/性能**：隔离 PostgreSQL、浏览器端到端、目标拓扑、容量和 A/B 数据。

低层证据不能替代高层证据。定向 API 测试通过，不等于主机已精确断开；SQLite 迁移通过，不等于 PostgreSQL 验收；本机回环通过，不等于跨 NAT 或生产可用。

### 2.4 执行规则与完成状态

每个工作包都按同一条交付链推进：确认缺陷或差距、写出可失败场景、完成数据与契约、服务端、传输、主机或查看端、管理台、失败回执和审计、自动化门禁、实机验收。缺少任一必要消费端时，状态保持“实施中”。

状态含义固定为：

- **待复核**：报告或历史记录称存在差距，当前源码尚未重新确认。
- **待设计**：产品行为和接口契约仍未确定。
- **实施中**：代码正在修改，或只有部分层已接通。
- **待验收**：实现与自动化完成，外部环境证据尚未取得。
- **已完成**：实现、自动化、适用的实机/生产证据全部通过，并记录版本与日志。
- **受环境阻塞**：剩余工作依赖明确缺失的外部资源，代码侧没有可继续完成的必要动作。
- **范围外**：产品负责人已明确排除，且已有替代流程或可解释边界。

同一任务不能只凭代码存在或定向测试通过改为“已完成”。新发现的账号隔离、越权、数据丢失、错误断开或核心连接阻断问题自动升到当前批次之前。

工作区约束：保留现有未提交改动，不执行 `reset`、`clean`、覆盖无关文件或擅自提交；新增迁移必须兼容 SQLite 和 PostgreSQL，并明确旧版本降级边界。
