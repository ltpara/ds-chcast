# M10.1 — 服务端向 RustDesk 对齐：持久身份、挑战应答与共享载体

本阶段不改 chast 线协议（仍为 v23），只改服务端、`chast-tunnel` 代理和查看者
的接入方式。目标是把 `server/` 从“注册表 + UDP 中继”推进到 RustDesk
`hbbs`/`hbbr` 的能力面：ID 与公钥永久绑定、可离线查询、每个数据面都有一次性
挑战、共享 TCP/WebSocket 载体按主机复用，以及 NAT/局域网候选信息。

## 1. 缺口与取舍

对照 RustDesk：

| RustDesk | 本阶段实现 |
| --- | --- |
| `RegisterPk` 首次登记 ID 公钥，之后续约只带签名 | `POST /v1/hosts` 携带 Ed25519 公钥、时间戳与注册签名；首次登记后公钥永久绑定，变更被拒绝 |
| `Peer` 记录在 hbbs 中持久化，离线仍可查询 | `chast-server-state.json` 保存 ID → 公钥/指纹；租约过期后查询仍返回身份与服务器签名绑定 |
| 客户端用内置服务器公钥校验 `RegisterPk` 响应 | 服务端用持久 Ed25519 身份签署 `binding`，查看者/主机可用 `/v1/server` 的 `public_key` 校验 |
| `PunchHoleRequest`/心跳都带签名挑战 | keepalive、UDP 中继、TCP/WebSocket 载体各自走一次性 nonce 挑战，nonce 30 s 过期 |
| 按 UUID 复用同一中继端口的 TCP 流 | 共享载体在单独端口上复用所有主机链路；查看者用查询得到的随机令牌选择主机 |

明确不做：不引入 RustDesk 的 protobuf/wire 兼容层；服务端仍不终止 QUIC，
不解析 chast 流；共享载体不做多查看者（`HostServer` 的语义仍是一个会话）。

## 2. 身份模型

- 服务端身份：`chast-server-identity.key` 保存 32 字节 Ed25519 种子；
  `--identity ""` 退化为临时身份（仅测试）。公钥经 `/v1/server` 与查询响应
  返回，主机代理可用 `--server-pubkey` 固定。
- 主机身份：`chast-tunnel host` 的 `--key` 经
  `SHA-256("chast-host-identity-v1\n" + key)` 派生 Ed25519 私钥，服务端只见
  公钥与可选证书指纹。`host.ini` 的 `tunnel_key` 因此仍只有主机知道。
- 注册消息（长度前缀字段，避免分隔符歧义）：

```text
chast-register-v1 | id | fingerprint | unix_timestamp
```

  请求体：

```json
{"id":"devbox","public_key":"<base64url RawStd>","fingerprint":"AB12…",
 "timestamp":1761300000,"signature":"<base64url>"}
```

  首次登记写入 `chast-server-state.json`；后续续约公钥必须一致，否则
  `409 host id is bound to another key`。指纹只在首次登记时可采用，防止他人
  换绑展示指纹。
- 服务器签名绑定：

```text
payload  = {"v":1,"id":"devbox","pk":"…","fp":"AB12…","iat":1761300000}
binding  = "CHASTB1." + base64url(payload) + "." + base64url(sig)
domain   = chast-host-binding-v1 | payload
```

  绑定在注册、查询（含离线身份）中返回。查看者校验后可确认“这个 ID 属于这把
  公钥，且由我固定的服务器签发”，替代单纯信任 HTTP 响应。

## 3. 一次性挑战

所有挑战由 `registry.IssueChallenge(id, purpose)` 生成 32 字节随机 nonce，
30 s 内单次有效，`CheckChallenge` 以常量时间比较；nonce 与用途、ID 绑定。

| 数据面 | 挑战 | 应答 |
| --- | --- | --- |
| UDP 会合 keepalive | `keepalive_ack` 携带 `nonce` | `keepalive` 重发并带 `signature` |
| UDP 中继 | `relay_challenge` | `relay_auth`，消息含中继端口与观察地址 |
| TCP/WS 载体 | `CHASTT-CHALLENGE1 {nonce}` | `CHASTT-AUTH1 {host_id,nonce,signature}` |

消息域分别为 `chast-keepalive-v1`、`chast-relay-v1`、
`chast-carrier-host-v1`，字段全部长度前缀编码，签名覆盖观察地址，防止把
主机链路重放到另一个端口/地址。

## 4. 候选与 NAT 信息

- 主机代理从绑定的 UDP 套接字枚举本机单播地址（最多 16 个），随 keepalive
  上报 `local_addrs`；服务端只把这些当作同网段提示，公网地址仍以观察值为准。
- 主机代理分别记录会合端口与中继端口观察到的公网映射；端口稳定为
  `asymmetric`（锥形 NAT），不同端口为 `symmetric`，未知为 `unknown`。
- 查询响应新增 `candidates`（公网观察地址 + 局域网地址去重）、`local_addrs`、
  `nat_type`；查看者按 `nat_type` 决定打洞预期，直连失败仍回退中继。

## 5. 共享载体

现有per-host载体（主机 `P+1`、中继端口 TCP）保留，用于直连和旧服务端。
新增 `chast-server --carrier-listen 0.0.0.0:8445`（空值禁用），一个 TCP 端口
同时服务所有主机：

- 主机链路：`CHASTT-HOST2\n` + `{"host_id":…}`，随后
  `CHASTT-CHALLENGE1` → `CHASTT-AUTH1` → `CHASTT-OK2`；认证通过后该链路只
  承载 `u32le length | payload` 帧。同一主机重新连接会替换旧链路并断开其查看者。
- 原始 TCP 查看者：`CHASTT-V2\n` + `{"host_id":…,"token":…}`。令牌来自认证
  查询的 `carrier_token`，仅在该主机在线时返回；租约续期保持不变，租约失效后
  重新注册会轮换，旧令牌立即失效。
- WebSocket 查看者：`GET /chast`，子协议 `chast-carrier.v1`，首条 binary
  message 为同样的 JSON hello；之后 binary message 直接承载帧。
- 配对语义与按端口载体一致：同一主机同一时刻一个查看者，第二个连接被关闭并
  计入 `busy`；主机链路断开时关闭查看者；查看者离开后主机链路保留。
- 帧上限 64 KiB、握手 10 s、主机空闲 90 s、查看者空闲 60 s、写超时 30 s；
  统计暴露 `hosts`、`host_links`、`viewers`、`busy`、`rejected`、
  `to_host_bytes`、`to_viewer_bytes`。

主机代理在注册响应里看到 `carrier` 时优先连接共享载体，否则回退到中继端口
TCP；查看者从隧道 `path` 事件拿到 `carrier`/`carrier_token`，`chast-quic`
与 Flutter 把同样的参数交给本地 QUIC 桥。共享载体只搬运数据报，QUIC 的
SNI、证书指纹、令牌与审批完全不变。

## 6. 服务端 API 变化

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| `POST` | `/v1/hosts` | 签名注册/续约；响应含 `binding`、`carrier`、`carrier_token` |
| `GET` | `/v1/hosts/{id}` | 在线时含候选、NAT、共享载体与令牌；离线时仍返回身份与绑定 |
| `DELETE` | `/v1/hosts/{id}` | 下线并释放中继端口（保留永久身份） |
| `DELETE` | `/v1/identities/{id}` | 管理员重置丢失密钥的主机身份 |
| `GET` | `/v1/server` | 版本、服务器公钥、会合地址、共享载体、TTL |
| `GET` | `/v1/stats` | `hosts`、`identities`、`relay`（含 `ports`、`shared_carrier`） |
| `GET` | `/healthz` | 存活检查 |

持久化：`--state chast-server-state.json` 保存身份与租约，重启后 ID 绑定与
中继端口分配可恢复；`--host-ttl`（默认 60 s）与 `--offline-after`（默认 30 s）
分别控制租约和在线判定。

## 7. 测试与验收

自动化：

- Go：注册签名/公钥换绑、离线查询、挑战一次性与过期、keepalive/relay 签名、
  共享载体主机认证、原始/WS 查看者配对、忙拒绝、链路断开清理、令牌轮换、
  `carrier_token` 不出现在离线响应；`go vet ./...`、`go test ./...`。
- C++：`chast-carrier-test` 覆盖共享 hello 的魔数、host id + token、缺令牌
  拒绝；`ctest -C Release` 包含 `quic_carrier_tcp`/`quic_carrier_ws`。
- Flutter：`TunnelEvent` 解析 `carrier`/`carrier_token`，会话页选择共享载体；
  `flutter analyze`、`flutter test`。

环境限制：

- 本机单网卡、无真实 NAT/IPv6 路由器，`symmetric` 分类与局域网候选的真实
  跨网行为需要双机复核；回环上分类结果为 `asymmetric`。
- 共享载体尚未经过真实 HTTP 代理/CDN；WebSocket 代理行为留待部署环境验证。
- 共享载体与按端口载体都是单查看者；多查看者需要先改造 `HostServer` 会话层。
- 服务端 HTTP 仍为明文，TLS 终止、限流与指标属于下一阶段（M10.2）。
