## 1. 按模块比较

“已有”表示存在可执行实现，不代表实机效果与 RustDesk 相同。“缺少”表示在当前发射端源码、协议和配置中未找到相应完整路径。

| 模块 | 当前发射端 | 本地 RustDesk | 差异及影响 |
| --- | --- | --- | --- |
| 运行与服务 | Win32 托盘、便携模式、SYSTEM 服务及桌面会话 worker；服务可重启 worker、跟随 Windows 会话 | Windows 服务、桌面进程、连接管理器及 IPC | 基础常驻能力已有；本项目服务和交互审批的结合不足，见下一行。不是缺少 Windows 服务。[P01][R01] |
| 登录与审批 | 交互模式支持密码、点击审批、Both；有 TOTP、签名可信设备、IP/CIDR 限制。**服务模式强制永久密码，关闭临时密码和点击审批** | 连接通过 CM/IPC 进入批准流程，支持按审批模式判断，并单独处理登录屏幕条件 | 认证功能有基础，但“装成服务后仍由本地用户审批”的行为未对齐；不能把服务和托盘能力合并视为全部可用。[P02][R02] |
| 会话内提权 | 有本地 `runas` 用于安装/系统操作；未找到远程请求提权及响应协议 | `ElevationRequest` 启动 portable service，返回结果 | 便携远程支持过程中，不能获得相同的会话内提权流程；本地安装时弹 UAC 不等价。[P03][R03] |
| 多连接与本地管理 | 默认 2、配置上限 8；握手、权限、审计按连接。输入采用独占租约。本地权限、聊天、发文件默认转给最近准入的 `focused` 连接 | 连接具有 id；CM 按 `conn_id` 聊天、改权限、关闭连接 | **部分实现**。缺少明确的目标会话选择，双人同时连接时本地操作的对象不够明确。连接名额上限属于本项目策略。[P04][R04] |
| 全局策略与实时撤权 | 共享策略掩码、版本同步和传输层限制；全局关闭传播到已有及待审批连接，重新启用不自动恢复旧授权 | 按连接权限、全局选项和服务订阅控制 | 之前的跨连接撤权缺口已修复。后续仍需对权限语义逐项比对，不宣称所有授权规则相同。[P05][R04] |
| 单屏、合并屏与多人选屏 | 有 DXGI 单屏、合并桌面、显示切换；registry 只有一份 `desktop_info` 和一个 `desktop_publisher`，跟随者切屏返回 Busy | 按显示器创建视频服务；连接可 add/sub/set 显示器订阅，同一连接可订阅多屏 | **主要未对齐项**：A 看屏 1、B 看屏 2不能作为独立订阅工作；生产者离开还需要跟随者接管采集编码。接收端开多个窗口并不能补齐这个能力。[P06][R05] |

| 色彩与文字清晰度 | GPU BGRA → NV12，即 4:2:0；HDR 采集结果转为 SDR 输出链路 | 编码服务支持按能力选择 I444 等路径，也有平台相关色彩处理 | 未实现对应的 4:4:4 选项；小字号彩色文字、细线可能有色度损失。HDR 功能存在不等于 HDR10 端到端；不能仅凭源码断言两边色彩效果优劣。[P08][R06] |
| 静止桌面与关键帧 | `NoNewFrame` 时，有关键帧请求且缓存有效就重复编码；重建会清除旧缓存 | 新订阅者 snapshot；还有按条件限制次数的重复编码 | 静止首帧/关键帧滞留已修复。静态质量刷新策略仍不完全相同，不能把关键帧修复当作全部静态画质策略一致。[P09][R07] |

## 2. 建议先处理的四项

1. **独立选屏和共享视频服务**：把采集编码的生命周期从首个观看者移到按显示器管理的服务。验收：A 看屏 1、B 看屏 2；A 退出不重建 B 仍在使用的流。
2. **按会话 ID 管理**：列出当前连接，聊天、文件、撤权和断开都明确目标。验收：仅撤销 A 的剪贴板、回复 B，结果对象准确。
3. **所有订阅者参与 QoS，限制媒体排队时间**：采集不能以生产连接发送成功为全体广播前提。验收：A 慢/B 快以及反向组合，记录每个连接的画面年龄、队列与关键帧恢复。
4. **编解码能力协商**：Hello 交换实际支持的格式/色度，定义共享编码的兼容策略。验收：H.264-only 与 HEVC/AV1 接收端按不同顺序加入时有一致、明确的结果。

前三项对应旧报告尚未完成的 F05/F07/F06，第四项对应 F08。服务审批与提权、防休眠、文件分页和文件剪贴板可作为后续独立模块；不把 GPU-only 等有意取舍直接列为错误。

## 3. 已修复项与验证边界

- 静止画面关键帧：当前 `NoNewFrame` 分支使用有效 GPU 缓存帧响应请求。
- 跟随会话请求：显示跟随明确返回结果，OS 登录/WTS 进入对应 handler；独立选屏仍未实现。
- 全局策略：共享掩码和版本同步已落实，重新打开开关不会静默授予旧连接权限。
- 音频权限组合：先分发后处理发布者自身权限，其他有权限者不再依赖发布者的音频权限。

这些行为在 `tests/host_parity_test.cc` 中有针对性回归；本轮核查了源码和测试断言，没有重新运行产品测试，也没有触发本机输入、登录、锁屏或修改显示拓扑。旧测试成绩和上一轮 QUIC 黑洞试验均属于已有证据，不能改称本轮双机 A/B 成绩。

本轮源码已能确认共享流、发送依赖、能力字段、文件上限及缺少入口。实际首屏、弱网延迟、色彩、听感、硬件恢复和驱动兼容性仍需真实设备对照。
