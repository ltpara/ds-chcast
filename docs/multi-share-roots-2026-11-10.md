# 多共享根与盘符

日期：2026-11-10。接续 [发射端模块对比](host-rustdesk-module-comparison-2026-11-08.md) 的 G18/C31/C34 缺口；本轮只做“可授权多个共享根/盘符”，可协商压缩随后由同日 v66 的 [文件传输压缩](file-compression-2026-11-10.md) 补齐。RustDesk 对照仍为本地固定提交 `7423dced37845c48093b6f71bd82e4a16cc8c79d`：它允许把多个本地目录加入文件传输的共享列表，观看端在顶层看到每个共享根并逐层浏览；本轮按同样的行为与路径语义实现，不引入其代码或依赖。

## 用户行为

主机设置新增“共享文件夹”列表，最多 16 项，每项必须是绝对目录（盘符根如 `C:\` 或 UNC 路径），以分号分隔保存在 `host.ini` 的 `file_share_roots=`。未配置时行为与旧版完全一致：只共享“接收文件夹”一个根。配置后，接收文件夹自动加入共享列表并去重，仍是上传的默认落点。

观看端文件面板顶层显示每个共享根的别名，按名称排序，可以像普通文件夹一样逐层浏览、下载、递归下载、新建/重命名/删除和上传。别名规则：

- 普通目录取文件夹名（`D:\资料` → `资料`）。
- 盘符根取盘符（`C:\` → `C`），避免别名里出现冒号。
- 与已有别名冲突时追加 ` (2)`、` (3)`（不区分大小写比较），并保证不截断 UTF-8 多字节字符。
- `.chast-partial` 不会被当作共享根。

共享根本身不能被重命名或删除：顶层是虚拟别名，把别名当作空相对路径发给主机时会被拒绝。别名下的内容仍受原有沙箱约束：绝对路径、`..`、反斜杠、跨 reparse point 的路径一律拒绝，受保留的 `.chast-partial` 也不可见。列表请求仍按目录优先、UTF-8 字节序分页；顶层别名数量不超过 16，不受分页游标影响。

## 主机和协议

协议版本保持 **v65**，没有新增或修改任何线上字段：多共享根是主机本地的路径映射层。共享列表为空时主机继续把相对路径直接解析到接收目录，旧观看端连接带共享根的主机时，顶层别名就是一个普通目录，浏览、下载和上传语义不变。

会话建立时主机按“接收文件夹 + `file_share_roots`”构造别名并去重，然后逐个用 `GetFileAttributesW` 检查：不存在、不是目录或是 reparse point 的条目会被跳过并写日志。任何请求（列表、下载、文件操作、上传）都先在顶层拆分别名，命中后把剩余相对路径交给原来的 `resolve_receive_path`/`apply_file_operation`；未知别名返回 `NotFound`，其余校验与单根模式一致。上传的 `relative_path` 为空时仍落到接收文件夹本身，不经过别名拆分。

设置文件按行解析，`#`/`;` 只在行首作为注释；`file_share_roots` 的值按分号拆分、去除首尾空白并跳过空项；相对路径、含 NUL/CR/LF 的项会被跳过并在加载警告中列出；超过 16 项的部分被忽略并警告。保存时校验数量、空项、换行、分号和绝对路径，失败则整个设置文件不落盘。服务模式下保存安全页时，`file_share_roots` 与接收文件夹等字段一起参与“打开页面期间是否被并发修改”的合并检查。

## 边界

- 仅 Windows 主机；共享根必须在会话建立时可访问且不是 reparse point，之后新增的目录要重连才生效。
- 顶层别名不参与分页；单个共享根内部仍受 1024 项/页的分页限制。
- 别名只是虚拟视图，不改变文件系统 ACL；主机进程能读写的目录就能被拥有文件传输权限的观看端浏览。
- 共享根不可通过远程操作重命名、删除或移出列表；只能在主机设置里修改。
- G18 文件管理范围已由同日 v66 的 CFIL v2 压缩补齐，见 [文件传输压缩](file-compression-2026-11-10.md)。
