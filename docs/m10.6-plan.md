# M10.6 — 独立中继节点与健康探测

## 1. 背景与目标

RustDesk 的 `hbbs` 本身不转发媒体：`relay-servers` 只是 hbbr 地址列表，
`check_relay_servers` 周期性探测这些地址，`get_relay_server` 为需要中继的会话
选择一个可用节点。M10.5 的 `--relay-servers` 只是同一 chast-server 实例的多个
地址（多网卡/VIP），无法把中继负载放到另一台机器。本阶段补上 hbbr 式的独立
中继进程：

- 新增 `chast-relay` 进程，独占 UDP/TCP 中继端口与可选共享载体；
- hbbs 新增 `--relay-nodes`（URL 列表）、`--relay-node-key` 与
  `--relay-node-health`，注册时向节点申请租约并把该节点地址下发给主机；
- 节点离线/租约失败时按健康状态跳过并回退到下一节点；全部节点不可用时
  回退到本机 `--relay-servers`（chast 扩展，hbbs 此时直接失败）；
- 主机代理与查看者代理**不改协议**：仍然使用 `relay_hello`、`relays` 与
  `relay_challenge`，只是地址从本机变成节点。chast 协议保持 v23。

## 2. 能力对照

| hbbs / hbbr | chast（本阶段前） | 本阶段 |
| --- | --- | --- |
| `relay-servers` 地址列表 | `--relay-servers`，只能是本实例地址 | `--relay-nodes` URL 列表；本机列表保留为回退 |
| `check_relay_servers` 定期探测 | 无 | 每 `--relay-node-health` 请求节点 `/healthz`，记录 RTT、租约与载体在线快照 |
| `get_relay_server` 选择节点 | 轮询本机地址 | 健康节点轮询；已有租约保持节点，节点失效后才迁移 |
| hbbr 独立进程 | 无 | `chast-relay`：控制面 + UDP/TCP 中继 + 共享载体 |
| hbbs 向 host 下发 relay_server | 下发本机 `relay`/`relays` | 下发节点地址；续约重新申请同一节点的租约 |
| hbbr 按 uuid 配对 | 按主机分配 UDP 端口 | 节点按租约分配端口；QUIC 不可解复用，端口仍按主机独占 |
| 中继健康状态只影响新会话 | — | 节点失效时新注册回退；已有租约在下次注册刷新时迁移 |

不做：迁移进行中的 QUIC 连接；节点之间的共享载体漫游；GeoIP 选路；控制面
mTLS（可给节点配 TLS 或放在反向代理后）。

## 3. 节点控制协议

`chast-relay` 至少需要 `--key`（与 hbbs 的 `--relay-node-key` 相同）和
`--advertise`（节点对主机/查看者公布的主机名或 IP）。控制面走 HTTP，可用
`--tls-cert`/`--tls-key` 启用 HTTPS。

| 方法 | 路径 | 认证 | 说明 |
| --- | --- | --- | --- |
| `POST` | `/v1/leases` | Bearer key | 申请或续约主机租约 |
| `DELETE` | `/v1/leases/{id}` | Bearer key | 释放租约与端口 |
| `GET` | `/healthz` | 无 | 存活、节点名、租约数与共享载体在线列表 |
| `GET` | `/v1/stats` | Bearer key | 中继/载体/租约统计 |

`POST /v1/leases` 请求：

```json
{"id":"devbox","public_key":"<base64url>","carrier_token":"<32 hex>","ttl_sec":120}
```

响应：

```json
{"id":"devbox","port":41100,"relay":"203.0.113.7:41100",
 "carrier":"203.0.113.7:21119","expires_in_sec":120}
```

语义：

- 同一 ID 重复申请是幂等的：公钥一致则续约并返回原端口；公钥不同返回
  `409`，防止另一个 ID 抢占已验证的主机槽位；
- 节点只接受 5 s–1 h 的 TTL；hbbs 传两倍主机 TTL，使 hbbs 短暂不可用时
  主机链路不会立刻失效；
- 到期租约由节点清理协程释放端口、关闭主机/查看者链路与共享载体链路；
- 端口从 `--relay-ports` 预绑定集合中分配；每个端口在租约申请后按
  `--advertise` 解析出的本机地址重绑（`relay.Manager.BindHost`），保证
  回包源地址与主机/查看者拨号地址一致；
- `--carrier-listen` 非空时节点提供共享载体，租约响应带 `carrier`；
  否则主机退回每端口的 TCP 载体。

节点鉴权：节点只保存 hbbs 下发的公钥与载体令牌，`relay_hello`、
TCP/WS 载体握手仍使用现有一次性挑战；节点不需要回连 hbbs。控制面 key
为空时节点拒绝启动。

## 4. hbbs 侧

- `internal/relaypool`：URL 规范化（仅 http/https、无路径）、健康循环、
  轮询、粘性申请、best-effort 释放、按节点缓存在线列表。
- 注册流程：先向首选节点（该主机上次的节点）申请租约；首选不可用时按
  轮询尝试其余健康节点；全部失败则记录警告并回退本机中继。切换节点时
  异步释放旧租约。
- `Host` 新增 `RelayNode`（节点 URL）与 `Carrier`（节点共享载体地址）；
  本机分配时清空两者。lookup 的 `relay`、`carrier`、`transport` 与
  `relay_only` 都按租约来源返回。
- 载体在线：健康响应带共享载体已连接的主机 ID 列表，hbbs 缓存后用于
  `online`/`transport=carrier` 判定；延迟上限等于健康间隔。
- 管理通道：`stats` 增加节点计数与健康数；`hosts` 增加 `node=`；
  `rs` 在节点模式下同时列出节点状态，`tg` 预览下一个健康节点或本机地址。
- 指标：`/v1/stats` 增加 `relay_nodes`；`/metrics` 增加
  `chast_relay_nodes`、`chast_relay_nodes_healthy`。

## 5. 主机与查看者路径

主机代理不需要改动：

1. 注册响应 `relay`/`relays` 指向节点；代理向该地址发 `relay_hello`；
2. 节点用 provisioned 公钥校验 `relay_auth`，把主机侧 UDP 地址记到端口；
3. 查看者查询得到节点地址，把 QUIC 直接发往节点；节点按端口把数据报
   原样转发给主机代理；
4. 共享载体 / 每端口 TCP 载体与 M10.0 相同，只是监听在节点。

## 6. 测试

- `internal/relaynode`：租约幂等、公钥冲突、TTL 过期释放、控制面鉴权、
  节点挑战与 UDP/TCP 转发、载体令牌、健康输出；
- `internal/relaypool`：URL 校验、健康/离线切换、轮询与粘性、全部不可用、
  释放与 linked 快照；
- `internal/api`：节点注册/续约/切换/回退、远程载体在线、注销释放、
  `transport` 与 `relay_only`；
- `internal/admin`：节点状态输出与 `tg`；
- 真实二进制回环：hbbs + chast-relay + 主机/查看者代理，验证节点中继、
  节点故障后的健康降级与回退、节点恢复后的新租约分配。

## 7. 验证记录

2026-10-25，独立中继节点（M10.6）在单机回环上验证。拓扑：`chast-relay`
（控制面 `127.0.0.1:18447`、UDP/TCP 端口 `41100-41199`、共享载体
`127.0.0.1:18448`、`--advertise 127.0.0.1`、`--key m106-node-secret`）+
`chast-server`（API `18443`、会合 `18444`、本机中继 `41200-41299`、本机载体
`18445`、管理 `18446`，`--relay-nodes http://127.0.0.1:18447
--relay-node-key m106-node-secret --relay-node-health 1s --host-ttl 30s`）+
主机/查看者代理 + UDP 回显。协议仍 v23，代理未改动。

- 远程租约：devbox 注册得到 `relay=127.0.0.1:41100`、
  `carrier=127.0.0.1:18448`；节点 `/healthz` 返回
  `{"ok":true,"node":"relay-local","leases":1}`。hbbs 的 `/v1/server`、
  `/v1/stats` 带 `relay_nodes`，`/metrics` 为 `chast_relay_nodes 1`、
  `chast_relay_nodes_healthy 1`。
- 数据面：`viewer --mode relay` 输出 `remote=127.0.0.1:41100`，经节点转发的
  UDP 回显三次成功（`probe-ok`）；节点端口统计 `to_host_bytes=51`、
  `to_viewer_bytes=51`，hbbs 本机中继端口计数保持 0。
- 管理通道：`stats` 增加 `relay_nodes=1 healthy=1`；`hosts` 显示
  `relay=41100 relay_host=127.0.0.1 node=http://127.0.0.1:18447`；`rs`
  先输出节点状态再列本机地址（`status=up leases=1 linked=0`）；`tg` 返回
  `next=http://127.0.0.1:18447`。
- 节点故障与回退：停止节点后 1 s 内 `rs` 变为 `status=down` 并带
  `dial tcp ...: connectex: No connection could be made`；主机下一次续租
  记录 `relay node unavailable; falling back to the local relay` 与
  `no healthy relay node is available`，自动回退本机中继
  （`relay=127.0.0.1:41200`、`node=-`、`assigned=1`），本地中继回显三次
  成功。
- 节点恢复：重启节点后下一次续租迁回 `127.0.0.1:41100`，本机端口释放
  （`assigned=0`），新查看者经节点回显三次成功；节点 `/healthz` 恢复
  `leases=1`。
- 共享载体：主机侧本地载体桥（`19001 -> 19434`）就绪后链路建立，节点
  `/healthz` 返回 `linked:["devbox"]`，`hosts` 显示 `carrier=true`；
  `viewer --mode carrier` 输出 `path="carrier 127.0.0.1:18448"`，UDP 回显
  往返成功；节点 `/v1/stats` 的 `shared_carrier` 为 `hosts:1`、`viewers:1`、
  `to_host_bytes:45`、`to_viewer_bytes:45`。连续启动 10 个 carrier viewer
  均得到 `ready`（一次早期启动在宿主载体端点就绪前报
  `host has no shared carrier address`，重试成功）。
- 自动化：`gofmt -l .` 无输出，`go vet ./...`、`go build ./...`、
  `go test ./... -count=1` 通过。`internal/relaynode` 覆盖租约幂等、公钥
  冲突、TTL 清理、控制面鉴权、UDP/TCP 转发与载体令牌；`internal/relaypool`
  覆盖 URL 校验、健康翻转、轮询与粘性、`Preview`、释放与 linked 快照；
  `internal/api` 覆盖远程注册/续约/切换/回退/注销释放、远程载体在线与指标；
  `internal/admin` 覆盖节点状态、`carrier` 与 `tg`。
- 已知限制：节点故障时已有查看者不会迁移，要等下一次注册刷新或新查看者；
  节点健康快照最多滞后一个 `--relay-node-health`；控制面默认明文，生产需
  `--tls-cert` 或反向代理；跨机时钟偏差超过租约 TTL 会让节点提前释放。
