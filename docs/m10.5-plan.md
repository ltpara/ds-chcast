# M10.5 — IP 变更审计与中继地址轮换

RustDesk hbbs 在 `RegisterPk` 里维护 `IP_CHANGES`，记录同一主机短时间内
公网 IP 的抖动，并只对 180 s 窗口内出现过至少两个 IP 的条目保留审计；
管理通道用 `ip-changes`/`ic` 查看、分页、删除。中继侧，hbbs 支持
`relay-servers` 列表（`rs` 运行时设置）、按查询轮换
（`get_relay_server`）以及 `test-geo`/`tg` 预览。chast 目前只公布单一
`--advertise` 中继地址，也没有 IP 变更审计。本阶段补齐这两块管理面能力，
线协议仍为 v23。

## 1. 缺口与范围

| hbbs | chast（本阶段前） | 本阶段 |
| --- | --- | --- |
| `IP_CHANGES`：注册时比较观察 IP，180 s 窗口；`ic` 剪掉 360 s 以上或仅一个 IP 的条目 | 无 | `internal/ipchange`；HTTP 注册与认证后的 keepalive 都记录观察 IP；管理通道 `ic` |
| `relay-servers` 列表、`get_relay_server` 轮换、`rs`/`tg` | 只有单一 `--advertise` 中继主机 | `internal/relayaddr`；每主机粘性分配、注册下发 `relay` + `relays`；管理通道 `rs`/`tg` |
| `check_relay_servers` 定期 TCP 探测并切换活动中继 | 无 | 不做；本阶段所有地址必须指向同一 chast-server 实例（多网卡/VIP/端口映射） |

不做独立 hbbr 进程与跨服务器中继协议：chast 的中继端口按主机动态分配，中继
状态保存在本进程内，多个真正独立的中继需要一套跨服务器握手与会话迁移协议，
不能用一个地址列表冒充。`tg` 也因此只做“下一次轮换结果”预览，不读取
GeoIP。

## 2. IP 变更审计

`internal/ipchange.Tracker` 与 hbbs 的语义对齐：

- 首次观察到某 ID 的 IP 只作为基线，不生成审计条目。
- 观察 IP 改变时：没有条目则以当前时间开窗并记录上一个与新 IP（第一次
  变化就能在 `ic` 中看到成对地址）；窗口内已有条目则累加/新增；窗口超过
  180 s 则重置窗口，只保留新 IP。
- 读取/统计时剪枝：条目年龄达到 360 s 立即删除；只包含一个 IP 的条目
  不展示也不计数，但保留在内存中直到再次变化或老化。hbbs 的 `ic` 会直接
  删除单 IP 条目；chast 的指标抓取是自动的，若同样删除会让审计在两次变化
  之间被清空，因此这里有意只在输出层过滤。
- 基线表最多保留 65536 个 ID，超出时淘汰最久未观察的条目；条目同样有
  上限，避免异常流量撑爆内存。
- 并发安全；`SetClock` 供测试推进时间。
- 计数：`tracked`（当前审计条目）与 `changes`（累计变更次数，新增指标）。

记录点：

1. `POST /v1/hosts` 签名校验与注册成功后，用 `clientIP`（受
   `--proxy-header` 影响）记录一次。
2. 会合服务 `KeepaliveAuth` 在 `TouchChallenge` 成功后，用 UDP 实际源 IP
   记录一次。未通过签名/挑战的报文不能影响审计，避免伪造源地址污染。

两处使用同一个 Tracker：主机每 `TTL/2` 续约一次，keepalive 只携带观察
地址；任一通路先看到变化就记录，另一通路随后看到相同 IP 不会重复计数。

## 3. 中继地址列表与分配

`internal/relayaddr.List` 保存一组**不含端口**的主机名/IP（IPv6 用方括号），
因为 chast 的每个主机在本实例上有独立的中继端口，条目端口必须由注册时的
分配结果补全；拒绝 `host:port`、URL 与空项。列表支持 CSV 设置、去重、
恢复初始值（`rs -`）与轮换计数。

分配规则：

- 注册：新主机按轮换计数选择列表中的一个地址；已有租约若其
  `RelayHost` 仍在当前列表中则保持，避免每次 `TTL/2` 续约都换中继。
- 注册响应新增 `relays` 数组：列表中的每个地址都与该主机的中继端口拼接，
  主机代理据此接受来自任一地址的中继挑战；`relay` 仍是本次分配的主地址，
  兼容旧代理。`carrier` 也使用分配到的地址。
- 注册表租约保存 `RelayHost`；查询响应、`keepaliveAck.relay` 使用租约中的
  地址，而不是启动时的单一 `--advertise`。
- 中继端口的 UDP/TCP 监听在注册时重绑到租约地址（`relay.Manager.BindHost`），
  这样查看者访问 `B:port` 时收到的回包源地址也是 `B:port`。通配监听会按路由
  选择源地址（通常总是启动时的主地址），多 IP 主机上的第二个地址会被查看者
  丢弃。租约地址不是本机地址或无法解析时回退 `--relay-listen`；同一租约的
  续约不重复重绑。
- 管理通道 `rs a,b` 只影响之后的分配；已有租约保留自己的地址，直到该地址
  不再出现在列表中且下次续约发生。`rs -` 恢复启动配置。
- `tg <ip1> [ip2]` 消耗一次轮换并返回 `next=<addr>`，与 hbbs 的
  `get_relay_server` 忽略地址、直接轮换的行为一致。
- 默认列表是 `[--advertise]`；新增 `--relay-servers a,b` 可替换启动列表。

主机代理：

- `registerResult` 增加 `relays`；解析每个地址（DNS 名解析出全部 A/AAAA），
  维护允许的中继地址集合。
- `RelayChallenge` 与服务器控制报文识别改为“源地址 ∈ 集合”；签名使用挑战
  源端口，因此同一实例的不同地址（同一分配端口）都能完成握手。
- 集合为空时退回单地址行为，兼容不返回 `relays` 的旧服务端。

## 4. API 与运维面

- `POST /v1/hosts`：响应 `relays`（可选）、`relay`/`carrier` 使用分配地址。
- `GET /v1/hosts/{id}`：`relay`/`carrier` 从租约读取，未设置时回退
  `RelayHost`。
- `GET /v1/server`：新增 `relay_servers`。
- `GET /v1/stats`：新增 `ip_changes` 与 `relay_servers`。
- `/metrics`：`chast_ip_change_events_total`、
  `chast_ip_change_tracked`、`chast_relay_servers`。
- 启动日志输出中继地址列表数量与内容。

## 5. 管理通道

在 M10.4 命令基础上新增：

| 命令 | 说明 |
| --- | --- |
| `relay-servers`/`rs` | 列出当前中继地址 |
| `rs <a,b,...>` | 替换列表（仅影响后续分配） |
| `rs -` | 恢复启动配置（chast 扩展） |
| `ip-changes`/`ic` | 审计条目数 + 前 10 条（按 ID 排序） |
| `ic <id>` / `ic <id> -` | 单条详情 / 删除单条（删除后下次观察重新建立基线） |
| `ic <start> [count]` | 分页 |
| `ic -` | 清空审计与基线（chast 扩展，与 `pr -`/`ib -` 一致） |
| `test-geo`/`tg <ip1> [ip2]` | 校验 IP 参数并预览下一次轮换结果 |

`stats` 增加 `ip_changes tracked=... changes=...` 与
`relay_servers=<n>`；`hosts` 输出追加 `relay_host=...`，便于确认粘性分配。

## 6. 测试与验收

自动化：

- `internal/ipchange`：基线不产生条目、窗口内多 IP 累加、180 s 重置、
  单 IP/360 s 剪枝、删除后重新基线、清空、容量淘汰、并发。
- `internal/relayaddr`：主机名校验、拒绝端口/URL/空项、去重、轮换顺序、
  `Join` 端口拼接（含 IPv6）、重置、并发分配。
- `internal/api`：注册响应 `relays` 完整、同一主机续约地址稳定、不同主机
  轮换、查询/载体使用租约地址、IP 变更统计与指标、`/v1/server` 列表。
- `internal/admin`：`rs` 列表/设置/重置/非法输入、`ic` 分页/详情/删除/
  清空/剪枝、`tg` 预览与非法 IP、`stats`/`hosts` 新字段。
- `internal/rendezvous`：认证 keepalive 记录 IP 变更，错误签名与候选不匹配
  不记录；新 IP 在下一次认证后进入审计。
- `internal/agent`：多地址挑战集合校验（含 DNS 多 IP）、集合为空回退、
  注册刷新更新集合。
- `internal/relay`：`BindHost` 把端口绑定到指定本机地址，查看者看到的中继
  回包源地址与目标地址一致，两个方向都能转发。
- `go vet ./...`、`go build ./...`、`go test ./... -count=1`。

### 验收标准

1. 同一 ID 在 180 s 内从 A→B→C，`ic` 能看到含 B/C 的条目；360 s 后或只剩
   一个 IP 时自动消失；`ic <id> -` 与 `ic -` 生效。
2. 两个新 ID 注册时按列表轮换得到不同中继地址；同一主机续约时地址不变；
   `relay` 与 `relays` 指向同一实例与同一端口。
3. 真实主机代理在分配地址上完成中继挑战与中继会话；DNS 名称解析出多个 IP
   时任一来源都能通过挑战校验。
4. `rs` 修改后只影响新注册；`rs -` 恢复；`tg` 预览与下一次分配一致。
5. 现有 M10.0–M10.4 测试与真实回环不回归，文档记录验证结果。

## 7. 验证记录

2026-10-25，Windows 10.0.26200 本地回环：`chast-server --relay-listen
0.0.0.0 --relay-servers 127.0.0.1,127.0.0.2`，主机 devbox/devbox2/devbox3、
中继模式查看者与 UDP 回显目标。

1. 轮换与粘性：devbox 注册得到 `127.0.0.1:41100`，devbox2 得到
   `127.0.0.2:41101`；两者注册响应都带两个端点的 `relays`，主机日志为
   `relay challenge set updated endpoints="[127.0.0.1:41100 127.0.0.2:41100]"`。
   两个主机都用 `--mode relay` 的查看者打通 UDP 回显
   （`m10.5-relay-probe`、`m10.5-relay2-probe`）。
2. 中继源地址：`netstat` 显示端口按租约绑定到分配地址
   （`UDP/TCP 127.0.0.1:41100`、`127.0.0.2:41101`）。修复前通配监听按路由
   选择源地址，访问 `127.0.0.2:41101` 的查看者收到来自 `127.0.0.1:41101`
   的回包并丢弃（回环下被误判为本地客户端，生产环境直接丢包）；
   `relay.Manager.BindHost` 在注册时重绑 UDP/TCP 监听后回包源地址与目标
   一致。devbox 重启并从 `127.0.0.4` 重新注册后仍保持 `127.0.0.1:41100`，
   查看者再次探测正常。
3. IP 审计：`ic` 看到 devbox 的 `127.0.0.1, 127.0.0.2` 在重启加入
   `127.0.0.4` 后变为
   `ips=127.0.0.1:4,127.0.0.2:2,127.0.0.4:2`；devbox2 为
   `127.0.0.1, 127.0.0.3`。回环下 HTTP 注册源固定为 `127.0.0.1`、keepalive
   源是主机绑定地址，因此同一主机在两个地址间交替计数；生产环境两条通路
   看到同一个公网地址，不会产生这种抖动。
4. 管理通道：`rs` 列出两个地址；`rs 127.0.0.2` 后 devbox/devbox2 的
   `relay_host` 保持 `.1`/`.2` 不变，新注册的 devbox3 得到
   `127.0.0.2:41102` 且中继回显正常；`rs -` 恢复两地址；`rs bad:123`
   被拒绝（`must not include a port`）；`tg 192.0.2.10 192.0.2.11`
   返回 `next=127.0.0.1` 并消耗一次轮换。`ic 0 1` 分页、`ic devbox2 -`
   删除、`ic -` 清空（`cleared 2`，`changes` 保持 15）。
5. 指标与接口：`/metrics` 输出 `chast_ip_change_events_total 14`、
   `chast_ip_change_tracked 3`、`chast_relay_servers 2`；`/v1/stats` 的
   `ip_changes` 与 `relay_servers=2` 与之一致；`/v1/server` 的
   `relay_servers`、查询响应的 `relay`、`hosts` 的 `relay_host` 均与分配
   一致。
6. 回归：`go vet ./...`、`go build ./...`、`go test ./... -count=1` 全部
   通过；新增 `TestBindHostKeepsRelaySourceAddress`。
