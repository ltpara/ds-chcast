## 功能问题

### F1 / P1：同步用旧缓存覆盖其他设备的新修改

位置：`app/lib/address_book_sync.dart:142`、`:200`、`:233`；调用方 `app/lib/pages/home_page.dart:1695`。

触发：两台查看器同步同一账号。A 已缓存设备名称、标签或备注（修订号 1）；B 将其改为新值（修订号 2）；A 再同步，期间 A 并没有主动编辑。

当前行为：拉取只在本地字段为空时吸收服务器值；非空本地旧值被当成待上传修改。更关键的是，上传使用本次拉取到的 `peer.revision`，而非本地编辑所依据的修订号。服务器的修订号检查因此正常放行旧值覆盖。该问题同时影响名称、标签、备注以及仍有效的分组分配；多客户端交替同步可能反复覆盖。

独立复现输入：本地 `name=Old, revision=1`，服务器 `name=New, revision=2`。实际输出为 `merged=Old; push=Old; ifRevision=2`，预期新远端值应进入本地且不产生无编辑回写。期望行为断言失败。

建议：区分已同步缓存与真正的本地脏字段，记录编辑时的基准修订号。未编辑字段接受远端更新；本地修改使用原基准修订号进行条件写入，冲突时明确合并或提示。仅更换上传修订号还不足以解决缓存更新和冲突反复出现的问题。

### F2 / P1：退出登录后，晚到的同步结果重新保存旧账号

位置：`app/lib/pages/home_page.dart:1575`、`:1671`、`:1765`–`:1779`。

触发：地址簿请求仍在等待网络响应时，打开账号对话框并退出登录；然后原同步请求返回成功。

当前行为：退出先清空账号存储和 `_account`；同步任务仍持有旧 `account`，完成后无条件执行 `_accountStore.save(session)` 并恢复 `_account`。`mounted` 只检查页面是否存在，无法确认账号、服务器或登录代次仍相同。退出按钮在同步期间仍可使用。

独立复现：用 `Completer` 暂停地址簿响应，点击账号入口和退出登录，验证账号存储确实已清空；释放旧响应后，存储重新出现 `AccountSession`，保持退出状态的断言失败。

影响：界面和本地持久化恢复为已退出的账号，并可能覆盖后续登录状态。此结论不意味着服务端已撤销的令牌重新有效；服务器撤销成功时后续请求仍会拒绝该令牌。

建议：为账号和服务器切换建立会话代次；每个异步同步阶段完成后、尤其是上传与持久化前检查代次。退出时立即使旧任务失效，并防止旧任务在清理之后再次写入。

### F3 / P2：长会话结束录制时，过期的内存令牌导致自动归档被静默跳过

位置：`app/lib/pages/session_page.dart:710`–`:725`、`:864`–`:883`、`:1433`–`:1491`。

触发：启用录制自动上传，查看器已登录账号；通过直连或不需要持续访问票据续期的会话长时间录制，没有文件传输或重连触发该会话页刷新账号；录制结束时会话页持有的访问令牌已经过期。服务端访问令牌默认有效期为 30 分钟（`server/internal/account/store.go:38`）。即使首页已刷新并保存了新令牌，会话页仍可能保留旧快照。

调用链：`_trackRecording` 从跟踪集合移除已结束文件，然后调用 `_queueRecordingUpload`；后者直接检查 `_account.isActiveAt`，失败立即返回。真正会读取新令牌或续期的 `_activeAccount()` 在后面的 `_processRecordingUploads` 中，但文件根本没有入队，因此不会运行到这里。后续轮询也不再将该文件视为刚结束的录制。

影响：本地 MP4 保留，但用户开启的自动上传没有执行，也没有归档失败提示。持续续期访问票据的托管连接通常会避开此条件，因此不能泛化为所有超过 30 分钟的会话都会失败。

独立复现：会话组件先接收 `recording=true`，随后将可刷新账号模拟为过期并发送 `recording=false`。测试确认工具栏已先后反映录制中/已停止，但账号刷新资格检查次数仍为 0，期望至少尝试一次续期的断言失败。该用例使用模拟原生桥接和账号过期状态，不等同于 30 分钟以上真实录制实测。

建议：先保留完成文件及其账号归属，再由上传队列统一获取有效账号。短暂认证/网络失败保留待重试任务，并给出明确状态；不能在尝试续期前永久丢弃任务。

## S01 追加发现与修复：管理台账号竞态（F4 / P1）

位置：`server/internal/webadmin/assets/app.js` 的 `api`、`refreshSession`。

触发及影响：管理操作等待响应期间退出或换号，旧请求收到 401 后调用不绑定原账号的刷新与重试，可能使用新登录身份重发旧请求或把新登录退出；旧刷新在退出后完成仍调用 `writeSession`，把旧账号令牌重新写回浏览器会话存储；同时过期的两个请求会各自刷新同一刷新令牌。

修复：每个 API 操作绑定起始 auth 对象，检查响应读取、刷新和重试阶段的身份一致性；身份变化后取消旧请求，不用新账号重试或执行退出。令牌刷新成功后仅在原身份仍然有效时保存；同一登录的并发刷新共享一个 Promise，完成后清理。

验证使用 Node VM 执行实际管理台脚本中的认证/API 函数，仅替换启动和 DOM 渲染，不替换请求逻辑。三个竞态回归在修复前均失败，修复后全部通过。此验证不代替整个管理台的浏览器验收。

## S01 查看端 Strategy 闭环

查看端现在在账号认证后的目标 host lookup 中接收查看端策略 delivery，固定来源设备、revision、digest、随机 context 和五项设置。tunnel、WebSocket、录制上传、初始剪贴板与视图适配在 tunnel 建立前使用会话快照；会话启动后上报绑定查看器账号、设备、client key 和 delivery context 的逐键回执。回执失败不会拆已经建立的会话，也不会显示成功。

会话页新增账号/服务器/peer/连接设置身份代次。身份变化会先停止旧会话和 tunnel，再用新身份重新 lookup；旧 lookup 与 token renewal 的晚到响应会被拒绝。账号服务器与目标服务器不一致时不能启动 tunnel，避免错误账号 namespace。初始剪贴板切换会更新下一连接的有效快照，策略锁定时不绕过 managed 值。
