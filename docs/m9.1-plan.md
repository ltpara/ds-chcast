# M9.1 — 查看器画质、帧率与编码器偏好

更新时间：2026-10-24
分支：`feat/m7-security`
基线：M9.0 完成（协议 v20；Ctrl+Alt+Del、系统组合键、断线自动重连）。
本阶段将协议升到 v21。
参考：`D:\rustdesk` @ `c7f212d`（只做能力对照，不复制实现）

## 1. 范围与取舍

M9.0 之后，连接与输入已经完整；画面参数仍只有主机的全局配置，查看器
无法按当前网络或本机解码能力调整。M9.1 增加一组**会话内**的流参数偏好：

| 偏好 | 取值 | 效果 |
| --- | --- | --- |
| 画质 | 高清 / 均衡 / 流畅 | 视频预算的 100% / 75% / 50% |
| 帧率上限 | 自动 / 15 / 30 / 60 | 采集节奏的上限，ABR 仍可继续下调 |
| 编码器 | 自动 / H.264 / HEVC | 自动跟随主机配置；显式选择不可用时拒绝 |

不做的部分：

- 偏好不持久化到主机，也不跨设备共享：它属于这次查看会话，页面在每次
  重连后重新下发自己的选择。
- 不新增 HDR、色深、GOP 或码率绝对值输入。查看器只能压缩主机预算，
  不能超过操作者在主机上配置的上限。
- 不改多显示器合并视图（M9.3）；一块屏一条流仍是基本单位。

关键语义：

1. **主机预算是硬上限。** 主机的 `bitrate_kbps`（0 为编码器自动）减去音频
   预留后得到视频预算；查看器的画质档只在这个预算内取百分比。
2. **帧率上限不是目标。** ABR 仍按链路状况继续降帧；上限只是恢复时的
   天花板。上限高于主机配置时取主机配置。
3. **HEVC 是请求，不是保证。** 主机先创建替换编码器并确认它真的输出
   HEVC，才切换；硬件不支持或回退到 AVC 时回答 `Unsupported`，旧流不动。
4. **只重建编码器一次，切换失败不影响在跑的流。** 画质和帧率走
   `set_rate`，不重建；只有编码器变化才建新实例，成功后才换。

## 2. 协议 v21

版本从 20 升到 21，ALPN 保持 `chast/1`。新增两条控制消息：

| 类型 | 方向 | 载荷 |
| --- | --- | --- |
| `SetStreamOptions = 30` | 查看器 → 主机 | `u8 codec`、`u16 max_fps`、`u8 quality` |
| `StreamOptionsResult = 31` | 主机 → 查看器 | `u8 code`、`u8 effective_codec`、`u16 effective_fps`、`u8 effective_quality`、`u16 reason_len`、UTF-8 reason（≤256 B） |

编码器偏好：

| 值 | 名称 | 含义 |
| --- | --- | --- |
| 0 | Auto | 跟随主机 `codec` 配置 |
| 1 | H264 | 必须是 H.264 |
| 2 | HEVC | 必须是 HEVC，否则拒绝 |

画质档：

| 值 | 名称 | 视频预算 |
| --- | --- | --- |
| 0 | High | 100% |
| 1 | Balanced | 75% |
| 2 | Smooth | 50% |

结果码：

| 值 | 名称 | 含义 |
| --- | --- | --- |
| 0 | Ok | 已生效（或本来就一致） |
| 1 | Unsupported | 主机无法产出请求的编码器 |
| 2 | Failed | 替换编码器创建或 `set_rate` 失败 |
| 3 | Busy | 刚重建过编码器，稍后重试 |

`max_fps` 为 0 表示跟随主机配置，否则必须是 1..240。解析器拒绝越界值、
未知枚举和尾随字节；结果里的 `effective_*` 描述回答时**实际在跑**的流，
拒绝时也不例外，方便查看器把菜单恢复到真实状态。

## 3. 主机：应用偏好

### 3.1 会话状态

会话开始时记录一份不随编码器重建变化的预算：

- `base_video_budget = video_budget(初始 encoder->bitrate(), bitrate_reserve(audio))`
- `quality_percent`（100/75/50，默认 100）
- `viewer_fps_cap`（0 表示不设上限，默认 0）
- 当前生效的编码器偏好（默认 Auto）与 `encoder_config.codec` 同步

`BitrateController` 增加两个 setter，避免重建控制器丢失当前的 ABR 位置：

- `set_ceiling(bps)`：更新天花板，目标回到新天花板，按当前链路阶梯重算帧率。
- `set_top_framerate(fps)`：只改帧率阶梯顶部，按当前目标/天花板比例重算帧率。

画质上限 = `base_video_budget * percent / 100`，且不低于 `video_floor()` 的
约束；帧率顶部 = `cap == 0 ? 主机配置 : min(主机配置, cap)`。

### 3.2 请求处理

每个 `SetStreamOptions` 都恰好回答一次 `StreamOptionsResult`：

- 与当前状态完全一致：`Ok` 空操作，不碰编码器、不重发 StreamInfo。
- 画质或帧率变化：更新 ABR 与采集节奏，`encoder->set_rate(新目标, 新帧率,
  &keyframe)`，只有当编码器报告序列无法延续时才强制 IDR，更新
  `stream_info.bitrate/framerate` 后 `refresh_stream`，回答 `Ok`。
- 编码器变化：解析目标编码器（Auto → `settings_.codec`）。若当前编码器已
  是目标，按空操作处理；否则：
  1. 用 `encoder_config` 建替换编码器（尺寸沿用当前采集，码率与帧率直接取
     当前 ABR 目标，参数已一致时不再多一次 `set_rate`）；
  2. 校验 `encoder->codec()` 与请求一致（Auto 不校验）；
  3. 用当前 ABR 目标与生效帧率 `set_rate`；
  4. 全部成功后替换、强制 IDR + 一次额外 IDR、重发 StreamInfo、回答 `Ok`；
  5. 任一步失败就销毁替换实例，回答 `Unsupported` 或 `Failed`，旧流不动。
- 一秒内再次要求切换编码器：`Busy`（重建比 `set_rate` 贵得多）。
- 不要求输入权限：这只改变查看器自己的画面，不移动主机桌面。

编码器层（精细 reset 策略，参考 zerocast 的做法）：

- 目标码率与帧率的“有效值”都没变：空操作，不 reset、不产生 IDR。
- H.264，且帧率不变、已经编码过真实帧：先带
  `mfxExtEncoderResetOption{StartNewSequence=OFF}` 调 `MFXVideoENCODE_Query`
  确认运行库能在当前状态下继续序列，再用同一描述 `Reset`；成功且标志仍为
  OFF 时保留参考帧，`keyframe_required = false`。Query 拒绝、标志被改写或
  Reset 失败都回退普通 `Reset`（重启序列，要求 IDR）。
- 帧率变化不在“可继续序列”的参数集内，未出过真实帧时唯一参考还是查看器
  从未收到的探针图，两者都走普通 `Reset`；新帧率会被编码器写进序列头，
  所以需要 IDR。
- H.264 初始化时关闭 `NalHrdConformance`、`VuiNalHrdParameters` 与
  `PicTimingSEI`：HRD/VUI 会把目标码率写进 SPS，关掉后纯码率变化不再改变
  序列头，连续 reset 对解码器才是真的透明。
- mfx-gen 的 HEVC VDEnc 对 `MFXVideoENCODE_Reset` 一律回答
  `MFX_ERR_INCOMPATIBLE_VIDEO_PARAM`，连重复当前参数、未出帧或换 GOP 也
  一样。`MfxEncoder` 在这种错误下关闭并重新 `Init` 同一条 VPL 会话（D3D11
  句柄与 legacy 分配器保留），新码率打不开就恢复旧配置；重开后首帧是新的
  IDR，`keyframe_required = true`。HEVC 的纯码率变化因此仍有一次重开和
  IDR，只在拒绝 Reset 的运行库上发生。
- 主机只有在 `keyframe_required` 为真时把 `force_keyframe` 置位（用逻辑或，
  不吞掉此前挂起的请求）；编码器替换路径仍无条件 IDR + 额外 IDR。

统计新增 `stream_option_requests`、`stream_option_changes`、
`stream_option_failures`；日志记录生效的编码器、fps 上限与画质档。

### 3.3 重建路径保持一致

会话内的偏好必须活过所有已有的编码器重建路径：

- 采集重建（锁屏/桌面切换）：新控制器按画质档与帧率上限构造，再
  `set_rate` 到当前目标；`encoder_config.codec` 已是请求的编码器。
- 显示器切换 / 分辨率模式切换：新建的编码器继续使用
  `encoder_config.codec`，并按 `stats.target_bitrate` 与生效帧率 `set_rate`。
- 自适应分辨率：重建尺寸时沿用 `encoder_config.codec` 与当前目标。

若重建时硬件不再支持请求的编码器而回退，主机记录回退日志，StreamInfo
里的 `codec` 是实际值；查看器以 StreamInfo 为准更新显示。

## 4. 查看器：引擎、bridge 与菜单

- `ViewerEngine::SetStreamOptions`：会话运行中可调用，保存最新偏好并排队；
  发送前会等到流已建立。重连后页面重新下发，和剪贴板开关的处理一致。
- 状态新增 `stream_option_code`、`stream_option_error`、
  `stream_options_results`（计数）与 `stream_quality`（生效档位）；实际
  编码器与帧率继续读 `codec` / `framerate`，不重复字段。
- Bridge 新增 `setStreamOptions(codec, maxFps, quality)`；状态映射补上新字段。
- Flutter 工具栏新增“画面”菜单，三组互斥选项：
  - 画质：高清 / 均衡 / 流畅
  - 帧率上限：自动 / 15 / 30 / 60
  - 编码器：自动 / H.264 / HEVC（标明 HEVC 需要主机硬件支持）
- 菜单变更立即发送并进入 pending；结果计数增加后：
  - `Ok`：保持选择，清理 pending；
  - 拒绝：恢复到上一组选择，并用 SnackBar 显示主机原因；
  - `Busy`：提示稍后重试，选择回滚。
- 结果到达前再次改选：以最后一次为准，pending 只保留一份；主机对每个
  请求都回答，计数配对不会错位。

## 5. 验证

- `chast-protocol-test`：两种消息的往返、0 fps、三个枚举边界、未知枚举、
  越界 fps、超长/非法 UTF-8 reason、尾随字节。
- `chast-bitrate-test`：`set_ceiling` 重定目标、`set_top_framerate` 重算阶梯、
  下限/上限倒置保护。
- `chast-quic verify --stream-options`：沿用主回环（标志不能用 `--quality`，
  它已经是 serve/connect/verify 的 VPL 编码质量）。先显式请求当前编码器
  （`Ok`、生效值不变、无 StreamInfo），再发 Balanced + 15 fps，断言 `Ok`、
  生效帧率 `min(主机帧率, 15)`、随后 StreamInfo 的 `framerate` 相同、主机
  计数 +1；再恢复 High + 自动帧率，断言帧率回到主机值并再次公告；随后在
  帧率不变的前提下只改画质到 Balanced，等恢复步的 IDR 落地后采样关键帧
  计数，断言 H.264 基线不新增关键帧、StreamInfo 的码率确实下降且帧率/
  编码器不变，再恢复 High；最后请求另一种编码器族，断言结果只能是与实际
  硬件一致的 `Ok`（跟随 StreamInfo，冷却后恢复原编码器）或 `Unsupported`
  （生效字段仍是原编码器、reason 非空）。HEVC 基线不要求零关键帧（本机
  重开会话必然有一次 IDR），打印计数供人工核对。
  ctest 用独立的 `quic_stream_options` 跑该探针；不含探针的主回环继续做
  离线回放断言，因为探针按设计让同一条流里先后出现两种编码器，单一编码器
  的回放无法解析。
- `chast-encode --bitrate-switch MS:KBPS`：H.264 输出 “sequence continued”
  且全程 `keyframes=1`（只有首帧）；HEVC 输出 “IDR required” 且
  `keyframes=2`（重开后的首帧）。
- 主回环（`chast-quic verify --file-upload --file-download --privacy`）：
  查看端等待视频帧的上限降到 250 ms，及时取走控制流上的 StreamInfo 与
  切换结果（会话对控制消息只保留最新一条，长等待会让相邻公告互相覆盖）；
  第二次切换请求从第一次实际发出后再隔 1.2 s，帧停顿时两条请求不会挤在
  同一轮被合并。
- Flutter：模型与菜单选择、拒收回滚、结果计数配对、重连后重新下发。
- 构建：Release 原生构建、`ctest`、`flutter analyze`、`flutter test`、
  Windows Release 构建。

单机验收限制：无法制造“HEVC 不支持”的真实硬件组合、不同网络质量下的
画质体感、双机 HEVC 解码兼容性；这些保留人工/双机验收。

编码器运行时结论：纯码率变化在 H.264 上通过
`mfxExtEncoderResetOption{StartNewSequence=OFF}` 的 Query + Reset 继续序列，
参考帧保留、解码器无需 IDR；关闭 HRD/VUI 计时后 SPS 不再随目标码率变化。
帧率变化、首个真实帧之前以及编码器替换仍要求 IDR。mfx-gen 的 HEVC VDEnc
拒绝一切 `MFXVideoENCODE_Reset`（连重复当前参数、未出帧、不同 GOP 都回答
`MFX_ERR_INCOMPATIBLE_VIDEO_PARAM`），`MfxEncoder::set_rate` 在 -14 时改为
关闭并重新 `Init` 同一条 VPL 会话，失败则恢复旧码率，因此 HEVC 的每次改
码率仍有一次重开（首帧 IDR）。编码器切换的替换实例直接用 ABR 目标码率/
帧率创建，避免多余的一次重建。主机只按 `set_rate` 返回的
`keyframe_required` 强制 IDR，不再对每次画质/ABR 调整无条件插入关键帧。

仍待人工/双机验收：无 HEVC 硬件时显式 HEVC 的 `Unsupported` 文案、双机
HEVC 解码兼容性、不同网络质量下的画质/帧率体感，以及真实硬件上的 ABR
重开节奏。
