### 1.1 管理台角色与账号登录（2026-10-28）

- 账号角色扩展为四级：`admin`（账号管理 + 全部控制台）、`operator`
  （设备写操作与只读控制台）、`readonly`（只读控制台）、`user`（仅查看器，
  无控制台）。首个账号与旧库最早账号仍自动成为 admin；最后一个 admin
  不能降级、封禁或被删除。
- API 鉴权按三级重写：`/v1/identities`、`/v1/stats`、三类审计列表与 CSV
  导出要求 `readonly` 及以上；`PATCH /v1/identities/{id}`、身份重置、
  `DELETE /v1/hosts/{id}`（移除租约）要求 `operator` 及以上并分别写入
  `device_labels`/`device_reset`/`device_lease_remove` 审计（含操作者
  用户名）；`/v1/accounts*` 只允许 admin 或服务器密钥；`user` 角色一律 403。
  服务器密钥仍是隐式超管，主机注册/查询/指标等 host-only 接口不受影响。
- 内嵌 Web 管理台支持账号登录：登录方式可选“服务器密钥”或“账号”，账号走
  `/v1/account/login`（两步验证码 6 位数字按 TOTP、其他按恢复码提交），
  访问令牌过期自动调 `/v1/account/refresh` 并重试，退出调
  `/v1/account/logout`；`user` 账号登录后立即登出并提示无权限。只读角色
  隐藏设备编辑/重置/移除按钮并显示说明，账号页签仅 admin 可见。
- 创建账号可在一次插入中指定角色；首个账号即使请求其他角色也保持 admin，
  不再出现“账号已创建但接口返回 409”的半成功状态。
- 验证：`TestConsoleRoleMatrix`（4 角色 × 读/写/管理端点）、
  `TestOperatorAndReadonlyRoles`、`TestCreateUserWithRole` 通过；真实
  `chast-server` 回环 + 浏览器用 alice(admin)/bob(operator)/carol(readonly)/
  dave(user) 验证登录、页签与按钮差异、readonly CSV 导出、401→refresh
  保活、user 被拒并吊销会话；全量 `go test ./...` 通过。

### 2. 账号安全

- **登录失败锁定**（`internal/authlimit`）：按“用户名小写 + 客户端 IP”计数，
  默认 10 分钟窗口内失败 5 次即锁定 1 分钟；成功登录清零。
  - 配置 `--state` 后锁定记录写入 SQLite `login_locks`，跨重启与多实例共享；
    计数通过 `BEGIN IMMEDIATE` 原子累计，避免并发登录丢计数。
  - 管理台 `user unlock <name>` 可手动清除该用户的锁定键；解锁动作写入审计。
  - 通过 `--login-max-failures` / `--login-window` / `--login-lockout` 调整，
    设为 0 可关闭。
- **设备会话**：登录令牌对应可枚举的会话记录；查看器可列出设备、改名、
  撤销单个会话、一键退出其他设备；改密/撤销立即影响后续鉴权。
- **自助改密**：`POST /v1/account/password` 校验旧密码并轮换哈希；查看器提供
  修改密码对话框。
- **邮箱与密码找回**（2026-10-28）：`users.email` 唯一且大小写不敏感，自助
  设置/清空要求当前密码，管理 API 与管理台可代设；`password_resets` 只存
  令牌 SHA-256、单账号仅一个未用令牌，默认 30 分钟过期（`--recovery-ttl`）。
  `POST /v1/account/recover` 对未知账号、无邮箱与发信失败统一返回 202，按
  客户端 IP+用户名每分钟限流；`POST /v1/account/recover/complete` 原子消费
  令牌并吊销该账号全部访问与刷新令牌。新增 `internal/mail`（STARTTLS 默认、
  隐式 TLS、无 TLS 与可选 PLAIN 认证）与 `--smtp-addr`/`--smtp-from`/
  `--smtp-user`/`--smtp-pass`/`--smtp-tls`/`--recovery-url`；未配置 SMTP 时
  管理台 `user recover` 打印一次令牌供线下交付。写入 `account_email` 与
  `account_recover` 审计。
- **TOTP 两步验证**：RFC 6238（SHA1、6 位、30 秒、±1 步），启用时返回
  `otpauth://` URI；登录时必须提供验证码，已用步进持久化以防重放；
  一次性恢复码仅哈希保存，可在用尽前重新生成。
  - 管理台 `user 2fa <name> off` 可重置丢失的 2FA。
- **WebAuthn 安全密钥**（2026-10-28，P2-19/P2-30）：Windows Hello / FIDO2
  平台认证器可作登录第二因素（密码 + 断言）或免密码登录（用户名 + 断言）。
  服务端只存 COSE 公钥，挑战按 `(user_id, purpose)` 单活并在登录成功时与
  令牌同一事务消费；两种登录 purpose 互不替换、互不重放。免密码 begin 对
  未知账号与无凭据统一 202 且不计限流失败，封禁只对有效断言返回 403。
  支持 ES256/RS256/EdDSA，attestation 接受 `none`/`packed` 但不校验证书链。
  `--webauthn-rp-id` 与 `--webauthn-origin` 成对启用，查看器账号对话框可
  注册/命名/删除，登录页提供“使用安全密钥”与“使用安全密钥登录”。
  `user reset-2fa` 与删号清空凭据与挑战，封禁保留凭据但登录 403，改密不
  删除凭据。不做无用户名的可发现凭据（passkey）与跨设备同步。
- **令牌生命周期**（2026-10-26）：登录返回 30 min 访问令牌与 720 h 刷新令牌；
  `POST /v1/account/refresh` 轮换两枚令牌，重放被轮换的刷新令牌即撤销整个
  会话；登出/撤权/改密/重置同步删除刷新令牌，旧库长令牌（`access_expires_at=0`）
  保持可用。审计新增 `session_refresh`（rotated/replay/invalid）；查看器在访问
  令牌到期前自动续期，旧 `account.json` 仍可加载。
- **登录审计**：记录登录成功/失败、锁定、解锁、2FA 变更、改密、会话撤销等；
  管理台 `audit [count]` 查看，表按 10000 条保留。HTTP 列表（审计、连接、
  文件传输）支持 `before_id`/`next_before_id` 游标分页；`--audit-retention-days`
  与管理台 `audit prune <days>` 可按时间清理三类历史。
- **账号角色**（2026-10-27）：`users.role` 分 `admin`/`user`，首个账号与旧库
  最早账号为 admin；管理台 `user role` 设置，`/v1/accounts*` 提供管理 API。
  最后一个 admin 不能降级，库中还有别的账号时也不能删除；角色与管理操作写入
  账号安全审计。
- **持久封禁**（2026-10-27）：`users.banned` 持久标记；`POST|DELETE
  /v1/accounts/{username}/ban` 与管理台 `user ban|unban` 管理，`user list`
  显示 `banned=true`。封禁在同一事务中吊销该账号全部访问/刷新令牌，密码正确
  登录返回 403，错误密码仍是普通失败；最后一个可用 admin 不能封禁（已封禁
  admin 不参与降级/删除的可用性判定）。写入 `account_ban`/`account_unban`
  审计。
- **日志轮转与归档**（2026-10-27）：新增 `internal/logging`，slog 文本日志在
  stderr 之外可追加到 `--log-file`；写满 `--log-max-size`（默认 100 MiB）后
  重命名为 `<name>.<20060102-150405.000000000>`，`--log-compress`（默认开）
  gzip 归档；`--log-max-backups`（默认 5，0 保留全部）与 `--log-max-age`
  （默认 0）在轮转与重启打开时按目录内容清理。`chast-relay` 同名旗标。
- **请求链路 tracing**（2026-10-27）：新增零依赖 `internal/tracing`，按
  OTLP/HTTP JSON 批量导出 HTTP span（路由、方法、协议、状态码，≥500 标记
  错误）；`chast-server` 覆盖 API（含 429 拒绝），`chast-relay` 覆盖节点
  控制面。`--trace-endpoint` 默认空关闭，`--trace-sample` 控制本地采样，
  `--trace-service` 设置资源 `service.name`；接受 W3C `traceparent` 并在
  响应回写，collector 故障或队列满只丢弃 span，不阻塞请求。
- **mTLS 与私有 CA**（2026-10-27）：`chast-server`/`chast-relay` 的
  `--tls-client-ca` 要求并校验客户端证书；主机/查看者代理与
  `chast-tunnel` 用 `--tls-ca`/`--tls-client-cert`/`--tls-client-key`
  信任私有 CA 并出示证书，服务端节点池用 `--relay-node-ca`/
  `--relay-node-client-cert`/`--relay-node-client-key`。全部为空时沿用
  系统根与原有行为；ACME 自动申请已于 2026-10-28 补齐（P2-20，HTTP-01，
  见下）。
- **TLS 证书热加载**（2026-10-27）：`chast-server` 与 `chast-relay` 改用
  `netutil.LoadReloadingTLSConfig`，在距上次检查至少 5 秒后的下一次握手时
  重读 `--tls-cert`/`--tls-key`，PEM 摘要变化才原子换证书并记
  `TLS certificate reloaded`；文件损坏/不完整时保留旧证书并按错误去重记录
  `TLS certificate reload skipped`，certbot 式续期无需重启。`--tls-client-ca`
  原先只在启动时读取；2026-10-28 已由 P2-26 补齐热加载。
- **内嵌 Web 管理台**（2026-10-27）：`GET /admin/` 提供与服务端同端口的静态
  管理页面（`internal/webadmin` 用 `//go:embed` 打包，只放行 `index.html`/
  `app.js`/`style.css`，附 CSP/nosniff/no-store/no-referrer/DENY），`/admin`
  301；登录只需 server-key（存于 `sessionStorage`，401 自动锁屏），覆盖总览、
  设备（新增 `GET /v1/identities` 全量含离线、搜索/在线过滤、别名标签与身份

### 3. 地址簿

- 服务端地址簿：peer ID、显示名、标签、分组 ID、逐条 `revision`、墓碑；
  支持增量快照（`since`）与分组变更列表，删除保留墓碑供多端合并。
- 分组：创建/改名/删除；删除分组在事务内解绑成员并写分组墓碑；条目只能
  指向存在的分组，失效分组在读取时归一为空。
- 分组嵌套与排序（2026-10-28，账号库迁移 v3）：分组可设置 `parent_id`
  （根为空串，上级须为同一账号的存活分组，成环/深度超 8 拒绝）与
  `position`（非负，按 `position,name,group_id` 排序）；条目也有
  `position`（按 `position,peer_id` 排序）。删除分组时子分组上移到被删组
  的上级、组内条目解绑，各自推进修订，并撤销该分组范围的共享授权；分组
  授权覆盖整棵子树。查看器首页按分组树缩进显示，分组对话框可改上级并用
  上下按钮重排同级，设备菜单支持组内上移/下移。
- 查看器同步：登录后全量/增量合并，保留本地连接参数；标签与分组编辑可离线
  记录意图，恢复在线后上传并撤销意图；删除通过本地 outbox 重试
  （成功/404 清理，401 保留）。
- **条目级乐观并发控制（OCC）**：
  - `PATCH /v1/addressbook/peers/{id}` 接受可选正整数 `if_revision`；
    事务内重新读取修订号与墓碑，令牌不匹配、条目已删除或从未以该令牌存在
    时返回 409 且不写入；`0`/负数返回 400；省略令牌保持最后写入者优先。
  - 查看器 `Device` 持久化 `revision`；同步与即时编辑携带令牌，成功后立即
    写回新修订号。409 时不重试旧值，改为全量拉取并用服务器条目覆盖本地
    （服务器已删除则移除本地行），界面提示“已刷新为服务器版本”，同步摘要
    显示冲突数。
  - 共享地址簿的 `PATCH` / `DELETE .../shared/{owner}/peers/{id}` 同样接受
    `if_revision`（删除用查询参数），与属主写入共用条目修订号；共享编辑
    409 后重新读取共享地址簿并采用服务器行。共享新增仍为最后写入者优先。
- **墓碑保留**（2026-10-27）：`--addressbook-tombstone-days`（默认 0 保留全部）
  在启动与每 6 小时删除早于该天数的条目/分组墓碑，管理台 `ab prune <days>`
  可手工执行；存活条目不受影响。离线超过窗口的客户端错过墓碑后需整本快照
  才能收敛，窗口应长于最长预期离线时间。

### 6.4 剪贴板文件反向（协议 v34，2026-10-30）

- 协议：`FileOffer` 负载在大小之后新增 flags 字节（bit0 `resume`、
  bit1 `clipboard`），协议升到 v34；普通上传 flags=0，既有字段语义不变。
- 查看器：在剪贴板权限内每 500 ms 读一次本机 CF_HDROP，会话与权限建立时
  只记录基线不发送。列表身份（有序名字、相对路径、大小哈希）变化时先经
  CCLB 广播 FileList，再按列表顺序逐个发带 `clipboard` 位的普通文件
  offer，文件字节仍走上传通道。与普通上传共用一条上传队列和活动传输槽：
  列表变化、剪贴板权限撤销或主机替换了剪贴板项时，仍在排队的 clipboard
  上传被丢弃、活动传输被取消。本地复制优先：正在下载的主机列表若被本机
  复制打断，暂存目录删除并向主机回 `IoError` 结果，本机新列表随后公告；
  主机列表写进 CF_HDROP 时把身份哈希记为自身基线，因此不会被当成新变化
  回送。文件占用剪贴板期间富剪贴板轮询暂停，文本与文件不互相覆盖。
- 主机：带 `clipboard` 位的 offer 只受剪贴板权限（`allow_clipboard` +
  会话权限位）约束，不需要文件传输权限或接收目录。主机在临时目录建
  `chast-clipboard-<时间>-<序号>-in` 暂存根：扁平文件各占一个隐藏目录
  `.item-<序号>`，复制树按 `rel_path` 第一个分量归到 `.root-<首条目序号>`
  下并重建顶层文件夹与子目录，同名文件/文件夹不会互相覆盖。逐个校验 offer
  的名字与大小是否和公告条目一致，不一致整份列表拒绝（`Refused`）；上传槽
  被普通上传占用时回 `Busy`。全部到齐后把 CF_HDROP 顶层项（每个扁平文件、
  每棵复制树的顶层文件夹）交给 `clipboard_write_files`（默认真实写剪贴板，
  探针替换为捕获）；暂存目录保留给剪贴板引用，下一次列表、会话结束或失败
  时删除。
- 注入点：`ViewerEngine::SetClipboardFileSource` 提供本机文件列表，
  `HostServerConfig::clipboard_write_files` 捕获主机侧写入；探针的所有
  场景都注入空来源，自动化运行不读取也不写入操作者剪贴板。
- 验证：`chast-viewer-probe --clipboard-files-up`（ctest
  `viewer_clipboard_files_up`）真实 QUIC 回环：查看器在会话基线之后把
  `up-one.txt`、`向上 二.bin`（256 KiB 二进制）与 `up-folder/`
  （`inner.txt`、`sub/deep.bin`）公告给主机；主机捕获到 3 个顶层项，全部
  位于同一个 `%TEMP%\chast-clipboard-*-in`，两个扁平文件与文件夹的两层
  文件逐字节一致，目录顶层恰 3 项；等待 1500 ms 后查看器没有回传同一
  列表（`clipboard_received=0`、`clipboard_failed=0`）；会话结束、主机
  释放后暂存目录已删除，退出码 0。正向 `--clipboard-files` 同批复跑通过。
  C++ Release 全量构建与 ctest 36/36 通过（新增
  `viewer_clipboard_files_up`，559.90 s）。
- 边界：仅在 Windows 上读写 CF_HDROP；真实剪贴板写入由现有 Win32 后端
  承担，探针用捕获代替（未在 GUI 中人工粘贴验证）；列表大小/条目/深度
  上限与 v33 相同；同一会话同一时刻只有一份剪贴板文件列表。

### 6.5 剪贴板文本上限提升到 4 MiB（2026-10-30）

- 协议：`ClipboardFormat::Text` 的格式上限改为独立的
  `kMaxClipboardTextBytes = 4 MiB`，与 Html/Rtf 相同；CCLB 流的总量上限
  40 MiB 与 format 数 5 不变。Text 走 CCLB 流，不再继承旧
  `ClipboardUpdate` 控制消息的 256 KiB（`kMaxClipboardBytes`），该控制
  消息本身及旧客户端路径保持原样。
- 校验：`valid_clipboard_content` 的 Text 分支只检查非空、无 NUL 与合法
  UTF-8，长度由 `format_limit` 统一约束；Win32 `read_text` 在 UTF-16
  单元数超过上限时直接放弃转换（每单元最多 3 字节 UTF-8），其余交给
  `accepts()` 复验，避免读侧用旧控制消息上限提前拒绝。
- 验证：协议测试新增 4 MiB 恰等可通过、往返一致、4 MiB+1 被拒三项；
  `chast-quic verify` 的模拟主机把更新文本改为 300 KiB（含非 ASCII），
  回环断言查看器收到的文本超过旧 256 KiB 上限。C++ Release 构建通过；
  单独复跑 `protocol` 与 `quic_loopback` 通过（后者 129 项断言）。
  全量 ctest 复跑情况见文首快照。

## 约束与注意事项

- 不要改动用户真实的 `%APPDATA%\chast\host.ini`；主机回环测试使用
  `build/*.ini` 隔离配置。
- 音频编码使用 vcpkg 安装的独立 Opus，不使用 FFmpeg 自带 Opus。
- 避免全仓 `gofmt` / `dart format` 造成无关改动；只格式化本次触及的文件。
- 不提交 `server/chast-server-identity.key`、`build/` 产物、dump 或测试私密配置。
- 协议字段只增不改；每次语义变化提升协议版本，保持 ALPN 家族名不变。
