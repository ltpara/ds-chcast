## 当前完成状态（基线 + 本轮）

### 1. 账号体系与服务端 API

- SQLite 账号存储（单连接、WAL、`ensureColumn` 迁移）：用户、密码哈希、登录
  令牌与会话、地址簿、分组、共享授权、审计、登录锁定共用同一数据库。
- 账号 HTTP API：
  - `POST /v1/account/login`、`POST /v1/account/refresh`、
    `POST /v1/account/logout`、`GET /v1/account`
  - `POST /v1/account/password`
  - `POST /v1/account/2fa/start|enable|disable|recovery`
  - `GET /v1/account/sessions`、`PATCH|DELETE /v1/account/sessions/{id}`、
    `POST /v1/account/sessions/revoke-others`
  - `POST /v1/account/connections`、`GET /v1/account/connections`
  - `POST /v1/account/file-transfers`、`GET /v1/account/file-transfers`
- 查看器侧：`account_store.dart` 持久化服务端地址与账号令牌，
  `server_api.dart` 覆盖全部账号、地址簿、共享、审计与分页查询，
  首页与账号对话框完成登录/退出/会话管理接线。

### 2. 账号安全

- **登录失败锁定**（`internal/authlimit`）：按“用户名小写 + 客户端 IP”计数，
  默认 10 分钟窗口内失败 5 次即锁定 1 分钟；成功登录清零。
  - 配置 `--state` 后锁定记录写入 SQLite `login_locks`，跨重启与多实例共享；
    计数通过 `BEGIN IMMEDIATE` 原子累计，避免并发登录丢计数。
  - 管理台 `user unlock <name>` 可手动清除该用户的锁定键；解锁动作写入审计。
  - 通过 `--login-max-failures` / `--login-window` / `--login-lockout` 调整，
    设为 0 可关闭。
- **设备会话**：登录令牌对应可枚举的会话记录；查看器可列出设备、改名、
  撤销单个会话、一键退出其他设备；改密/撤销立即影响后续鉴权。
- **自助改密**：`POST /v1/account/password` 校验旧密码并轮换哈希；查看器提供
  修改密码对话框。
- **TOTP 两步验证**：RFC 6238（SHA1、6 位、30 秒、±1 步），启用时返回
  `otpauth://` URI；登录时必须提供验证码，已用步进持久化以防重放；
  一次性恢复码仅哈希保存，可在用尽前重新生成。
  - 管理台 `user 2fa <name> off` 可重置丢失的 2FA。
- **令牌生命周期**（2026-10-26）：登录返回 30 min 访问令牌与 720 h 刷新令牌；
  `POST /v1/account/refresh` 轮换两枚令牌，重放被轮换的刷新令牌即撤销整个
  会话；登出/撤权/改密/重置同步删除刷新令牌，旧库长令牌（`access_expires_at=0`）
  保持可用。审计新增 `session_refresh`（rotated/replay/invalid）；查看器在访问
  令牌到期前自动续期，旧 `account.json` 仍可加载。
- **登录审计**：记录登录成功/失败、锁定、解锁、2FA 变更、改密、会话撤销等；
  管理台 `audit [count]` 查看，表按 10000 条保留。

### 3. 地址簿

- 服务端地址簿：peer ID、显示名、标签、分组 ID、逐条 `revision`、墓碑；
  支持增量快照（`since`）与分组变更列表，删除保留墓碑供多端合并。
- 分组：创建/改名/删除；删除分组在事务内解绑成员并写分组墓碑；条目只能
  指向存在的分组，失效分组在读取时归一为空。
- 查看器同步：登录后全量/增量合并，保留本地连接参数；标签与分组编辑可离线
  记录意图，恢复在线后上传并撤销意图；删除通过本地 outbox 重试
  （成功/404 清理，401 保留）。
- **条目级乐观并发控制（OCC）**：
  - `PATCH /v1/addressbook/peers/{id}` 接受可选正整数 `if_revision`；
    事务内重新读取修订号与墓碑，令牌不匹配、条目已删除或从未以该令牌存在
    时返回 409 且不写入；`0`/负数返回 400；省略令牌保持最后写入者优先。
  - 查看器 `Device` 持久化 `revision`；同步与即时编辑携带令牌，成功后立即
    写回新修订号。409 时不重试旧值，改为全量拉取并用服务器条目覆盖本地
    （服务器已删除则移除本地行），界面提示“已刷新为服务器版本”，同步摘要
    显示冲突数。
  - 共享地址簿的 `PATCH` / `DELETE .../shared/{owner}/peers/{id}` 同样接受
    `if_revision`（删除用查询参数），与属主写入共用条目修订号；共享编辑
    409 后重新读取共享地址簿并采用服务器行。共享新增仍为最后写入者优先。

### 4. 共享地址簿

- 授权级别：只读、读写、完全控制；属主可授权/升级/撤销，完全控制者可查看
  授权、代属主授权与撤销第三方。
- 读写/完全控制者可修改、删除属主条目，并可新增条目；新增落入属主地址簿，
  不复制到被授权者自己的地址簿。
- 查看器共享对话框展示属主、权限与条目，支持连接、按权限编辑/新增/删除、
  完全控制下的授权管理，并处理 401/403/404/409。

### 5. 会话聊天（协议 v24）

- 新增控制报文 `ChatMessage = 32`：单条非空 UTF-8 文本，最大 4096 字节，
  拒绝 NUL 与非法 UTF-8；空行不发送。
- 主机托盘聊天窗口与查看器 Flutter 聊天面板双向收发，按控制流顺序显示。

### 6. 连接与文件传输审计

- 查看器上报连接事件（目标、方向、结果、时间）与文件传输汇总事件；
  服务端存储、按账号查询，管理台 `connections` / `transfers` 查看。
- 每类审计表按 10000 条保留；账号登录审计与连接/传输审计共用管理台入口。

### 7. Wake-on-LAN（查看器）

- 查看器可为本地设备条目填写 MAC 并发送局域网魔术包（UDP 广播）；
  MAC 只保存在本地 `Device`，不随账号同步，也不向服务端上传。
- 当前仅覆盖同网段直发，未实现跨子网/中继唤醒。

### 8. M10.8（已包含在基线提交）

- `--rmem` UDP 接收缓冲、默认名单文件、`--test-punch` 启动自检、
  RustDesk 配置键名别名、启动自检与日志；`chast-server` / `chast-relay`
  共用 hbbs 风格配置来源。

## 已知限制 / 与 RustDesk 的剩余缺口

### 地址簿

- 条目级与分组级 OCC 已覆盖自有地址簿、共享编辑/删除与分组改名/删除；
  共享新增仍是最后写入者优先（新条目没有可比较的基线修订号）。
- 已支持按分组共享与分组级 ACL（2026-10-26）：授权可选 `group_id`，读取按
  范围过滤，读写只作用于该分组；整本授权仍覆盖全部条目。共享条目不复制到
  被授权者自己的地址簿。
- 地址簿不保存任何凭据：共享条目没有密码，也没有设备 hash。RustDesk 的
  服务端地址簿（`flutter/lib/models/ab_model.dart` 的 `_serialize`）同步
  `toCustomJson(includingHash: true)`，只含 peer 的 `hash`，密码不在其中；
  `Peer.toJson` 的密码只进本机地址簿缓存。chast 的受信设备保存在主机侧
  `TrustStore`，地址簿只负责分组与共享；被授权者连接目标仍需目标主机
  自己的密码与审批。
- RustDesk 没有地址簿导入/导出（`flutter/lib/common/widgets/address_book.dart`
  的菜单只有添加/分组/标签等），chast 也不提供；如日后要加，属于本地备份
  便利功能，不是对齐项。
- 分组不支持嵌套、拖拽排序；分组名只在查看器内存缓存，重启后首次同步需全量
  读取；墓碑尚未按时间或同步水位清理。
- 地址簿只保存 peer ID、名称、标签与分组 ID，不保存连接参数；搜索/筛选只
  作用于“我的设备”，不支持拼音/模糊匹配，筛选状态不跨重启。
- Wake-on-LAN 的 MAC 仅本地保存，不同步；仅同网段直发。这是 RustDesk 的
  同等行为（`src/lan.rs` 的 `send_wol` 也只对局域网发现得到的 IPv4 发
  `wol::send_wol`）。

### 账号与安全

- 访问令牌与刷新令牌都以明文保存在 `account.json`，刷新令牌每次续期轮换，但
  文件本身未加密；刷新响应丢失（如断网）会导致会话失效，需要重新登录。
- 有登录失败锁定与解锁，登录审计记录客户端 IP；配置 `--geoip-file` 时另写入
  离线表给出的登录地点（管理台审计与查看器设备会话展示），未配置时只记录
  IP。没有持久封禁（只有限时锁定与管理台解锁）。
- 支持 TOTP 与恢复码，但没有短信/邮件备用验证；没有忘记密码/邮件找回，
  忘记密码仍需管理台重置。
- 账号标签只是逐设备标签，没有按组授权。

### 审计与运维

- 连接与文件传输审计已覆盖查看器上报与主机侧入站（主机写 spool、代理签名
  上报，按 `audit_ref` 合并）；但仍没有地理位置、服务端抓包核对或批量导出，
  查看器文件传输按轮询窗口聚合（主机侧逐文件）。
- 审计保留按条数（10000），没有时间保留策略或外部归档。
- 主机自报元数据未签名；软件更新只写代理日志并在查看器显示一次性横幅，
  不自动下载或安装。

### RustDesk 功能面

- 未实现虚拟显示器、安装器与多语言（i18n）；查看器终端面板已实现，
  但真实会话里的点击复核与双机验收待做。
- 音频已实现 AEC/降噪/设备选择，并按 RustDesk 把查看者系统声音改为
  到达即播（到达锚定、0 lead，见 `docs/m6.3-lipsync-plan.md`）；A/V skew
  实测与长期漂移校正仍待补。采集、麦克风与播放端点丢失或默认设备变化
  时会在 1 s 内跟随新默认（固定端点重试同 id），播放器也按 RustDesk 的
  5 s 启动确认对齐（已交出音频 5 s 内不被端点消费即重建，空闲端点不
  触发）；真实热插拔验收未做。
  更多采集/编码后端仍待补。
- 租约、中继分配与打洞地址只在内存中（重连后重建，与 hbbs 行为一致）；
  跨子网/中继协助的 Wake-on-LAN 未实现。
- UPnP 端口映射为可选（`--upnp`），只处理 IPv4 与 WANIPConnection/
  WANPPPConnection；本机没有 IGD，真实路由器上的映射、续租与对称 NAT 直连
  仍需部署复核。
- 录制：查看器侧录制已按 RustDesk 放在查看器（`src/client.rs record_screen`），
  但实现不同——RustDesk 把解码后的帧重新编码，我方直接把主机已编码的
  Annex B 访问单元无损封装成 MP4（`tools/mp4_recorder.h`），不占编码器、
  不多拷贝一次像素；首帧关键帧的 SPS/PPS 生成 avcC，样本改写为长度前缀，
  按 `pts_ms` 落在 1/1000 时基上。画面尺寸中途变化（弱网分辨率阶梯下调或切屏）
  会像 RustDesk 重开录制那样**分段续录**：当前段收尾，携带新参数集的关键帧开启
  下一段（`out.mp4`、`out-2.mp4`…），尺寸变化前的非关键帧丢弃并计数。CLI 通道
  `chast-quic connect --record out.mp4` 与回环探针 `verify --record out.mp4` 均已
  验收：`connect` 真实会话 sender `encoded=541` = receiver `received=541` = 录制
  `samples=541 keyframes=1 skipped=0`，FFmpeg 重新打开读回 541 个样本；
  `verify --record` 断言“每个收到的访问单元都被封装或计为关键帧前丢弃”
  “录制保留查看器看到的每个关键帧”“重开文件读回全部封装样本”，并在默认 75%
  分辨率探针下断言“分辨率变化滚动到第二段”；新增 ctest `quic_recording`
  （全套 26/26 通过），跨段计数求和后 `segments=2 samples=121 keyframes=3
  skipped=0 verified-samples=121 ok=1`。目前仅 H.264。查看器 GUI 录制开关
  （工具栏按钮 + 桥接 `setRecording` + `ViewerStatus::recording/record_path/
  record_error`）已接通，复用同一 `Mp4Recorder`：只在收到关键帧后才开文件，
  默认写入用户 Videos 目录，画面尺寸变化时同样滚动到新段；`flutter analyze`
