# M10.8 — 配置来源、UDP 接收缓冲与启动自检

## 1. 背景与目标

M10.0–M10.7 已把 hbbs/hbbr 的中继、治理、审计与独立节点对齐到 chast 服务端，
但两者的**运维入口**仍有一截差距：RustDesk 的 `hbbs`/`hbbr` 除了命令行参数，
还读取 `--config` 指定的 INI、工作目录下的 `.env`、以及继承的环境变量，并且
按 `BIND`、`PORT`、`RELAY-SERVERS`、`RMEM`、`TEST_HBBS`、`ALWAYS_USE_RELAY`、
`MAX_PUNCH_REQUESTS`、`DB_URL` 这些固定键名工作；`hbbr` 还会自动加载工作目录
下的 `blacklist.txt` / `blocklist.txt`；`hbbs` 启动时还能用 `TEST_HBBS`
对本机会合端口做一次 UDP 往返自检。

chast 目前只有命令行参数，名单文件必须显式给路径，UDP 接收缓冲用系统默认值，
也没有启动自检。本阶段补上这部分：

- 新增 `internal/servercfg`，为两个二进制提供相同来源与优先级；
- `chast-server` / `chast-relay` 新增 `--config` 与 `--env-file`；
- UDP 监听统一设置接收缓冲（`--rmem`，对齐 hbbr 的 `RMEM`）；
- 名单文件路径留空时回退到工作目录下的 `blacklist.txt` / `blocklist.txt`；
- 启动时可选地对一个 UDP 端口做自检（`--test-punch`，对齐 `TEST_HBBS`）；
- 协议保持 v23，主机/查看者代理无需改动。

## 2. 能力对照

| hbbs / hbbr | chast（本阶段前） | 本阶段 |
| --- | --- | --- |
| 参数 > `--config` INI > `.env` > 环境变量 | 只有命令行参数 | `servercfg.Apply`，同一套来源与优先级 |
| 键名大小写不敏感、`-`/`_` 等价 | — | `normalizeKey`，另接受 `CHAST_<KEY>` 前缀 |
| `Y/N` 布尔值 | — | `parseBool` 兜底 `y/yes/on`、`n/no/off` |
| `BIND` / `PORT` / `RELAY-SERVERS` 等固定键 | 只有同名 flag | flag 名即键名（`punch-listen`、`relay-servers` …）；同时接受 RustDesk 原名别名 |
| `RMEM`（UDP 接收缓冲） | 系统默认 | `--rmem`，作用于会合与全部中继 UDP 端口（共享载体只有 TCP/WebSocket，无 UDP 侧） |
| `blacklist.txt` / `blocklist.txt` 自动加载 | 必须显式 `--relay-*-file` | 留空时回退工作目录同名文件 |
| `TEST_HBBS` 启动自检 | 无 | `--test-punch`（空=跳过，`auto` 或 `host:port`；仅 `chast-server`） |
| `DB_URL` / SQLite 持久化 | JSON 状态文件 | 不在本阶段；状态文件已覆盖绑定持久化 |

不做：INI 的分节语义（chast 只按 key=value 读取，分节头被忽略）、配置热重载、
RustDesk 的 `DB_URL`/SQLite 后端替换、TLS 证书热加载。

## 3. 配置来源

优先级从高到低：

1. 命令行显式给出的 flag（`flag.Visit` 判定，含 `--x=value` 与 `--x value`）；
2. `--config <path>` 指定的 INI；
3. `--env-file <path>` 指定的 dotenv（默认 `.env`，缺失时静默跳过，其他读错
   直接退出；`--env-file ""` 关闭）；
4. 进程环境变量。

键名规范化：去掉首尾空白与成对引号，`-` 换成 `_` 后转大写；查找时先试
`CHAST_<KEY>` 再试 `<KEY>`，因此 `HOST_TTL`、`host-ttl`、`CHAST_HOST_TTL`
指向同一个 flag。INI 的 `[section]` 行、以 `#`/`;` 开头的行与空行被跳过；
dotenv 额外接受 `export ` 前缀与成对单/双引号。同一文件内重复键以最后一次为准。

`Apply` 只填充**没有**在命令行出现的 flag，且跳过 `config`/`env-file` 自身；
值转换失败时先按 `Y/N` 重试一次，仍失败则返回 `config <flag>=<value>: …`
并让进程退出，避免带病启动。

## 4. 实施状态

已完成（未发布）：

- `internal/servercfg`：`Layer`/`FromEnv`/`LoadINI`/`LoadEnvFile`/`Apply`，
  包注释说明优先级与键规范化；
- `servercfg_test.go`：INI 分节与注释跳过、dotenv `export`/引号/前缀、
  显式 flag 优先、INI 覆盖 .env、坏值报错、`CHAST_` 前缀优先；新增别名、
  canonical 键优先与跨层优先级用例；
- `cmd/chast-server`、`cmd/chast-relay`：新增 `--config`、`--env-file`，在
  `flag.Parse()` 之后、读取任何业务参数之前应用；
- `--rmem`：新增 `internal/netutil.SetUDPReadBuffer`，在 `rendezvous.New`
  与 `relay.NewManager`/`listenOn`（含按租约地址重绑）上设置 `SO_RCVBUF`
  并通过 `GetsockoptInt` 回读生效值；`0` 保持系统默认，失败只告警。
  `/v1/server` 增加 `punch_udp_read_buffer`/`relay_udp_read_buffer`，
  `/v1/stats` 中继统计增加 `udp_read_buffer_bytes`，`/metrics` 增加
  `chast_punch_udp_read_buffer_bytes`/`chast_relay_udp_read_buffer_bytes`。
  原计划的“共享载体 UDP 侧”不存在：共享载体只有 TCP/WebSocket；
- 默认名单：`relay.DefaultListFile` 在显式路径为空时探测工作目录下的
  `blacklist.txt`/`blocklist.txt`，存在则加载；两个二进制启动日志记录实际
  路径，控制台 `b`/`B` 与 `/v1/stats` 的 `policy.blacklist`/`blocklist` 可查；
- 启动自检：`rendezvous.ProbeTarget`/`Probe` 实现 `--test-punch`；空值跳过，
  `auto` 仅在 `--advertise` 未配置或为回环时探测本机监听地址，显式
  `host:port` 无条件探测；注册临时 ID，每秒重发签名 keepalive，12 s 无应答
  退出并返回最后错误，成功日志记录 RTT；
- RustDesk 别名：`BIND`/`PORT`→`punch-listen`（`PORT` 覆盖 `BIND` 内的端口，
  仅 `PORT` 时保留当前主机）、`RELAY-SERVERS`→`relay-servers`、
  `RMEM`→`rmem`、`TEST_HBBS`→`test-punch`、`ALWAYS_USE_RELAY`→`relay-only`、
  `MAX_PUNCH_REQUESTS`→`punch-rate-max`；同层 canonical 键优先，别名遵循
  INI > .env > 环境的层级，显式 flag 始终最高；
- `README.md` 部署小节补充配置来源与别名、默认名单、`--rmem` 与自检说明；
- 自动化：改动文件 gofmt 无差异（工作区 CRLF 规范化后检查），`go vet ./...`、
  `go build ./...`、`go test ./... -count=1` 通过。

已知限制：`--test-punch` 只在 `chast-server` 实现；`chast-relay` 没有会合
端口，其中继端口需要有效租约才应答，因此没有等价自检。`BIND`/`PORT` 是
常见的环境变量名，部署时应优先使用 `punch-listen` 或 `CHAST_` 前缀避免误配。

## 5. 测试

- `internal/servercfg` 单测覆盖上表全部行为；
- 二进制级回环：同一组 flag 分别由 `.env`、INI、环境变量提供，`/v1/server`
  与日志显示最终值；显式 flag 不被覆盖；
- `--rmem` 通过 `GetsockoptInt` 回读生效值，并由 `/v1/server`、`/v1/stats`
  与 `/metrics` 交叉断言（Linux 可能把请求值翻倍，Windows 回环为原值）；
- 默认名单文件在临时工作目录放置后启动，控制台 `b`/`B` 列出条目，
  `/v1/stats` 的 `policy.blacklist`/`blocklist` 为 1；
- `--test-punch` 对可用端口成功、对关闭端口在 12 s 后失败退出。

## 6. 验证记录

2026-10-25，配置来源、接收缓冲、默认名单与启动自检在单机回环上验证：

- 拓扑：`build/m108` 工作目录放置 `config.ini`、`.env`、`blacklist.txt` 与
  `blocklist.txt`；`chast-server` 显式指定 `--punch-listen 127.0.0.1:18444`
  与 `--relay-ports 42100-42102`，INI 为 `http-listen=127.0.0.1:18843`、
  `punch-listen=127.0.0.1:18443`、`relay-ports=42000-42002`、
  `rmem=1048576`，`.env` 为 `PUNCH_LISTEN=127.0.0.1:18442`、
  `HTTP_LISTEN=127.0.0.1:18842`、`ALWAYS_USE_RELAY=Y`、`RMEM=524288`，
  环境变量为 `PUNCH_LISTEN=127.0.0.1:18441`、`HTTP_LISTEN=127.0.0.1:18841`、
  `ALWAYS_USE_RELAY=N`、`RMEM=262144`、`TEST_HBBS=auto`。
- 优先级：ready 日志中 `punch=127.0.0.1:18444`、`relay_ports=42100-42102`
  （显式 flag 覆盖 INI），`HTTP API listening on 127.0.0.1:18843` 与
  `rmem=1048576`（INI 覆盖 .env/环境变量），`relay_only=true`
  （.env 的 `ALWAYS_USE_RELAY=Y` 覆盖环境变量的 `N`）。去掉 `--config` 后，
  `.env` 的 18842/18442/524288/Y 覆盖环境变量的 18841/18441/262144/N，
  `relay_only=true` 且自检目标为 `127.0.0.1:18442`。
- 生效缓冲：`/v1/server` 返回 `punch_udp_read_buffer:1048576` 与
  `relay_udp_read_buffer:1048576`；`/metrics` 的
  `chast_punch_udp_read_buffer_bytes`、`chast_relay_udp_read_buffer_bytes`
  同为 `1048576`；`/v1/stats` 的 `relay.udp_read_buffer_bytes` 一致。
- 默认名单：启动日志分别输出 `using the default relay blacklist file
  path=blacklist.txt` 与 `blocklist.txt`；`/v1/stats` 为 `blacklist:1`、
  `blocklist:1`；管理台 `b`/`B` 分别返回 `203.0.113.9` 与 `198.51.100.7`。
  `chast-relay` 在同样目录启动后也加载两份名单，`b`/`B` 输出一致，ready
  日志为 `rmem=1048576 relay_read_buffer=1048576`，`/v1/stats` 为
  `udp_read_buffer_bytes:1048576`。
- 自检成功：`TEST_HBBS=auto` 的两次回环启动均在 ready 前输出
  `startup punch self-check passed target=… rtt=2ms`，临时 ID 在结束后从注册表
  移除。自检失败：`--test-punch 127.0.0.1:18449`（无监听端口）运行 12 s 后
  `exit=1`，报 `no keepalive acknowledgement from 127.0.0.1:18449 within 12s:
  context deadline exceeded (last error: … i/o timeout)`。
- 自动化：改动文件经 LF 规范化后 `gofmt -l` 无输出（工作区为 CRLF，直接运行
  会把所有文件列为待格式化，属既有换行差异）；`go vet ./...`、`go build
  ./...`、`go test ./... -count=1` 通过（18 个有测试的包）。
- 已知限制：`--test-punch` 只在 `chast-server` 提供；`chast-relay` 的中继 UDP
  端口需要有效租约才能完成挑战，无法用同一套临时 ID 流程自检。`BIND`/`PORT`
  是常见环境变量名，部署时建议使用 `punch-listen` 或 `CHAST_` 前缀。配置只在
  启动时读取，不做热重载；INI 不支持分节层级，多个 `[section]` 中的同名键
  后者覆盖前者；dotenv 不展开 `$VAR`；`CHAST_` 前缀与 RustDesk 原名同时存在时
  chast 键优先。
