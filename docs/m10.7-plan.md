# M10.7 — 中继带宽限制、黑名单与降级

## 1. 背景与目标

RustDesk 的 hbbr 除了转发，还承担中继资源治理：每个会话有单连接带宽上限，
所有会话共享总带宽上限，黑名单地址被压到更低的“惩罚速度”，阻断名单地址
直接断开；会话持续跑满带宽达到阈值后会在启动一段时间后自动降级。hbbr 还
提供 `blacklist.txt` / `blocklist.txt` 与回环控制台管理这些状态。

M10.0–M10.6 的 chast 中继已有 UDP、每端口 TCP/WS 载体与共享载体，并能把
中继放到独立节点，但没有任何带宽或地址级治理。本阶段对齐 hbbr 的这部分：

- 新增 `internal/relay` 内的策略对象：单会话、全局总带宽、黑名单速度、
  降级阈值与降级启动时间；
- 策略同时作用于本机 `relay.Manager` 与 `chast-relay` 节点，二者不改协议；
- 黑名单按地址限速，阻断名单拒绝新会话并断开既有会话；
- 控制台命令与 hbbr 同名：`ba/br/b`、`Ba/Br/B`、`ls/tb/sb/dt/t/u`；
- `/v1/stats` 与 `/metrics` 暴露策略配置、名单大小、限速/丢弃/阻断/降级计数
  与活动会话用量；chast 协议保持 v23，主机/查看者代理无需改动。

## 2. 能力对照

| hbbr | chast（本阶段前） | 本阶段 |
| --- | --- | --- |
| `SINGLE_BANDWIDTH`（默认 128 Mb/s） | 无 | `--relay-single-bandwidth`，每个查看者会话双向合计 |
| `TOTAL_BANDWIDTH`（默认 1 Gb/s） | 无 | `--relay-total-bandwidth`，全实例所有会话合计 |
| `LIMIT_SPEED`（默认 32 Mb/s，黑名单速度） | 无 | `--relay-blacklist-speed` |
| `DOWNGRADE_THRESHOLD` / `DOWNGRADE_START_CHECK` | 无 | `--relay-downgrade-threshold` / `--relay-downgrade-after` |
| `blacklist.txt` / `blocklist.txt` | 无 | `--relay-blacklist-file` / `--relay-blocklist-file`，可选 |
| hbbr 控制台 `ba/br/b`、`Ba/Br/B`、`ls/tb/sb/dt/t/u` | 无 | 同一组命令；hbbs 管理台与节点回环控制台都可执行 |
| 黑名单限速、阻断名单断开 | 无 | UDP 超限丢弃；TCP/WS 载体超限等待；阻断名单 1 s 内断开 |

不做：按 ID 而不是按地址限速；GeoIP；跨节点共享名单；对 QUIC 连接做
读取级整形（UDP 只能按数据报丢弃，拥塞控制由端点负责）；动态改端口。

## 3. 语义

- **单位**：命令行参数与控制台使用 Mbit/s；内部按 bit/s 保存。`0` 表示
  不限制该维度。默认值与 hbbr 相同：单会话 128、总带宽 1024、黑名单 32。
- **会话**：一个查看者的一次中继会话（UDP 端口上的当前查看者、每端口载体
  查看者或共享载体查看者）。双向流量计入同一会话；源地址取查看者地址。
- **UDP**：令牌不足时丢弃该数据报，计入 `rate_dropped`；主机→查看者和
  查看者→主机都受限。
- **TCP/WS 载体**：令牌不足时睡眠到补足再转发，形成背压；计入
  `limited_bytes`。读取超时（180 s）足以覆盖正常的限速等待。
- **黑名单**：会话建立时命中即使用黑名单速度；会话期间新增黑名单在 1 s
  内切换，删除后恢复单会话速度。
- **阻断名单**：会话建立时命中直接拒绝；会话期间新增在 1 s 内关闭会话。
  对于 UDP，查看者数据报被丢弃，不发 `busy`，避免把阻断状态当作可重试错误。
- **降级**：会话运行满 `--relay-downgrade-after`（默认 30 min）后，若平均
  速率超过 `threshold × single`（默认 0.66），本会话剩余时间按黑名单速度
  处理；只降不升，与 hbbr 一致。阈值 `0` 关闭降级。
- **名单匹配**：按查看者 IP 的规范文本匹配；名单文件每行取第一个字段，
  支持 hbbr 的 `ip note` 写法；`#` 开头与空行忽略。显式给出文件路径时，
  启动加载、控制台增删后原子回写；未给路径则只在内存中。
- **总带宽**：所有会话、两个方向共享一个令牌桶。UDP 超限丢弃；载体等待。
- **令牌桶**：容量取 `max(1 s × 速率, 单个最大帧)`，初始满桶；因此允许
  一个最大帧的突发，之后按配置速率平滑。

## 4. 接入点

- `internal/relay/policy.go`：配置、名单、令牌桶、会话、控制台命令与统计；
- `Manager`：UDP 端口、每端口载体、共享载体在查看者绑定/解绑时开/关会话；
  `Stats()` 增加 `policy` 与 `sessions`；
- `internal/admin`：未知命令转发给 `relay.Policy.Command`，帮助文本补充策略
  命令，`stats` 增加策略摘要；
- `cmd/chast-relay`：新增 `--admin-listen`（默认 `127.0.0.1:8449`，空值
  禁用）与同一组策略参数；回环控制台复用 `relay.Policy.Command`，`stats`
  输出节点摘要；
- `cmd/chast-server`：新增同一组策略参数；
- `internal/api`：`/metrics` 增加
  `chast_relay_single_bandwidth_bps`、`chast_relay_total_bandwidth_bps`、
  `chast_relay_blacklist_speed_bps`、`chast_relay_policy_blacklist`、
  `chast_relay_policy_blocklist`、`chast_relay_policy_sessions`、
  `chast_relay_limited_bytes_total`、
  `chast_relay_rate_dropped_total{unit="datagrams"|"bytes"}`、
  `chast_relay_blocked_sessions_total`、`chast_relay_downgraded_sessions_total`
  与共享载体的 `chast_carrier_blocked_total`。

## 5. 控制台

```
blacklist-add(ba) <ip[|ip...]>
blacklist-remove(br) <ip|all>
blacklist(b) [ip]
blocklist-add(Ba) <ip[|ip...]>
blocklist-remove(Br) <ip|all>
blocklist(B) [ip]
downgrade-threshold(dt) [0..1]
downgrade-start-check(t) [seconds]
limit-speed(ls) [Mbit/s]
total-bandwidth(tb) [Mbit/s]
single-bandwidth(sb) [Mbit/s]
usage(u)
```

`u` 每行一个活动会话：IP、键、运行秒数、总字节、峰值/平均/当前速率、
是否降级、是否黑名单。命令大小写敏感，`b` 与 `B` 分别是黑名单与阻断名单。

## 6. 测试

- 策略单测：令牌桶丢弃/等待、总带宽共享、黑名单生命周期与慢速档、阻断、
  降级判定、控制台命令与配置校验；
- `internal/relay`：UDP 限速丢包、阻断名单拒绝新 UDP 查看者、阻断名单释放
  已绑定的 UDP 查看者、每端口载体与共享载体拒绝阻断地址；
- `internal/admin`：`PolicyOnly` 回环控制台转发策略命令；
- `internal/api`：`/metrics` 策略指标；
- 真实二进制回环：`chast-server` + `chast-relay` + 主机/查看者代理，验证
  UDP 丢包限速、黑名单/阻断即时生效、降级、名单文件启动加载、节点故障回退
  到本机中继后同一策略仍生效、`u`/`stats`/`/v1/stats`/`/metrics` 一致。

## 7. 验证记录

2026-10-25，单机回环验证：`chast-relay`（控制面 `127.0.0.1:18547`、端口
`41300-41399`、载体 `127.0.0.1:18548`、控制台 `127.0.0.1:18549`）与
`chast-server`（API `127.0.0.1:18543`、管理台 `127.0.0.1:18546`、本机中继
`41400-41499`），主机/查看者代理与 UDP 回显目标；协议仍 v23。

- 参数面：节点启动 `--relay-single-bandwidth 0.08 --relay-total-bandwidth 100
  --relay-blacklist-speed 0.05`，控制台 `dt 0.01`、`t 3` 后 `stats` 显示
  `single_bps=83886 total_bps=104857600 blacklist_bps=52428 ... ratio=0.01
  after=3s`；hbss 使用 `64/512/16`，`/v1/stats` 的 `relay.policy` 与
  `/metrics` 的 `chast_relay_single_bandwidth_bps` 等 gauge 一致。
- 控制台：节点 `h/stats/sb/tb/ls/dt/t/b/B/u` 全部可用，`ba/br/Ba/Br/all`
  的增删与文件回写生效；hbss 管理台同样可执行策略命令，`stats` 增加策略摘要。
- 阻断：会话建立前 `Ba 127.0.0.1` 后查看者探针无回包，节点
  `blocked_sessions=1`、端口 `dropped=1`；`Br` 后同一探针 3 次往返成功
  （双向各 21 字节）。会话进行中新增阻断由集成测试覆盖：下一数据报被丢弃，
  查看者槽位立即释放，清除名单后可重新接入。
- 限速与降级：`sb 0.08` 下 burst 400 × 1400 B 仅收到 4 个回包；节点计数
  `limited_bytes=319200`、`rate_dropped_datagrams=228`、
  `rate_dropped_bytes=319200`、`downgraded_sessions=1`，`u` 显示同一会话
  `downgraded=true`；端口 `41300` 统计
  `to_host=58821 to_viewer=5621 dropped=229 blocked_sessions=1`。
- 黑名单运行时切换：`ba 127.0.0.1` 后 `u` 显示 `blacklisted=true`，
  `br all` 后恢复 `false`，无需重建会话。
- 名单文件：第二个节点启动前写入 `seed-blacklist.txt`（`203.0.113.77`）与
  `seed-blocklist.txt`（`198.51.100.5`），启动后 `b`/`B` 各列出一条，`stats`
  显示 `blacklist=1 blocklist=1`。
- 节点故障回退：停止节点后主机续租回退本机中继（`relay=127.0.0.1:41400`），
  在新查看者路径上重复阻断与 burst：hbss `/metrics` 的
  `chast_relay_limited_bytes_total 338800`、`chast_relay_rate_dropped_total`
  为 `242`（`bytes` 338800）、`chast_relay_blocked_sessions_total 1`、
  `chast_relay_downgraded_sessions_total 1`，本机端口 `41400` 统计
  `to_host=49021 to_viewer=15421 dropped=243 blocked_sessions=1`，`u` 同样
  显示 `downgraded=true`。
- 自动化：`gofmt -l .` 无输出，`go vet ./...`、`go build ./...`、
  `go test ./... -count=1` 通过；`policy_test.go` 覆盖令牌桶/名单/降级/命令，
  `policy_relay_test.go` 覆盖 UDP 限速、阻断拒绝与阻断释放、载体与共享载体
  阻断，`internal/admin` 覆盖 `PolicyOnly` 控制台，`internal/api` 覆盖策略
  指标。

已知限制：令牌桶按会话与全局两级，不支持按 ID 限速；UDP 只能整包丢弃，不做
读取级整形；名单只在内存与给定文件之间同步，不做跨节点分发；降级只降不升；
真实跨机带宽、时钟与多节点策略一致性仍需部署复核。
