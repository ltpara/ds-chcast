# 文件剪贴板按需读取

日期：2026-11-09。继续补齐本地 RustDesk 固定版本 `7423dced37845c48093b6f71bd82e4a16cc8c79d` 的文件剪贴板差距。本轮实现 Windows 双向虚拟文件剪贴板，不表示全部复制来源、粘贴程序和网络环境都已经验收。

## 用户行为

复制文件或文件夹后，接收端立即获得名称、目录结构和大小。正常原生主机、服务工作进程和 Windows 观看端不再先下载整个目录到暂存文件夹；粘贴程序读取文件流时，才按偏移请求实际字节。目录直接通过描述表达，零字节文件仍是文件。

接收端使用 `FileGroupDescriptorW` / `FileContents`、`IDataObject` 和 `IStream`。支持顺序读取、随机定位、克隆流、大小查询和异步粘贴能力接口。操作为复制，不因目标程序报告移动而删除源文件。完成后的文件属于粘贴目标，远程连接结束不会删除这些文件。

关闭同步、撤销剪贴板权限、断开连接、替换远程内容或失去本地剪贴板所有权，会使旧虚拟文件失效，并唤醒等待回复的读取。文件复制继续只依赖剪贴板权限与方向策略，不要求普通文件传输权限。

## 实现

- 协议为 **v59**，两端需要一起更新。CCLB 容器升级至版本 2，在头部携带发送代次；双方丢弃较旧代次的内容，避免并行剪贴板流晚到后覆盖新复制。文件请求同时绑定会话、代次、原列表索引和范围。
- 每次范围请求最多 64 KiB，每个方向限制未完成请求数量。传输层核对已发送/收到的请求、代次、长度及方向权限，再交给会话处理；不接受无匹配请求的回复。撤权清除相关队列和请求记录。
- `ClipboardFileChannel` 在会话线程处理网络状态，独立执行器读取本地文件。COM 对象只持有可取消的共享状态，不保存主机、观看端或 QUIC 对象的裸指针。等待网络超过 20 秒会使该虚拟文件列表失效。
- 剪贴板扫描线程保留文件的元数据句柄。收到读取请求后通过原句柄重新打开数据句柄，校验文件身份、大小和修改时间；路径被换成同名新文件时，旧请求不会读取新文件。已修改内容读取失败，不混合两个版本。源身份变化参与新复制判断，即使名称和大小相同也能重新发布。
- 原生剪贴板所有者在独立 STA 线程中运行消息循环，并绑定调用者桌面。被占用导致的发布失败可以重试；停止时先取消读取，清理时仅清除自己仍然拥有的剪贴板。
- 自身发布的远程虚拟文件带本地标记，轮询时跳过，避免触发延迟读取或跨连接回送。旧暂存式接口保留供已有注入式集成使用；默认原生收发及本轮双向探针使用虚拟文件路径。

## 边界

读取来源仍是本机 CF_HDROP 文件/文件夹；没有增加从其他应用的虚拟文件 IDataObject 导入功能。目标应用须支持 Windows Shell 虚拟文件格式。原生文件描述的路径长度必须小于 `MAX_PATH` 个 UTF-16 单元；无法表达的名称、冲突路径会拒绝发布，不截断或重命名。保留 256 个列表条目、64 KiB 列表、16 层目录和单文件 16 GiB 限制。

本轮已验证原生 OLE 跨线程交互和真实会话数据收发，但没有把它称为 Explorer 人工粘贴验收，也未验证跨网络吞吐、多用户/RDP 切换及锁屏恢复。当前按 64 KiB 请求/回复工作，没有做流水线预读或断线后的粘贴恢复；高时延链路吞吐仍待测量。更广泛的发射端开发目标仍未完成。
