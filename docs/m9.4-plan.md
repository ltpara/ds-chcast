# M9.4 — 音频设备选择、回声消除与降噪

更新时间：2026-10-24
分支：`feat/m7-security`
基线：M9.3 完成（协议 v23；多显示器合并视图）。
本阶段**不改变协议版本**，仍为 v23；所有能力都在本机音频链路内完成。

## 1. 范围与取舍

M8.5 打通双向音频后留下三个实际缺口：两端都无法选择音频端点；查看器
麦克风拾取扬声器声音、主机 loopback 又把远端语音采回来，形成双向回声；
麦克风没有降噪。M9.4 补齐这三项。

| 能力 | 行为 |
| --- | --- |
| 主机输出设备 | 设置中可选择用于系统声音捕获的 render 端点，留空跟随系统默认；该端点同时用于播放查看器麦克风 |
| 查看器播放设备 | 音量按钮长按列出 render 端点，可在会话内切换；留空跟随默认 |
| 查看器麦克风设备 | 沿用 M8.5 的采集端点选择，不重复实现 |
| 主机回声消除 | loopback 采集以“本机正在播放的远端麦克风 PCM”为参考，抵消远端语音的回采 |
| 查看器回声消除 | 麦克风采集以“本机正在播放的系统声音 PCM”为参考，抵消扬声器串入麦克风的远端声音 |
| 查看器降噪 | 麦克风在 AEC 之后做谱减降噪；AGC 仍不做，避免音量泵动 |
| 兼容 | 不改变 Hello/AudioInfo/Opus 载荷；旧版本仍按 v23 互通 |

不做的部分：

- **不做 AGC/自动增益。** 语音通路的增益交给系统与 Opus；自动增益在
  扬声器/耳机切换时容易泵动，单独评估。
- **不做音频设备热插拔的自动切换。** 固定设备被拔出后持续重试同一 id，
  与现有麦克风策略一致；用户可切回“系统默认”。
- **不做每端独立的回放设备。** 主机只有一组输出设置，系统声音捕获与
  远端语音播放共用，保证 AEC 参考与实际播放路径一致。
- **不做跨进程/虚拟声卡方案。** 不引入虚拟音频驱动，也不把参考信号
  经网络回传；AEC 只在本进程内完成。
- **不提升协议版本。** 设备选择与 DSP 都是本地行为，线上格式没有变化。

关键语义：

1. **AEC 需要“正在播放”的参考。** 只有远端麦克风/系统声音确实在渲染时
   才启用；没有播放时旁路并重置自适应滤波器，避免把系统声音误当回声。
2. **参考延迟固定、滤波器覆盖余量。** 参考从解码后立即写入环形缓冲，
   读取时回退 `120 ms`；Speex 自适应滤波器长度 `200 ms`，覆盖播放 lead、
   端点缓冲与声学传播的偏差。参考与近端必须同为 48 kHz。
3. **AEC 在采集线程、编码之前。** 主机在 loopback 重采样到 48 kHz 立体声
   之后处理；查看器在麦克风重采样到 48 kHz 单声道之后处理。处理失败的
   帧按原样通过，不中断音频流。
4. **设备留空跟随默认。** 固定 id 失效时保持相同的 AudioInfo 重试，
   不重新协商；恢复后继续编码。
5. **回声消除可关闭。** 主机设置 `audio_aec` 默认开启；查看器在麦克风
   长按菜单里可分别开关 AEC 与降噪，改动在 1 个音频块内生效。

## 2. 协议

版本保持 v23，ALPN 仍为 `chast/1`。没有新消息、新字段或标志位变化。
`AudioInfo` 的 Opus 格式、`CMIC` 首部与现有 20 ms 帧长都不变。不同构建
之间唯一新增的是本机能力，线上互通性不受影响。

## 3. 音频参考与 DSP

**参考环形缓冲**

- 新增 `AudioReference`：固定 48 kHz 立体声 s16 的线程安全环形缓冲，
  容量约 2 秒。`push()` 接受 1/2 声道，单声道复制成双声道。
- `read_delayed(frames, delay_ms, out)` 返回“最新写入位置回退 delay_ms
  之前”的整块参考；历史不足时补零。
- `set_active(bool)` 在播放开始时打开、停止/静音时关闭；关闭时 `read`
  返回零，DSP 旁路并重置滤波器，避免用静音训练回声路径。

**自适应回声消除**

- 引入 vcpkg `speexdsp`（BSD-3-Clause）静态库，只在 `chast.audio` 内使用。
- 新增 `AudioPreprocessor`：
  - 固定 10 ms / 480 样本帧；近端 1 或 2 声道，参考固定 2 声道；
  - `speex_echo_state_init_mc(480, 9600, near, 2)`；每帧读取延迟参考并调用
    `speex_echo_cancellation`；
  - 需要降噪时，每个近端声道一个 `SpeexPreprocessState`，打开 DENOISE，
    关联 echo state 做残余回声抑制；AGC 保持关闭；
  - 输入块可任意长度，内部攒帧；停止时丢弃不足 10 ms 的尾部。
- 统计：已处理帧、参考欠载帧、重置次数。欠载表示参考缓冲尚未跟上，
  只影响当帧抑制效果，不报错。

**降噪**

- 只用于查看器麦克风。谱减噪声估计由 Speex 预处理器完成；默认开启，
  与会话级 AEC 开关分开。

## 4. 设备选择

**主机**

- `HostSettings` 新增：
  - `audio_device`：render 端点 id，UTF-8；空表示系统默认；
  - `audio_aec`：bool，默认 true。
- 设置文件新增 `audio_device=` 与 `audio_aec=1/0` 两行；未知 id 在保存时
  允许保留（设备可能稍后接入），会话创建时打不开则按音频不可用处理。
- 托盘设置“高级”页新增输出设备下拉框（含“系统默认”）、AEC 复选框；
  刷新按钮重新枚举。设备列表来自 `list_audio_outputs()`。
- 同一个端点用于 `create_loopback_capture()` 和主机侧麦克风播放器；
  `HostServerConfig` 在创建会话时把设置写进两个 config。

**查看器**

- `AudioPlayerConfig` 新增 `device_id`；`create_audio_player()` 优先
  `GetDevice(id)`，空 id 才取默认 render 端点。
- 新增 bridge `listAudioOutputs` / `selectAudioOutput`；状态增加
  `audioDevice`、`audioDeviceName`。
- 音量按钮长按弹出输出设备菜单（“系统默认”+ 所有活动 render 端点）；
  选择后立即重建播放器，保留解码器与最近时钟偏移；重建失败回退默认并
  在 `audioError` 中说明。
- 麦克风长按菜单在设备列表上方增加“回声消除”“噪声抑制”两个复选项；
  bridge `setAudioProcessing(aec, ns)` 保存到引擎，重启麦克风采集生效。

## 5. 主机接入

- `HostServer` 会话在开启系统声音且开启 AEC 时创建 `AudioReference`：
  - 传给 loopback capture；capture 在重采样后、静音门之前处理；
  - CMIC 解码线程在把 PCM 交给播放器时同步写入参考；
  - 播放器创建/启动时 `set_active(true)`，停止/释放时 `false`。
- AEC 启用时静音门改用峰值阈值（≤32）判断数字静音，避免残余噪声
  让空闲端点持续发送 Opus。
- `AudioCaptureStats` 增加 `processed_frames`、`reference_underruns`、
  `dsp_resets`；`HostServerStats` 汇总为 `audio_dsp_frames` /
  `audio_dsp_resets`，托盘状态与日志可见。
- 没有麦克风权限或没有 CMIC 流时参考保持 inactive，loopback 原样通过。
- 设备打开失败仍按现有策略：系统声音不可用不影响视频；麦克风播放器
  打不开则回答该 CMIC 流打不开。

## 6. 查看器与 Flutter

- `ViewerEngine`：
  - 会话级 `AudioReference` 在系统声音播放器启动后 active，暂停/静音或
    音频流结束时 inactive；
  - 解码出的系统声音 PCM 在非静音时写入参考；
  - 麦克风 `MicrophoneCaptureConfig` 带上参考、AEC/NS 开关；
  - 输出设备原子变量变化时重建播放器；`setAudioProcessing` 触发麦克风
    采集重建；
  - 状态增加 `audioDevice/audioDeviceName/audioAec/audioNoiseSuppression`
    与麦克风 `aecFrames/nsFrames` 计数。
- `ViewerStatus` 与 bridge map 同步新增字段。
- Flutter：
  - 工具栏音量按钮支持长按输出设备菜单；
  - 麦克风长按菜单增加两个处理开关；
  - 设备切换与开关失败通过 SnackBar 提示；
  - 新增 widget 测试覆盖菜单项、选中标记与回调。

## 7. 验证

自动化：

- 新增 `chast-audio-dsp-test`：
  - 合成远端噪声经 140 ms 延迟、衰减和简单滤波混入近端，AEC 稳态 ERLE
    ≥ 20 dB；
  - 双讲段近端语音保留（处理后与原始近端相关性 ≥ 0.9）；
  - 参考 inactive 时输出与输入逐样本一致；
  - 降噪把平稳噪声底降低 ≥ 6 dB，同时保留幅度调制的 440/880/1320 Hz
    谐波语音能量（输出/输入 RMS ≥ 30%）；
  - 单声道/立体声近端、非整帧输入、参考欠载不崩溃。
- `chast-host-settings-test`：`audio_device`/`audio_aec` 往返、空值、
  非法布尔与未知键警告。
- `chast-audio-codec-test` 保持通过（DSP 不改变编解码）。
- `verify --microphone` 与 `verify` 普通回环保持通过，确认 AEC 开关
  不影响合成音频链路与视频。
- Flutter：`analyze`、`test`（新增输出设备菜单与处理开关）、
  `build windows --release`。
- `ctest -C Release` 全绿（新增 DSP 测试后 15 项）。

手工（本机可做）：

- 长按音量选择本机扬声器/默认设备，系统声音不断流。
- 查看器麦克风开启 AEC/降噪后，主机扬声器听到的语音正常、无明显金属声。
- 关闭 AEC 后对比宿主 loopback 中回采的远端语音。

需双机/真实声学环境：

- 扬声器外放时查看器不再听到自己的延迟回声；不同设备延迟下 AEC 收敛。
- 麦克风 AEC 对真实房间混响、双讲与设备切换的效果。

## 8. 完成标准

1. 主机与查看器都能选择音频端点，留空/设备丢失时按默认或固定 id 重试。
2. AEC 在合成回声测试中达到 ≥20 dB ERLE，inactive 时严格旁路。
3. 降噪与 AEC 开关不改协议，旧回环与 `verify --microphone` 不回归。
4. Flutter `analyze`/`test`/`build windows` 通过；`ctest -C Release` 全绿。
5. `docs/m9-plan.md`、`docs/roadmap.md` 与本计划状态同步。
