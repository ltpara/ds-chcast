# 本地 UAC 提权与主机接管（2026-11-09）

本轮完成从查看端请求、本机 Windows UAC、主机进程接管到查看端重新连接的实现。协议由 v59 升为 **v60**，主机、服务和查看端需要一起升级。

对照仍是 `D:/rustdesk-ref` 的 `7423dced37845c48093b6f71bd82e4a16cc8c79d`，主要参照 `src/server/connection.rs` 的 `ElevationRequest` / `handle_elevation_request` 和 `src/server/portable_service.rs`。RustDesk 的便携服务可用特权辅助进程继续原会话；本实现使用已明确提示的短暂断线和重连，还没有实现 SYSTEM 便携捕获/输入辅助服务。

## 使用与范围

- 查看端工具栏新增“请求管理员权限”。主机本地人员需要在 Windows UAC 上确认，或输入另一管理员账户的凭据；应用协议不传输 Windows 管理员密码。
- 请求必须来自已认证的桌面连接，并持有键鼠权限与当前控制权。文件、终端、摄像头会话和旁观者不能借此提权；已经提权的主机及 SYSTEM 服务显示已取得管理员权限。
- 每个托盘主机同时只允许一个本地请求。未提交时，连接结束、权限回收、超时或 UAC 取消都会保留原主机。Windows 已显示的 UAC 对话框可能要等本地人员关闭，后台会阻止随后启动的子进程接管。
- 新进程准备好后，查看端收到 `Restarting`，原主机才停止监听和隧道。新进程保留原端口、配置路径、设备证书、设备注册信息、密码、可信设备及 TOTP；成功后原窗口退出，失败时原窗口恢复监听。
- 接管会断开这个主机的所有现有连接。发起端收到接管通知后自动重连，按原认证策略重新认证；TOTP 可能需要新验证码，Click/Both 模式可能需要再次审批。其他查看者使用各自的正常重连策略。
- 不安装服务、不新增开机启动项。取得管理员权限不等于获得 SYSTEM 安全桌面捕获能力；后续 UAC/锁屏能否捕获仍受现有进程权限和 Windows 桌面 ACL 限制。

## 实现

### 协议与会话

`ElevationRequest=77` 携带非零请求 ID；`ElevationState=78` 携带请求 ID、状态和最多 256 字节的 UTF-8 原因。ID 0 只用于主机能力公告。解析拒绝非法状态、NUL、错误 UTF-8、超长内容和尾随数据。队列有界；权限判断在主机会话线程再次执行。

`IElevationTask` 将启动、轮询、提交和取消分开。发送接管通知成功入队后才提交，普通断线清理不会再取消已经提交的任务。提交后让出至少 350 毫秒供通知发送，这是有界的发送机会，不保证极端网络下通知一定到达；没有收到通知的查看者仍走已有掉线策略。

### 本机 IPC 与身份

`host/elevation_handoff.{h,cc}` 在独立线程调用 `ShellExecuteExW(runas)`。线程持有独立任务状态，不捕获窗口或 HostServer 的裸指针，取消不会阻塞视频线程等待 UAC。

接管通过随机名称、首实例、拒绝远程客户端的消息管道完成。ACL 限制到原用户、管理员和 SYSTEM，客户端没有创建第二实例的权限。父进程核对启动句柄对应 PID、会话、可执行文件和提权令牌；子进程核对管道服务器 PID、父进程创建时间、会话和可执行文件。命令行只携带端点标识和进程身份，不包含配置或凭据。

子进程从已验证的父进程复制原用户模拟令牌、取消事件和实例互斥量句柄。另一个管理员账户需要时，只在打开父进程期间临时开启调试权限，随后恢复。传递的配置由现有设置序列化器生成，直接经过本机管道，不产生明文交接文件。

原用户身份只包围证书、DPAPI 和配置持久化操作，之后恢复线程原来的身份。证书必须匹配原指纹；找不到时拒绝接管，不创建替代证书。原用户私钥在模拟期间取得并缓存在证书上下文，之后 SChannel 使用该上下文。TOTP 解密失败会中止接管，原密文不会被另一个管理员账户重新保护。

原窗口停止服务器后，先处理已经排队的令牌、可信设备、密码和远程设置保存通知，再发送最终配置。安全设置对话框尚未关闭时会等待其保存或取消。新进程报告同指纹监听就绪，并完成双向确认后，原窗口才退出。失败时先取消并等待新进程退出，再恢复原监听；卡住的本次子进程在清理超时后尝试终止，未确认退出前不抢占端口。

### 桌面暂停与重连

验收补齐了主机会话循环遗漏的每秒输入桌面检查。之前虽有 `next_desktop_check`，主循环并未调用，因此共享采集自行恢复时可能漏报桌面暂停。现在 UAC/锁屏期间持续检查，并在可访问时恢复采集。

查看端收到 Secure/Unavailable 桌面状态后，不再用普通的 20 秒无帧期限判断该会话失败；回到默认桌面时重置帧期限。传输失联判断仍有效。发起端的已计划提权重连最多 8 次，退避为 1/2/4/8/15/15/15/15 秒（首个实际启动约 800 毫秒），覆盖接管失败后的清理和恢复时间。认证失败或身份变化仍停止自动尝试，不改变信任指纹。

没有新增 CMake 测试目标。复用 `protocol`、`protocol_fuzz`、`host_settings`、`host_parity`，以及已有 Flutter 测试和 `chast-viewer-probe`。

- 协议往返、非法输入和模糊输入；设置的内存往返及原配置路径默认值。
- 真实 QUIC 的控制权限制、重复请求、权限回收、断线取消、提交次序。
- 使用当前测试可执行文件启动真实子进程，经过同一个生产管道实现验证父子身份、复制令牌、准备/提交/就绪确认。替换 UAC 启动器，因此没有弹出系统 UAC。覆盖取消、原指纹、DPAPI/TOTP、接管后 SChannel 握手和指纹不符时原主机恢复。
