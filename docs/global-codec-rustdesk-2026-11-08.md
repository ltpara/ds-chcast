# 全局编码协商与 RustDesk 对照

参考 `D:/rustdesk-ref` 提交 `7423dced37845c48093b6f71bd82e4a16cc8c79d`，主要入口是 `libs/scrap/src/common/codec.rs` 的 `Encoder::update`、`src/server/connection.rs` 的 supported_decoding 更新和连接退出清理。整体复刻目标仍未完成；本次推进 Windows 桌面连接的编码协商。

## 规则及结果

| 行为 | 当前实现 |
| --- | --- |
| 能力范围 | 所有已加入视频服务的桌面连接取交集，跨显示器生效，不再仅按同屏订阅取交集 |
| 编码偏好 | 每连接一票；只统计可供全部接收端解码、全部活动显示源编码的偏好；多数票生效 |
| Auto | 不投票。没有可用的显式票时，按 HEVC、H.264、AV1 的顺序尝试；每种格式优先硬件，软件兜底当前仅支持 H.264 |
| 不可用偏好 | 保存选择但排除计票，回复 Ok 和实际使用的编码；限制连接离开后重新参与计票 |
| 切屏 | 连接的能力和偏好保留；准备期间保留原屏和目标屏的订阅关联，每连接仍只投一票；成功后释放原订阅，失败或取消后释放目标订阅并重新协商 |
| 退出 | RAII 移除该连接的能力和投票，重新计算所有仍使用中的显示源 |
| 首次连接 | v53 Hello 增加编码偏好；CLI 把所选格式作为初始票，原生查看器默认 Auto，并携带已经排队的选择 |
| 准入失败 | 没有共同编解码格式，或候选编码无法产生 IDR 时，保留原有已提交的编码和投票，不向现有用户提交半套变更 |

RustDesk 同票时采用其 HashMap 遍历中首先遇到的最大票项，没有稳定次序保证。本实现按最早加入的连接打破同票，防止无操作的随机来回切换；多数票及可用性筛选与参考规则一致。

## 实现

`DesktopStreamPool::CodecPeer` 独立于显示器订阅。`CodecGroup` 串行处理准入、更新、迁移和退出；收集全部活动显示源，在每个源自己的 GPU 服务线程上创建并试编码候选编码器。全部源通过后才提交，否则释放候选并尝试下一个可用格式。原编码器在准备阶段继续保留，候选对象的创建、使用和销毁也都在所属服务线程。

每个连接记录按订阅标识区分的显示源集合，而非一个可以被提前覆盖的显示源。目标编码器准备成功后，切屏仍可能因后续步骤失败而放弃，隐私屏也有仅探测、不提交的路径。临时 `Capture` 销毁时只删除它自己的关联并重新计算；原屏继续参与协商，目标屏的硬件限制不再残留。这也保证切屏过程中短暂保留两个订阅不会给该连接多计一票。

准备期间暂停对应源的采集周期，但仍处理命令；显示缩放和采集重建与协商共用事务锁，不能在候选验证期间更换底层画面。提交后从 IDR 发布新格式，连接通过帧头和 StreamInfo 更新解码器。码率公告仍使用 v52 的格式快照核对，避免新码率先进入旧格式描述。

运行中 Auto 硬件编码连续三次失败时，该显示源排除硬件并重新进入全局协商。故障源必须实际证明软件 VP9 可用（2026-11-12 晚起软件回退由 H.264 改为 VP9），不能因为编码器已释放而当作普通离线显示器跳过；其他健康显示源保留硬件后端，并共同切到兼容格式。暂时没有共同格式时保留原有健康流，故障会话保留音频/控制并等待能力交集改变。恢复策略及真实编码验证见 [软件编码](software-encoder-2026-11-08.md)。

更新投票不必改变实际编码；回复包含全局实际格式。仅当实际码率、FPS 或格式改变时刷新流描述，保留“纯码率修改不额外产生 IDR”的行为。首帧/切屏描述改为值拷贝，避免协商替换订阅画面后继续引用旧元数据；已经排队的首个 IDR 直接使用，避免静态画面重复发送。

本次全局协商引入协议 **v53**，主机、服务 worker 和观看端需同步更新。新增 Hello 字段保留原有字段顺序，解析器拒绝未知偏好和多余字节。后续单连接多屏传输基础将当前版本升至 v54，见 [单连接多屏进度](D:/ds-chcast/docs/independent-streams-rustdesk-2026-11-08.md)。此协议不与 RustDesk 线协议互通。

## 验证

- `desktop_stream`：跨屏能力限制、不可用偏好暂存与恢复、稳定同票、多数票、Auto 撤票、所有投票退出后的自动选择、另一块显示器候选失败时整体不提交，以及 GPU 线程归属。切屏回退测试额外验证原屏在目标准备期间仍参与协商，放弃目标后无需原连接重新注册或投票即可恢复，并检查临时资源释放；强化后的测试通过日志 `build/global-codec-v53-lifetime-final-tests.log`（2.69 秒）。
- `host_parity`：17 个场景，包含真实 QUIC 跨屏交集、无共同能力拒绝、切屏保留能力、离开后两屏恢复，以及三连接跨屏投票和退出清理。订阅生命周期修复后通过日志 `build/global-codec-v53-lifetime-tests.log`（主机 38.86 秒、共享视频 2.75 秒）。测试等待格式公告时持续消费旧视频，避免测试本身触发 v52 的停读背压。
- `protocol`、`protocol_fuzz`：初始 Auto/H.264/HEVC/AV1 往返、非法偏好拒绝和现有消息解析回归通过，日志 `build/global-codec-v53-protocol.log`。
- 实际 GPU H.264 同屏双查看器通过，首位退出后另一个继续输出 GPU 纹理，采集/编码资源不重建；日志 `build/global-codec-v53-hardware.log`。
- 自动选择的 GPU 同屏双查看器通过，实际使用 Intel `mfx-gen (VDENC HEVC)`、1920×1080，各自解码为 GPU 纹理；首位退出后采集器和编码器创建数仍各为 1。订阅生命周期修复后重验日志 `build/global-codec-v53-lifetime-hardware.log`。
- `quic_stream_options`、`quic_weak_network` 均通过，日志 `build/global-codec-v53-hardware-net.log`（36.15 秒、28.63 秒）。订阅生命周期修复后重验 `quic_stream_options` 通过（35.86 秒），日志 `build/global-codec-v53-lifetime-final-tests.log`。参数测试明确保持当前格式的票来测量纯 FPS/画质变化，Auto 的选择由全局投票测试单独覆盖。
- `chast-host`、`chast-service`、`chast-quic`、`chast-viewer-probe` 及两个相关测试目标构建通过，最终日志 `build/global-codec-v53-lifetime-final-build.log`。保留已有的 LIBCMT 链接警告及 `normalized` 变量遮蔽警告；没有安装/重启服务或修改物理显示布局。

## 仍未完成的范围

1. 当前能力集合是 H.264、HEVC、AV1、VP9；软件回退为 VP9（2026-11-12 晚起，OpenH264 软件 H.264 已移除），既有创建/运行中故障兜底逻辑保留。RustDesk 的 VP8、软件 AV1 和 AV1 I444 路径未复刻。
2. 摄像头已并入全局协商，同设备共享采集编码，桌面加摄像头每连接一票，并支持 Camera-only 参数修改与运行中软件恢复。摄像头真实设备及反馈驱动自适应仍待完善，见 [摄像头共享视频](camera-shared-video-2026-11-08.md)。
3. v54/v55 已实现单连接 add/sub/set 多显示器独立流、逐屏光标和观看端解码/呈现。共享同一连接的原生多窗口仍未完成；合并屏仍是一幅拼接画面，见 [单连接多屏](independent-streams-rustdesk-2026-11-08.md)。
4. 双物理显示器/不同适配器的实际驱动组合、驱动重置和桌面切换期间的编码能力变化仍需实机验收；模拟双屏及本机 GPU 同屏不能代替这些环境。
5. 其他模块仍按完整功能审核继续，包括按连接 ID 本地管理、服务审批/远程提权、防休眠、主机录制、剪贴板方向/惰性文件、文件分页/空目录、键盘模式、打印及角色互换等。
