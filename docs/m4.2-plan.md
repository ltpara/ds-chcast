# M4.2 — 主机端隧道集成

状态：已完成（2026-10-22）
上一阶段：M4.1 已完成，查看者可经 `TunnelAgent` 使用设备 ID、打洞与中继。
下一阶段：M3.2b Windows 服务主机（锁屏/未登录场景）。

## 目标

让托盘主机自己完成 M4.0 的连接服务接入，用户不再手工启动 `chast-tunnel host`：

1. 托盘随包启动/停止 `chast-tunnel.exe host` 子进程，把本机注册到会合服务；
2. 在 `host.ini` 中持久化服务器地址/密钥、设备 ID/密钥、隧道监听地址和开关；
3. 托盘显示注册状态、分配到的中继地址和**查看者实际使用的路径**（直连/中继）；
4. Windows 构建同时产出 `chast-host.exe` 与 `chast-tunnel.exe`，防火墙规则覆盖主机 QUIC 端口和隧道 UDP 端口。

## 非目标（留给后续）

- Windows 服务（M3.2b）：锁屏、未登录、服务账户证书。
- 账号体系、设备 ACL、多用户共享。
- 跨网真机 NAT 演练：本机仍只有一张网卡，跨网锥形/对称 NAT 需要两台异网机器。
- 在 C++ 内重写代理：继续复用已验证的 Go 代理。

## 架构

```
chast-host.exe (Win32 托盘)
  ├─ HostServer              ── QUIC 监听 0.0.0.0:4433，采集成/编码/输入
  └─ TunnelProcess           ── spawn 同目录 chast-tunnel.exe host
        │  stdout JSON Lines: ready / viewer / relay
        │  stderr: 诊断日志 → 托盘日志窗
        ▼
  chast-tunnel host
        ├─ POST /v1/hosts        注册设备 ID、密钥摘要、证书指纹
        ├─ UDP keepalive         维持 NAT 映射，取得观察地址
        ├─ UDP relay_hello       绑定按主机分配的中继端口
        └─ 数据转发              viewer/relay ↔ 127.0.0.1:4433
```

关键决策：

- **子进程而不是把 Go 代理编译进 C++**：主机和查看者复用同一份 NAT 逻辑；托盘只负责生命周期、事件和展示。代理随 `chast-host.exe` 同目录分发，可用 `CHAST_TUNNEL` 环境变量覆盖路径（测试/排障）。
- **代理跟随“共享”生命周期**：HostServer 成功监听后才启动代理，停止共享时先停代理。这样服务端不会在主机不可用时仍报告在线。
- **主机侧路径由代理判定**：HostServer 看到的对端永远是代理的 loopback 地址，无法区分直连/中继。主机代理根据数据报来源是否等于分配到的中继端点，报告 `direct` 或 `relay`；托盘只在 HostServer 正在串流时显示该路径，避免会话结束后残留。
- **stdout 只输出机器事件**：`ready`（设备 ID、监听地址、会合/中继地址）、`viewer`（路径、远端地址）、`relay`（注册刷新后中继地址变化）。C++ 只解析扁平的字符串字段，不引入 JSON 库；stderr 仍走日志。
- **设备身份自动生成**：首次启动生成稳定的设备 ID（机器名规范化）和 16 字符设备密钥；用户可在“连接服务设置…”对话框中修改。设备密钥不上传，服务端只保存 SHA-256 摘要。
- **独立隧道端口**：主机 QUIC 继续监听 `port`（默认 4433），代理使用 `tunnel_listen`（默认 `0.0.0.0:14434`）。两个 UDP 端口都加入防火墙规则；中继路径只依赖出站连接，直连路径需要该端口可达。
- **证书指纹随注册上传**：代理从 HostServer 的持久身份取 SHA-256 指纹，服务端查询结果因此能直接给出 pin，查看者首次连接无需人工抄指纹。

## 验证计划

1. **单元**：
   - Go：主机代理初始 `ready` 信息；直连/中继数据报被分别报告；迟到/切换不重复报告。
   - C++：设置文件新字段往返与非法值回退；URL/设备 ID/密钥/监听地址校验；JSON 行解析与参数引用。
2. **构建**：`ctest -C Release` 全部通过；Release 目录中 `chast-host.exe` 与 `chast-tunnel.exe` 并存。
3. **真实回环**：`chast-server` + 带隧道配置的 `chast-host --tray`；查询 `/v1/hosts/{id}` 得到在线、候选、中继与指纹；查看者经服务分别强制直连/中继，`chast-quic connect` 断言帧数、CRC、摘要。
4. **UI/状态**：用 Win32 `EnumChildWindows` 读取托盘标签，确认“已在线”、中继地址，以及串流时的“最近路径：直连/中继”；设置对话框的鼠标路径受环境限制，逻辑由设置/参数测试覆盖。
5. **清理**：退出托盘后子进程消失；服务端注册在过期后下线。

## 验证结果（2026-10-22，单机回环）

- **单元**：
  - `go vet ./...`、`go test ./...` 全部通过；新增主机代理用例覆盖初始 `ready`、直连/中继数据报分类、路径切换只报告一次、`relay` 地址刷新。
  - `ctest --test-dir build -C Release` 5/5 通过（cursor、protocol、host_settings、host_tunnel、quic_loopback）。`host_tunnel` 覆盖 JSON 字段转义（含 `\u4e2d\u6587`）、三类事件、同目录/`CHAST_TUNNEL` 可执行文件查找、命令行引用、设置校验、子进程事件/退出码/停止超时。
- **构建**：Release 目录中 `chast-host.exe` 与 `chast-tunnel.exe` 并存；CMake 目标 `chast_tunnel_binary` 每次构建增量调用 `go build`。
- **注册**：托盘用 `build/m42/host.ini` 启动，日志出现“正在注册设备”；`GET /v1/hosts/m42-host` 返回 `online=true`、`candidate=127.0.0.1:16434`、`relay=127.0.0.1:41100`、`punch=127.0.0.1:18444`、`fingerprint=C2F256…6421`；托盘显示“连接服务：已在线 · 中继 127.0.0.1:41100 · 设备 ID m42-host”。
- **直连**：查看者代理 `--mode direct` 报告 `path=direct, remote=127.0.0.1:24434`；`chast-quic connect` 得到 `received=603 decoded=603 keyframes=1 crc-errors=0 decode-errors=0 gaps=0 digest=610B8EF3346AD47C elapsed=24053`。会话中托盘“最近路径：直连 · 127.0.0.1:24434”，同期中继计数为 0。
- **中继**：`--mode relay` 报告 `path=relay, remote=127.0.0.1:41100`；`received=603 decoded=603 keyframes=1 crc-errors=0 decode-errors=0 gaps=1 digest=659B01211DD715C6 elapsed=24009`。首帧序号为 1708（查看者中途加入已在运行的编码流），接收端因此记一次 gap，其余 603 帧连续。会话中托盘“最近路径：经中继 · 127.0.0.1:41100”；`/v1/stats` 的 41100 端口为 `to_host_bytes:35677, to_viewer_bytes:10594896, dropped:0`。
- **UI**：以 `WM_COMMAND` 驱动托盘菜单、`GetDlgItem` 读取标签：串流中“状态：正在共享”“画面：… 1920×1080 · H.264 · 30 fps”“连接服务：已在线 …”“最近路径：经中继…”，查看者离开后路径回到“—”。设置对话框的物理鼠标路径未演练，字段逻辑由设置/参数单测覆盖。
- **防火墙**：`chast-host.exe --firewall 46333 16434` 返回 0；`netsh advfirewall firewall show rule name="chast host"/"chast tunnel" verbose` 显示两条入站 UDP 允许规则，端口 46333/16434，程序分别为 `chast-host.exe`/`chast-tunnel.exe`，域/专用/公用全开。验证后删除这两条测试规则。
- **清理**：`WM_COMMAND 1020` 退出托盘后 `chast-host` 与 `chast-tunnel` 进程均消失；服务端在 TTL 内仍返回 `online=true, expires_in_ms≈26s`，约 50 s 后返回 `{"error":"host is not registered"}`。
- **限制**：单机单网卡，直连仍走回环，跨网锥形 NAT/对称 NAT 未演练；中继字节包含 QUIC 握手与重传，不能与裸帧大小直接比较；中继会话的 `gaps=1` 是中途加入的序号起点，不是丢帧。
