# 多人独立选屏：实现与 RustDesk 对照

本次针对 F05（多人独立选屏）。参考本地 `D:/rustdesk-ref`，提交 `7423dced37845c48093b6f71bd82e4a16cc8c79d`。没有以当前 RustDesk 发行版替代这份源码基线。

## 对齐结果

| 行为 | 本地 RustDesk | 本次实现 |
| --- | --- | --- |
| 每个连接选择显示器 | `Connection::capture_displays` 调整该连接的订阅 | Hello 和会话内切屏只选择当前连接的订阅 |
| 同屏复用 | 按显示器命名的视频服务 | `DesktopStreamPool` 按设备名及适配器 LUID 共享采集器、GPU 编码器 |
| 不同屏同时观看 | 订阅不同视频服务 | 不同显示器各自拥有管线，不再共享全局发布者画面 |
| 首位观看者切屏或离开 | 不改变其他连接订阅 | 仍有人使用的源与编码器继续存在，不接管、不重建；最后退订释放 |
| 静态画面的新订阅者 | snapshot / 关键帧 | 请求共享 IDR，缓存有效 GPU 图像；重建后清除旧图像与队列 |
| 无效选屏 | 无效索引不清除已有订阅 | 无效、无法采集或初始化失败返回结果，原订阅继续工作 |
| 只读连接选屏 | 视频订阅独立于键鼠控制 | 主机、QUIC、原生查看器、Flutter 均允许只读连接选屏；物理显示模式仍检查输入权限 |
| 系统声音 | 独立音频服务 | `SharedLoopback` 共享音源，每连接独立队列和授权，选屏不重开音源 |
| 视频服务驱动 | 服务拥有独立运行线程 | 每屏独立线程持有采集器和编码器，观看者暂停读取也继续生产；GPU 管线的创建、使用、重建和销毁均在服务线程 |
| 解码兼容性 | 按所有连接上报能力取交集，并统计有效偏好 | v50 增加 GPU 解码能力；v53 扩为全部桌面连接的交集和多数票，切屏保留该连接的能力和偏好；无可用票时 HEVC → H.264 → AV1 |

## 生命周期与失败处理

每个连接始终运行自己的主机会话循环。切屏在该循环内准备目标订阅，成功后交换视频订阅；不退出文件传输、终端、摄像头、端口转发、剪贴板或输入租约作用域。系统音频的生命周期独立于所选显示器。

v53 的全局编码协商按每个连接的实际存活订阅记录显示源。切屏准备或隐私屏探测期间，原屏和目标屏都参与协商，每个连接仍只投一票。若后续步骤失败或仅做探测，目标订阅销毁会撤销其关联并重新协商，原屏无需重新注册即可恢复；不会留下失效目标屏的编码限制。

每块屏幕的专用线程串行操作采集、编码与重建，并在创建、重建时附着当前输入桌面；连接线程通过命令队列请求操作、读取压缩帧，网络发送在连接线程中进行，不持有服务锁。每个订阅的压缩视频队列最多缓存 60 个画面/约 8 MiB（单个超大关键帧允许超过字节阈值）；溢出后清除该订阅的旧引用帧并等待 IDR。慢连接不要求其他连接等待它发送成功。帧头保留服务产生图像时的采集时间，不能把排队后的发送时间伪装为采集时间。

队列保存压缩帧及受引用计数保护的图像元数据；实际编码只由共享服务执行，连接适配器不访问 GPU 像素。重建使用代次，旧代次的连接缓存不能再次编码或发送。保留现有 GPU 采集、NV12 转换及硬件编码路径，没有增加 CPU 回退。

v53 在视频准入完成前，通过串行的全局协商事务汇总全部桌面连接的解码能力及偏好；每块活动显示源都验证候选编码器能产出关键帧后才提交。没有共同格式、硬件回退格式不受支持、候选编码失败或没有关键帧时，已有管线继续工作。限制能力的观看者离开后重新协商；同一观看者切到另一屏仍保留其解码能力约束。查看器同时检查 FFmpeg 的 D3D11VA 支持与显示 GPU 的 NV12 解码配置。

协议从 v49 升至 **v50**：Hello 末尾增加解码能力位。主机与查看器必须同时升级；原有版本检查会拒绝旧版对端。此处对齐功能行为，不与 RustDesk 线协议互通。

后续多人 QoS 引入 v51 双向探测和 v52 视频取帧确认；v53 的 Hello 新增全局编码偏好。v54 视频头新增独立流 ID，并加入多屏订阅控制消息和生产主机多屏调度；**当前版本为 v55**，已补齐逐屏光标、观看端多路解码与 Flutter 独立画面，主机和查看器需要同时更新。最新拓扑恢复和剩余范围见 [单连接多屏进度](D:/ds-chcast/docs/independent-streams-rustdesk-2026-11-08.md)。以上 v50 描述记录解码能力字段引入时的版本。

## 验证

- `host_parity`：12 个场景，包含已有静态关键帧、权限、音频与桌面恢复回归，以及多人独立选屏、切屏失败、并发准入、不同加入顺序的能力协商和跨屏能力迁移。使用模拟媒体及真实 QUIC；双屏分别为 640×480 和 800×480，核对描述、原点、压缩载荷和资源创建/销毁计数。
- 选屏测试覆盖 A/B 异屏、第三人同屏、首位观看者切屏/退出、只读选屏、物理模式拒绝、最后退订释放、目标不可用后重试。文件在切屏前发送一半，切屏后完成，校验摘要及实际落盘内容。
- 四连接并发加入、显示器列表交换编号后新加入，验证按稳定设备身份复用。
- `desktop_stream`：共享编码不重复执行、所有观看者停读期间仍继续生产、GPU 管线在专用线程创建/使用/销毁、慢订阅溢出后以 IDR 恢复、重建不回放旧画面、最后订阅释放；新增无共同格式、硬件回退不兼容、候选编码失败及无 IDR 的准入回退测试。
- `protocol`、`protocol_fuzz`：v50 能力位往返、零值/未知位拒绝及非桌面会话零能力合法；解析器模糊回归通过。
- `quic_stream_options`：真实硬件编码格式/参数切换回归。
- 显式 `chast-host-parity-test --hardware`：本机 1920×1080、Intel `mfx-gen (VDENC AVC)`，两查看器分别创建 D3D11 设备并上报探测能力，各自直接解码到 GPU；首位退出后剩余查看器继续解码，采集器和编码器创建数均保持 1。每次解码断言无 CPU 图片输出。此模式不注入真实输入，不修改显示布局、锁屏或登录状态。
- 上一轮单连接硬件 QUIC 回环：54 个访问单元全部解码，离线重放帧数和内容摘要一致；本轮使用上述双查看器 GPU 测试验证新增协商路径。
- 产品构建：`chast-host`、`chast-service`、`chast-quic`、`chast-viewer-probe` 编译成功。保留现有链接库警告，未启动或安装服务。
- 上一轮 Flutter：`dart analyze lib/pages/session_page.dart` 无问题；`session_start_polling_test.dart` 通过。本轮未再改 Dart；原生查看器重新编译目标为 `chast-viewer-probe`。

## 尚未等同的部分

1. v54 已加入单连接多流的标识、独立描述和 add/sub/set 控制消息，生产主机会话已支持多个视频订阅；v55 已接入逐屏光标发送与传输，观看界面的多路解码、纹理及光标呈现仍待完成，合并桌面仍是单幅拼接画面。单连接多屏完整功能尚未完成，见 [接入进度](D:/ds-chcast/docs/independent-streams-rustdesk-2026-11-08.md)。
2. v53 已实现全部桌面连接的能力交集、有效偏好多数票和 Auto 顺序，见 [全局编码协商](D:/ds-chcast/docs/global-codec-rustdesk-2026-11-08.md)。RustDesk 同票使用无稳定顺序的 HashMap 遍历，本项目按最早连接打破同票。I444、VP8/VP9、CPU 回退及摄像头流并入该策略仍未复刻。
3. 后续已接入全局多人 FPS/画质聚合、主机探测及 v52 视频取帧反馈，移除了每连接独立改码率和重复按 FPS 等待的桌面路径，见 [共享质量控制对照](D:/ds-chcast/docs/shared-video-qos-rustdesk-2026-11-08.md)。已验证慢连接停读期间切屏、另一屏继续发送和恢复 IDR。各连接有限窗口与 RustDesk 每屏同步等待的调度方式有区别，硬件拒绝设置后的恢复及其他流极端拥塞仍需继续验证，不能据此声称全部网络行为一致。
4. 双屏差异使用确定性模拟屏幕验证；真实 GPU 验证的是本机同屏双连接，未将其描述为两台异地设备、真实双屏热插拔或弱网 A/B 验收。隐私拓扑、驱动故障和系统桌面切换仍需相应实机验收。
