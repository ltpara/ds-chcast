# M4.1 — 设备地址簿与内置隧道代理

状态：已完成（2026-10-22）
上一阶段：M4.0 Go 会合/中继服务与 `chast-tunnel` 已完成并通过真实 chast 回环验证。
下一阶段：M4.2 主机端自动注册/内置 host agent（托盘主机不再需要手工启动 `chast-tunnel host`）。

## 目标

让 Flutter 查看者不再只能手输 `host:port`：

1. 用**设备 ID** 通过 M4.0 服务找到主机，直连失败自动走中继；
2. 首页维护**我的设备**地址簿，并让**最近连接**复用同一套连接流程；
3. 替换首页侧栏“身份与中继将在后续接入”的占位文案，显示连接服务、路径策略和已固定身份数量；
4. 将 Go 的 `chast-tunnel viewer` 作为客户端内置代理随应用构建、由会话页托管生命周期，用户无需手工开两个终端。

## 非目标（留给后续）

- 托盘主机自动注册/内置 `chast-tunnel host`（M4.2）。本阶段验证时仍手工启动主机代理。
- 服务端账号、多用户、设备共享和 ACL。设备地址簿保存在本机。
- 在 C++/Dart 内重写打洞逻辑。继续复用已验证的 Go 代理，减少协议分叉。
- 地址簿云同步。

## 架构

```
Flutter HomePage
  ├─ ServerSettingsStore  ── server URL + 路径策略(auto/direct/relay)
  ├─ DeviceStore          ── 我的设备 + 最近连接（同一 JSON，saved 标记区分）
  └─ ServerApi            ── GET /v1/hosts/{id} 在线/候选/中继/指纹
        │
        ▼
SessionPage
  ├─ TunnelAgent(Dart)    ── spawn chast-tunnel.exe viewer --listen 127.0.0.1:0
  │     └─ 解析 stdout JSON: ready / path 事件
  ├─ ViewerBridge         ── 连接 127.0.0.1:<agent port>（直连设备仍连原地址）
  └─ TrustStore           ── 按逻辑身份 pin：server:<url>/<id> 或 host:port
```

关键决策：

- **代理进程而不是重写打洞**：M4.0 的 Go 代理已有单元测试和真实 chast 验证；Flutter 只负责启动、读取事件和停止。代理监听 `127.0.0.1:0`，实际端口由 ready 事件返回，避免端口冲突。
- **逻辑身份做 pin**：经代理时 ViewerEngine 看到的是 `127.0.0.1:<随机端口>`，若按本地地址存指纹，每次会话都会丢 pin。`ConnectTarget.trustKey` 对服务设备使用 `server:<url>/<id>`，直连仍用 `host:port`。
- **设备与最近连接同一存储**：`DeviceStore` 里每条记录带 `saved`。首页“我的设备”显示 `saved=true`，“最近连接”显示未保存的临时连接；保存操作把临时记录转为设备，清空最近连接只删除未保存项。
- **主机 ID 与地址共用输入框**：包含 `:` 或以 `[` 开头按 `host:port` 解析；否则按设备 ID 解析并要求已配置服务。保留原有直连路径，不破坏命令行/局域网用法。
- **路径策略是全局默认**：`auto` 为默认；`direct`/`relay` 用于排障和分路径验证。设备本身不存策略，避免每台设备重复配置。
- **stdout 只放机器事件，诊断走 stderr**：`chast-tunnel viewer` 每行输出一个 JSON 对象，嵌入方不必解析人类可读日志。`ready` 带本地监听地址和初始路径，`path` 在直连/中继切换时输出，用于会话浮层显示当前路径。
- **本地 QUIC 客户端可重新绑定**：查看者重连时源端口会变，代理改为让最新的 loopback 来源接管客户端身份，而不是忽略“第二个客户端”，否则会话页复用代理时的第二次连接发不出去。

### 真实 chast 端到端（单机回环）

拓扑：`chast-server` + `chast-tunnel host` + `chast-quic serve`，Dart `TunnelAgent.start()` 启动 viewer 代理，`chast-quic connect 127.0.0.1:<agent port>` 作为查看者。服务端使用 `--server-key dev-secret`，主机 `--id devbox --key host-secret`，令牌 `--token auto --token-reuse`；查看者 pin 从 serve 日志解析的真实身份指纹。临时脚本位于 `build/m4.1/`（已由 `.gitignore` 排除，不提交）。

- **直连**（`mode=direct`）：`received=201 decoded=201 keyframes=1 crc-errors=0 decode-errors=0 gaps=0`，`digest=A188ABD0B85F082B`，`agent path after session: direct`，connect 退出码 0；同一时刻 `/v1/stats` 的中继计数为 `to_host_bytes:0,to_viewer_bytes:0`，证明数据未经过服务器。
- **中继**（`mode=relay`）：`received=202 decoded=202 keyframes=1 crc-errors=0 decode-errors=0 gaps=0`，`digest=E092051892076F56`，`agent path after session: relay`，connect 退出码 0；中继统计 `to_host_bytes:18054,to_viewer_bytes:2575942`，viewer 为 `127.0.0.1:57254`（查看者代理的映射地址）。

### 环境限制

- 本机只有一张网卡、无真实 NAT，直连路径走回环地址，未验证跨网锥形 NAT 打洞；对称 NAT 下 `auto` 的失败回退由 Go 单元测试覆盖，跨网真机仍需两台异网机器手动复核。
- 单显示器且无法合成物理键鼠事件，地址簿的鼠标点击路径由 widget 测试与 `WM_COMMAND`/等价调用验证，未做物理点击。
- M4.1 仍要求手工启动 `chast-tunnel host`；主机端自动注册与内置代理留给 M4.2。
