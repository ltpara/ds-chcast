# M9.3 — 多显示器合并视图

更新时间：2026-10-24
分支：`feat/m7-security`
基线：M9.2 完成（协议 v22；多文件/文件夹传输）。
本阶段将协议升到 v23。
参考：`D:\rustdesk` @ `c7f212d`（只做能力对照，不复制实现）

## 1. 范围与取舍

M9.2 之后，查看器一次只能看到一块屏：显示器菜单切换的是主机的采集目标，
其他屏幕完全不可见。M9.3 增加一种新的选择——“全部显示器（合并）”：主机把
所有输出按虚拟桌面布局拼成一张画布，编码成单条视频流。

| 能力 | 行为 |
| --- | --- |
| 合并选择 | Hello 的 `display` 可传 `kDisplayAll = 0xFFFE`，也可在会话内切到/切出合并 |
| 画布 | 所有显示器 `rect` 的并集；未覆盖区域填黑；随显示器热插拔重建 |
| 更新 | 只有产生新帧的显示器区域重新拷贝；整帧 NV12 转换与编码保持一条流水线 |
| 坐标 | 指针/输入仍用虚拟桌面绝对坐标；合并原点即并集左上角，协议不变 |
| 光标 | 系统光标按并集原点映射；形状取指针所在显示器的那一份 |
| 缩放 | 并集超过 4096 长边或 4096×2304 面积时自动等比缩小，自适应分辨率在有效比例上继续工作 |

不做的部分：

- **不做每屏一条流。** 合并视图是一条编码流，查看器不做多路解码与本地拼贴；
  每屏独立流留给以后有带宽/选择性需求时再评估。
- **不做混合适配器合成。** 所有子采集必须落在同一块 D3D11 设备上，不同显卡
  上的输出无法无拷贝合成；遇到时明确拒绝合并，而不是退回 CPU 拷贝。
- **不在合并下切单屏分辨率。** 合并画布由显示器布局决定，模式切换只对单屏
  选择开放；查看器在合并状态下不显示分辨率菜单。
- **不做 DPI 虚拟化。** 使用 DXGI 的物理像素虚拟桌面坐标；跨不同缩放比例的
  屏幕时，画面按物理像素拼接，与 Windows 的“扩展”桌面一致。
- **不做跨显示器的窗口裁剪。** 画布是显示器矩形的并集，位于屏幕间隙的窗口
  本来就不出现在桌面复制里；间隙填黑。
- **不持久化合并选择。** 设置文件仍只保存 auto 或具体显示器索引，避免主机
  在显示器数量变化后启动成一个意外的合并流。

关键语义：

1. **合并是显式选择。** `kDisplayAll` 与 `kDisplayAuto` 分开：auto 仍由主机
   选一块屏；只有明确请求合并才产生合并流。HelloAck 用 `merged` 标志告诉
   查看器当前是合并布局，`displays` 列出的是参与合成的输出。
2. **并集几何即协议几何。** `origin_x/origin_y` 是并集左上角，
   `source_width/source_height` 是并集尺寸（偶数对齐），`width/height` 是编码
   尺寸（可能被自适应分辨率缩小）。查看器现有的坐标映射无需新字段。
3. **成员判定。** 单屏条目的判定仍是“rect 起点等于原点且尺寸等于 source”；
   合并流没有单屏条目，查看器以 `merged` 标志决定菜单高亮和模式菜单的可用性。
4. **切换即重建。** 进入/离开合并、成员数量变化都会重建采集器和编码器，
   与现有 SwitchDisplay 的重建路径一致；切换成功后才发布新的 StreamInfo。
5. **失败要可解释。** 没有输出、跨适配器、画布超限（>16384）或合成器创建
   失败时，SwitchDisplay 返回 Failed 并带原因；Hello 时则回退到主机的默认
   单屏选择，`merged` 为假。

## 2. 协议 v23

版本从 22 升到 23，ALPN 保持 `chast/1`。载荷布局不变，只新增语义：

- Hello 的 `display` 接受 `kDisplayAll = 0xFFFE`；仍拒绝 ≥ `kMaxDisplayCount`
  且不等于两个哨兵值的索引。
- HelloAck/StreamInfo 的 flags 新增 `kServerInfoMergedLayout = 0x0040`。
  它描述流的布局，不属于权限位；权限掩码的相等校验改用
  `kServerInfoPermissionFlags`（原有的六个权限位），未知位校验仍用
  `kServerInfoKnownFlags`。
- `ServerInfo` 增加 `bool merged`，由 flag 解码，不是新的线上字段。
- 合并流的校验：`displays` 非空；每个显示器矩形都落在并集内；并集恰好等于
  `(origin_x, origin_y, source_width, source_height)`。并集尺寸向上取偶，
  因此允许 source 比严格并集大 1 像素（宽或高各自）。
- 单屏流的既有校验不变；查看器把 `merged` 与显示器列表一起用于 UI 状态。

## 3. 主机合成器

新增 `chast::create_merged_capturer(displays, config, error)`，返回与
`IDxgiCapturer` 相同的接口，由主机当作普通采集器使用。

**设备与子采集**

1. 选第一块显示器的适配器创建 D3D11 设备（BGRA 支持），所有子采集器通过
   新的内部工厂附着到这块设备和同一个 immediate context 上。
2. `DxgiCapturer` 增加外部设备模式：不拥有设备、不重复创建；`reinitialize`
   只重建 duplication，不重置共享设备。子采集器关闭 NV12（画布统一转换）并
   保持光标采集关闭（光标由合成器统一处理）。
3. 任一块显示器与第一块不在同一 LUID 时返回 Unsupported，错误文本列出冲突
   的显示器；子采集失败时销毁已建部分并返回原错误。

**画布与更新**

1. 画布是并集尺寸的 BGRA8 纹理（`SHADER_RESOURCE | RENDER_TARGET`，
   `MISC_SHARED`），首次创建或布局变化时清黑。
2. 每个子采集器记录自己的偏移 `rect.left - union.left`。某块产生新帧时，
   用 `CopySubresourceRegion` 把整帧拷到画布对应位置：同一设备同一 context，
   顺序天然一致，不需要 keyed mutex 或 fence。
3. 帧调度：先以 0 超时轮询所有子采集器；任一有帧就合成并返回。都没有时
   阻塞第一个子采集器剩余超时，避免空转，其他屏幕最多晚一个帧间隔。
4. 子采集器报告 `ReinitNeeded`（分辨率/旋转/桌面变化）时，合成器重建该子
   采集器并按新布局重算画布；任一块 `FatalError` 则整体上报，由主机重建。
5. 合成器自己创建 NV12 pass，在画布上做一次转换；目标尺寸受
   `kMergedMaxLongSide = 4096` 与 `kMergedMaxArea = 4096*2304` 限制，
   自动取最大整数百分比（不低于 1%）。`set_nv12_scale` 的请求值再与自动
   比例取较小者，`nv12_scale_percent()` 返回实际生效值。
6. 光标：`GetCursorInfo`/`GetCursorPos` 给出系统光标位置与可见性，
   映射到并集坐标；形状取包含该点的子采集器的解码结果（按 content id 缓存）。
   指针落在屏幕间隙或并集外时不上报光标。

## 4. 主机会话

- **Hello/默认选择**：`SelectDisplays` 识别 `kDisplayAll`；合并请求失败时
  回退到配置的默认单屏（记录警告），保证会话仍可建立。`HostStatus` 增加
  `display_merged`，`display_index` 在合并时保留为 0，`display_name` 为
  “全部显示器”。
- **描述流**：`describe_stream` 接受采集器状态；合并时 origin/source 用画布
  几何，`displays` 列出全部成员，flag 置位。`ServerInfo::merged` 同步。
- **切换**：SwitchDisplay 接受 `kDisplayAll`；已是合并且成员数量未变时视为
  空操作；成员变化（热插拔）触发重建。单屏 ↔ 合并走同一条重建路径，
  切换期间沿用 Busy 冷却。
- **模式**：合并流上 `RequestDisplayModes`/`SetDisplayMode` 返回
  `DisplayModeCode::Failed`，原因“合并视图不支持单屏模式”；查看器 UI 也会
  隐藏入口。
- **自适应分辨率**：主机保存“请求比例”，决策下发时与自动比例比较；应用到
  采集器后把 `stats.resolution_percent` 更新为实际生效值，避免每秒重复决策。
  编码器重建仍按实际 NV12 尺寸触发。
- **日志/状态**：会话启动日志写明合并成员与画布尺寸；`GetHostStatus` 能看到
  `display_merged` 与成员数量。

## 5. 查看器 UI 与 bridge

- `ViewerStatus` 增加 `merged_layout`；bridge 的 status map 增加
  `mergedLayout`；Start/SwitchDisplay 的参数校验接受 `kDisplayAll`。
- Dart `ViewerStatus` 增加 `mergedLayout`；`kViewerDisplayAll = 0xFFFE`；
  `streamedDisplayIndex` 在合并流时为 null。
- 显示器菜单在“服务端默认”之后增加“全部显示器（合并）”，副标题显示并集
  尺寸与成员数量；合并流时该条目高亮，单屏条目不误高亮。
- 合并流的工具栏隐藏分辨率按钮（`modeChangeAvailable` 增加
  `!mergedLayout`）；快捷键/程序化调用也由主机拒绝。
- 从合并切到具体屏、从具体屏切到合并都走现有 `_switchDisplay`：会话活跃且
  可输入时先发 SwitchDisplay，失败再重连；否则直接带新选择重连。

## 6. 验证

自动化：

- `protocol_test`：v23 未知 flag 位改为 0x80；合并 HelloAck 往返（flag、
  union 原点/尺寸、成员列表）；`kDisplayAll` 在 Hello 中接受；合并流并集
  不匹配、几何越界、空成员列表被拒绝；权限掩码与新 flag 并存不误判。
- `capture_test`（现有 GPU 冒烟）：合并采集器在单屏上输出画布尺寸、
  `merged() == true`、缩放封顶生效。
- `verify --merged`：接收端 Hello 请求 `kDisplayAll`；断言 HelloAck 的
  `merged`、union 几何、所有显示器落在并集内；切到 `kDisplayAll` 为空操作；
  越界索引仍被拒绝；与 `--display-mode` 互斥。
- Flutter：状态解析 `mergedLayout`；显示器菜单包含合并条目并在合并流时
  高亮；合并时分辨率按钮不可用。

手工（本机单屏可做）：

- 单屏机器选择“全部显示器（合并）”，画面应与单屏一致，工具栏无分辨率按钮。
- 合并 ↔ 单屏切换 3 次，会话不中断、坐标正确。
- 多屏机器（需人工）：横竖屏混合、不同分辨率、负坐标布局，确认拼接位置、
  指针映射、光标形状与热插拔重建。
