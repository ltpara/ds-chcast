# 主机自动录屏（2026-11-09）

本轮将主机端留档接入共享视频服务。对照仍使用本地 RustDesk `7423dced37845c48093b6f71bd82e4a16cc8c79d` 的 `src/server/video_service.rs` 中 `record_incoming` / `get_recorder` 路径。这里记录实现和实际验收边界，不表示其他发射端模块已经全部对齐。

## 使用方式

原生主机或服务机器设置的 **安全设置 → 主机录屏** 页新增自动录屏开关和目录选择。默认关闭；启用时必须选择绝对路径，服务账户需要有写入权限。

配置文件对应：

```ini
record_incoming=1
record_directory=D:\HostRecordings
```

这两个字段只通过本地设置修改，与原有 `record=` / `allow_record` 的查看者录制许可相互独立。机器设置使用已有并发合并和保存/重启流程；错误的布尔值或启用时缺少绝对目录会报告问题并保持关闭，保存时拒绝换行和 NUL 字符。

录像目录下，每个视频源使用包含时间、进程号、序号和源标识的独立目录，文件为 `part-0001.mp4` 等。独立目录通过原子创建预留，重连不会覆盖旧文件。目录创建、开始、完成、积压丢帧和写入失败通过主机现有日志上报。当前不自动删除旧录像。

## 实现

- `src/host/stream_recorder.{h,cc}`：每个源一个异步写盘线程。队列最多 120 个画面、32 MiB 压缩数据；不保留 GPU 纹理、不额外编码。工作线程另有正在写入的画面及封装缓冲，32 MiB 是排队上限，不是总内存上限。
- `src/host/desktop_stream.{h,cc}`：在共享源发布压缩画面时提交一次录像，同屏多人观看不会重复保存。源的编码器每次替换都会改变录像代次，即使格式、尺寸相同也会分段。
- `src/host/host_server.cc`：桌面、合并桌面、桌面附带摄像头和 Camera-only 都传入本地录像策略。最后一个源订阅释放后，排空已接收的队列并写完文件尾。
- 积压时丢弃排队画面，等待新的 IDR 后另起一段，不把丢失参考帧后的 P 帧接进旧片段。写入失败停止这个源的录像并记录错误，远程视频仍可继续。
- 正常情况下每 10 分钟请求关键帧并分段；编码器重建、格式或尺寸变化也分段。录像时间使用源的时间戳，结尾保留最后一张静止画面直到源结束。
- `tools/mp4_recorder.h`：沿用 H.264/HEVC 封装，新增 AV1 OBU 处理。只解析 OBU 边界并提取序列头，由当前 FFmpeg 的 MP4 muxer 构造 av1C；AV1 样本不经过 NAL 长度转换。对照本机 FFmpeg 8.1.1 的 `libavformat/av1.c` 和 `movenc.c`。
- 封装器保留一个待写样本以确定持续时间，并检查写文件尾、刷新和关闭错误。查看端停止录制时同步最终计数和收尾错误，避免遗漏最后一个样本。
- 真实验收发现共享编码协商的候选错误会残留到成功路径，导致 OpenH264 回退后的正常会话结束被误报失败。本轮清理成功路径的错误，并在现有共享流回归中加入断言。

这次没有新增 CMake 测试目标，也没有新增协议字段。

## 范围

目前只留存视频，不含系统声音或麦克风；单独传输给查看器合成的光标、聊天和其他 UI 叠层不写入视频。只录制正在被订阅的视频源，不是后台全天候桌面监控。

H.264 通过真实本机链路验收；AV1 通过真实编码的固定样本和容器读回验收，未覆盖 AV1 硬件编码器与跨网络。摄像头和 SYSTEM 服务账户的实际目录写入、多物理显示器、强制终止/磁盘拔出仍需设备验收。普通 MP4 的最后一段依赖正常收尾；进程被强杀或断电可能损坏正在写的片段，已关闭的片段保留。积压丢帧期间保留最后一张已记录画面，日志标明丢帧数量。
