## 实施约束

- Windows 优先，之后推进 Linux/macOS/移动端。
- 视频采集、处理、编码、解码、呈现保留 GPU 路径。没有新增 CPU/GDI 采集或软件编解码 fallback。
- 硬件不支持时报告失败；额外编码与色度格式也必须符合 GPU 零拷贝要求。
- 对齐本地源码可证实的功能与使用流程；不默认要求 RustDesk 协议互通或 Pro 服务端能力。

仍需硬件验证。多个桌面查看者同时连接时，隐私遮罩/本地键鼠屏蔽这类全局操作会被拒绝，

多终端标签不等于断线保活。当前仍在断连或撤权时结束 shell；可选的保活、恢复身份绑定与有限输出回放尚未实现。

## 协议和配置兼容

- 当前协议版本为 **42**，主机与查看器应配套更新；旧版本会被现有版本检查拒绝。
- v40 新增 `SetLockAfterSession = 56`、`LockAfterSessionState = 57`，使用现有输入权限；不添加新的授权位。
- 新消息：`SetBlockInput = 54`、`BlockInputState = 55`。
- 新权限及 HelloAck 标志：`0x4000`，`kPermissionBlockInput`；启用同时需要 `kPermissionInput`。
- `BlockInputState` 包含实际启用状态、结果码和原因。解除失败时允许返回失败且 `enabled=true`，避免界面误报已恢复。
- 主机配置 `block_input=0/1`，缺省为 `0`；升级旧配置不会自动授权屏蔽本地输入。
- 多终端使用已有 `TerminalRequest/Result/Resize/Stop` 和 CTTY 流，不增加视频路径或新监听端口。
- v39 的 `InputKind::Gesture=3` 使用原有 16 字节输入载荷；Pan/Zoom 的滚动增量限制为 ±1200，禁止按钮/HID 混入，未知操作和多余字节被拒绝。
- 主机侧复用封装 `CHASTM1\n` + 大端 64 位会话 ID + 原 QUIC 数据；能力位加入签名。查看者仍发送原 QUIC 数据，新的 agent/relay 应配套部署。
