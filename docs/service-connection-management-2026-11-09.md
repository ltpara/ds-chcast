# Windows 服务连接管理与本地审批

日期：2026-11-09。接续 [按连接 ID 管理](connection-management-2026-11-09.md)，实现托盘与服务工作进程之间的本地管理通道。

后续更新：公开服务身份展示及管理员机器设置编辑已完成，见 [服务机器设置](service-machine-settings-2026-11-09.md)。本文末尾“机器设置编辑仍待开发”为该阶段的历史边界；本地协议现为版本 2，增加公开身份和认证状态。

## 可用行为

当主机服务正在运行，普通启动或 `--tray` 启动的 `chast-host.exe` 进入服务连接管理界面。它不再因服务占用监听端口而退出。用户可以查看本 Windows 会话工作进程的连接，选择目标聊天、发送文件、修改权限、断开；退出管理器不会停止服务。

连接窗口与便携/普通托盘主机复用同一套控件。新连接、来信、工作进程重启都不会把旧选择悄悄转向其他人。管道 I/O 与命令在后台线程执行；界面成功提示表示操作已排队，服务拒绝或通信失败会产生结果通知。连接中断时清空可操作快照、取消待发操作，不自动重试可能已经执行过的动作。

服务读取机器设置中的 `auth_mode`：

- `password` 仍要求永久密码，未设置时拒绝连接。
- `click` 由本地管理器显示请求、来源、设备、会话类型和十五项权限；允许时可缩小授权，关闭窗口即拒绝。
- `both` 保留永久密码认证；没有提供密码时转本地审批，错误密码不会转审批绕过。
- 服务始终不生成临时密码。审批通道未启动、管理器离线、请求过期或查看者离开时拒绝，不降级为自动允许。

审批等待最长 60 秒，管理器心跳过期约 3 秒就取消尚未完成的审批。已经结束的请求不能再次批准；传输层继续检查原始权限上限和连接存活。

## 身份和生命周期

工作进程在当前 Windows 会话创建消息模式命名管道，拒绝远程管道客户端，只允许 SYSTEM 和当前交互登录的 logon SID 访问。该登录 SID 的权限不含创建另一管道实例、改 DACL 或改所有者；创建首个实例失败时不会接管已有端点。

客户端在发送可被模拟的请求前，检查服务端会话、管道的 SYSTEM 所有者，以及 ACL 中其他主体不能创建服务端实例或替换访问控制。这里不依赖普通用户读取 SYSTEM 进程令牌。服务端读到请求后模拟调用方，检查其 Windows 会话与 logon SID，再复制受控用户令牌用于文件操作。

每次工作进程/端点启动生成新的 128 位随机实例标识。所有修改操作携带该标识和目标 ID，服务拒绝旧实例请求。客户端为 `(实例标识, 连接 ID)` 分配不复用的界面 ID；即使重启后远端数值相同，旧窗口也保持已断开状态。审批请求有独立 ID 命名空间。

协议只携带连接、权限、聊天、文件路径和审批所需的公开字段；不序列化 Hello 密码、TOTP 或设备私钥。单条消息不超过 512 KiB，命令队列最多 32 条，服务聊天环形记录最多 64 条。连接、读写都可取消，单次读写超时 2 秒；客户端读取后应答，避免服务断管时丢掉尚未读出的回复。

## 文件权限

服务接收“发送文件”请求后，使用经过验证的调用方令牌检查文件属性并实际打开文件。属性可读不代表内容可读；无内容读取权限时立即拒绝排队。异步哈希和真正开始传输时的再次打开，也各自在调用方身份范围内执行，随后恢复原线程身份。

用户令牌随该连接的待发文件流转，并在队列/会话清理时释放；查看者自己发起的共享目录下载不会继承之前本地操作的令牌。服务不能利用自身 SYSTEM 权限替本地管理器发送其无权读取的文件。

## 实现位置

- `host/service_control.{h,cc}`：身份校验、管道协议、后台客户端、审批与聊天路由。
- `host/connection_control.h`、`host/connections.{h,cc}`：本进程与服务共用的明确目标操作接口。
- `host/service_manager.{h,cc}`、`host/main.cc`：服务托盘入口、重连状态与审批界面。
- `host/worker.cc`：启动管理端点，接入 HostServer 回调，退出时取消审批与管道等待。
- `src/host/host_security.cc`、`src/host/host_server.cc`：可选的服务审批策略、用户身份下的文件读取。

## 验证和边界

复用既有 `host_parity`、`host_security` 测试目标。`--service-control` 单独运行真实管道与真实 QUIC 场景，覆盖允许/拒绝、权限上限、来源明确的聊天、完整文件内容、指定断开、端点重启后的旧 ID、管理员关闭时取消审批，以及缺少管理器时拒绝连接。

`host_multi`、`host_parity`、`host_security`、`host_i18n` 共四项回归全部通过，耗时 98.37 秒，日志为 `build/service-control-regression.log`。`chast-host`、`chast-service` 及相关既有测试目标构建通过。

临时原生控件验证放在忽略的 `build/`，没有新增 CMake 测试项目。中英文均验证了实际 Allow 权限缩减、关闭即拒绝、服务丢失后关闭过期提示，并生成检查过的 `build/service-approval-zh.png`、`build/service-approval-en.png`；日志为 `build/service-manager-ui-check.log`、`build/service-manager-ui-check-en.log`。

共用连接操作接口改造后，原本进程内连接窗口的选择、草稿、Send/Disconnect 路由验证也重新通过，日志为 `build/service-control-local-ui-regression.log`。

本轮没有安装/启动正式 Windows 服务，也没有修改机器设置。临时辅助程序使用与产品相同的工作进程身份来源，启动了真实 SYSTEM 进程并调用生产 `ServiceControlServer::start`；另一个进程在禁用管理员组及额外权限的用户模拟令牌下，调用生产管道认证与 I/O 函数。验证通过：SYSTEM 所有者/ACL 校验、真实连接与聊天、旧实例标识在服务端被拒绝、SYSTEM 专用文件立即被拒绝、普通用户文件完整传送。此检查验证的是受限线程令牌的访问权限；没有把它扩大为普通用户桌面程序启动/安装的完整验收。日志为 `build/service-system-check.log`、`build/service-system-worker.log`、`build/service-system-client.log`。

根据上述跨权限验证补强了排队前的内容读取检查，随后重新构建主机、服务和既有回归目标，并复跑 `--service-control` 通过；还验证了生产身份检查拒绝用户伪造的服务端管道。日志为 `build/service-control-file-access-build.log`、`build/service-control-last-build.log`、`build/service-control-last-test.log`。

当前面板只管理同一 Windows 会话的工作进程；服务切换到另一登录会话后，需要该会话自己的管理器。机器设置编辑、服务登录信息展示、会话内远程提权、完整多用户切换体验仍是后续工作。驱动和文件系统的同步操作仍可能延长实际断开时间。
