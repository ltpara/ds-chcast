# M10.2 — 服务端运维能力：TLS、限流与指标

本阶段补齐 RustDesk 服务端在公网部署时需要、但 chast 目前靠反向代理和外部
监控拼凑的能力：HTTP API 原生 TLS、按客户端 IP 的请求限流、Prometheus 指标，
以及对应的部署文档。协议仍为 v23，不改任何数据面语义。

## 1. 原生 TLS

`chast-server` 新增：

- `--tls-cert` / `--tls-key`：同时给出时 HTTP API 直接用 HTTPS 监听，
  否则保持明文（兼容前置反向代理的部署）。只给一个视为配置错误。
- 最低 TLS 1.2，使用 Go 默认密码套件；证书在启动时加载，私钥/证书错误
  直接退出，避免“看似启动”却无法握手。
- `/v1/server` 增加 `"tls":true|false`，便于客户端和运维确认当前端点。
- 主机/查看者代理的 `--server` 已经接受任意 `http(s)://` URL；改 HTTPS 只需
  换 URL，`--server-pubkey` 的固定语义不变。

不做：内置 ACME、客户端证书（mTLS）、HTTP/2 专项调优。证书轮换通过重启或
前置代理完成，与 RustDesk 的 `--tls-cert`/`--tls-key` 行为一致。

## 2. HTTP 限流

- 新增 `internal/ratelimit`：按 key（客户端 IP）维护令牌桶，`--api-rate`
  （默认 50 请求/秒）与 `--api-burst`（默认 100）控制；`--api-rate 0` 关闭。
  空闲 10 分钟的桶会被回收，避免地址扫描把内存撑大。
- 所有 API 路径（注册、查询、删除、统计、指标）共用同一个限流器；超限返回
  `429` 与 `Retry-After: 1`，并计入 `chast_http_rate_limited_total`。
- 默认按 TCP 对端地址计费。前置可信代理时用 `--proxy-header X-Forwarded-For`
  取最后一跳地址；该参数只在代理会覆盖该头时使用，否则可被伪造。
- 数据面不受 HTTP 限流影响：UDP 会合已有按 IP 的 `punch_request` 固定窗口
  限速，中继/载体保留连接上限与忙拒绝。

## 3. Prometheus 指标

新增 `GET /metrics`，Prometheus 文本格式（`# HELP`/`# TYPE`），配置了
`--server-key` 时同样需要 `Authorization: Bearer`；Prometheus 可用
`authorization` 配置抓取。指标：

| 指标 | 类型 | 含义 |
| --- | --- | --- |
| `chast_server_info{version,tls}` | gauge | 恒为 1，带构建版本与 TLS 模式 |
| `chast_uptime_seconds` | gauge | 进程运行时长 |
| `chast_hosts` / `chast_identities` | gauge | 当前租约数 / 永久身份数 |
| `chast_relay_ports_assigned` | gauge | 已分配的中继端口 |
| `chast_relay_ports_host_online` | gauge | 当前有主机链路/最近流量的端口 |
| `chast_relay_ports_busy` | gauge | 当前有活跃查看者的端口 |
| `chast_relay_bytes_total{direction}` | counter | `to_host` / `to_viewer` 字节 |
| `chast_relay_datagrams_dropped_total` | counter | 中继丢弃的数据报 |
| `chast_relay_busy_total` | counter | UDP 中继忙拒绝次数 |
| `chast_relay_tcp_bytes_total{direction}` | counter | 按端口载体的 TCP 字节 |
| `chast_relay_tcp_viewers_total` / `_busy_total` | counter | 按端口载体的查看者/忙拒绝 |
| `chast_carrier_hosts` | gauge | 共享载体当前主机链路数 |
| `chast_carrier_host_links_total` | counter | 共享载体主机链路建立次数 |
| `chast_carrier_viewers` | gauge | 共享载体当前查看者数 |
| `chast_carrier_busy_total` / `_rejected_total` | counter | 共享载体忙/认证拒绝 |
| `chast_carrier_bytes_total{direction}` | counter | 共享载体字节 |
| `chast_http_requests_total{endpoint,code}` | counter | API 请求数与状态码 |
| `chast_http_requests_in_flight` | gauge | 正在处理的 API 请求 |
| `chast_http_rate_limited_total` | counter | 被限流的请求 |
| `chast_http_request_duration_seconds_sum/_count{endpoint}` | summary | 平均延迟 |

`/v1/stats` 的 JSON 保持不变，继续作为人读快照；`/metrics` 面向采集器，
标签基数受控（端点来自 mux 模式，状态码有限，不含主机 ID/客户端地址）。

## 4. 测试与验收

自动化：

- `internal/ratelimit`：突发额度、按时间补充（注入时钟）、按 IP 隔离、
  空闲回收、`rate=0` 关闭。
- `internal/api`：突发放行后返回 429 与 `Retry-After`；`/metrics` 文本包含
  主机数、中继与 HTTP 计数；配置 server-key 时未认证抓取被拒绝；
  `proxy-header` 选择客户端地址。
- `cmd/chast-server`：自签证书下 `loadTLSConfig` 成功、单个参数报错；
  用真实 TLS 监听抓取 `/healthz`，断言 TLS 1.2+。
- Go：`go vet ./...`、`go test ./...`。
- 手工：`curl` 明文 / HTTPS 两种启动方式，`--api-rate` 小值触发 429，
  Prometheus 文本与 `/v1/stats` 数值一致；Release 原生构建与
  `ctest -C Release` 不回归。

### 验收标准

1. 配置证书后，`https://host:8443/healthz` 正常，`/v1/server` 的 `tls` 为
   `true`；不配置证书时行为与 M10.1 完全一致。
2. 超过 `--api-rate` 的请求得到 429，正常速率的注册/查询不受影响；
   限流计数出现在 `/metrics`。
3. `/metrics` 可被 Prometheus 解析，主机数、中继字节与共享载体计数分别与
   `/v1/stats` 一致；未带 server-key 时被拒绝。
4. 原有 Go/C++/Flutter 测试全绿，回环摘要不因本阶段变化。

## 5. 验证记录

2026-10-25，单机回环：

- 自动化：`go vet ./...`、`go build ./...`、`go test ./...` 通过。
  `internal/ratelimit` 覆盖突发额度、注入时钟补充、按 IP 隔离、关闭与空闲
  回收；`internal/api` 覆盖 429 + `Retry-After`、`proxy-header` 取最后一跳、
  `/metrics` 内容（`chast_server_info{version="chast-server/1",tls="false"} 1`、
  主机/身份/中继/载体/HTTP 计数）、未认证抓取 401 与 `/v1/server` 的 TLS
  字段；`cmd/chast-server` 用自签 Ed25519 证书建真实 TLS 监听，客户端完成
  HTTPS 探测并断言 `MinVersion` 为 TLS 1.2。
- 明文手工：`--api-rate 2 --api-burst 3`，连续 `/healthz` 得到
  `200,200,429,429`，1.2 s 后恢复 `200`；`/v1/server` 返回 `"tls":false`；
  `/metrics` 文本包含 `chast_server_info`、`chast_uptime_seconds`、
  `chast_http_requests_total`、中继与载体计数；未带 server-key 为 401；
  `/v1/stats` 与指标中的零值一致（含 `relay.shared_carrier`）。
- HTTPS 手工：OpenSSL 自签证书（SAN `IP:127.0.0.1,DNS:localhost`）配合
  `--tls-cert`/`--tls-key` 启动，`curl --cacert cert.pem
  https://127.0.0.1:18446/healthz` 返回 `ok`/200，`/v1/server` 为
  `"tls":true`；`openssl s_client` 分别协商 TLSv1.3 与 TLSv1.2，校验码 0；
  同一端口发送明文 HTTP 时返回 400 `Client sent an HTTP request to an HTTPS
  server.`；HTTPS 下 `/metrics` 未认证 401、带 Bearer 返回
  `chast_server_info{version="chast-server/1",tls="true"} 1`。
- 说明：本机 OpenSSL 3.5 默认禁用 TLS 1.0/1.1 客户端，无法从外部复现低版本
  握手拒绝；最低版本由 `loadTLSConfig` 的 `MinVersion: tls.VersionTLS12` 与
  自动化测试共同保证。
- 数据面未改动，未重跑 C++/Flutter 全量；Go 变更不影响协议 v23 与既有回环
  摘要。
