# 文件传输压缩（CFIL v2，协议 v66）

日期：2026-11-10。关闭 [发射端模块对比](host-rustdesk-module-comparison-2026-11-08.md) 与 [RustDesk 全量对照](rustdesk-full-parity-2026-11-07.md) G18/C34 的最后一个缺口“可协商压缩”。RustDesk 对照为本地固定提交 `7423dced37845c48093b6f71bd82e4a16cc8c79d`：它用 zstd 压缩文件传输块，接收端按块标记解压，剪贴板文件和已压缩容器不走压缩；本轮按相同行为实现，不引入其代码或依赖。

## 用户行为

文件传输和文件管理无需新增开关。主机下载与观看端上传在文件不小于 4 KiB、不是剪贴板文件、扩展名不属于已压缩容器时自动启用块压缩；压缩收益不足的块原样传输，因此单个文件可以混合压缩块和原始块。小文件、续传中的文件和剪贴板文件继续走原来的原始字节流，不增加块头开销。

扩展名按最后一个 `.` 之后的小写名称判断，以下类型不做压缩：`xz`、`gz`、`zip`、`7z`、`rar`、`bz2`、`tgz`、`png`、`jpg`。文件内容和文件名不被信任，压缩只是传输优化，不影响大小、摘要、落盘和权限校验。

## 主机和协议

协议版本升到 **v66**。`FileStreamHeader` 仍是 20 字节，`version` 字段取 2 表示块流；接收端同时接受 v1（原始字节）和 v2。v2 的流内容由重复块组成，每块 9 字节头：

| 字段 | 宽度 | 语义 |
| --- | --- | --- |
| `stored_size` | u32 | 线上负载字节数，1～65536+4096 |
| `raw_size` | u32 | 解压后的字节数，1～65536 |
| `flags` | u8 | bit0 = zstd；其余位为 0 |

原始块的 `stored_size == raw_size`；压缩块使用 zstd（level 1），只有 `stored_size < raw_size` 时才写压缩块，否则发送端回退为原始块。v2 只允许从文件偏移 0 开始，断点续传一律使用 v1，避免从任意偏移重建块边界。每个块独立压缩，不跨块共享字典。

接收端把 CFIL 流按块解析，块可以跨任意 QUIC 接收缓冲区；不完整的块尾巴保留到下一批字节。坏块头、未知 flags、解压长度与 `raw_size` 不符都会让该上传失败并中止流。流在块中间收到 FIN 同样报错，不会把截断的文件交给接收器。`received` 仍统计解压后的内容字节，`wire_bytes` 单独统计流内容（含块头）用于诊断；主机摘要、大小上限、`.chast-partial` 和续传逻辑不变。

两端必须同时升级到 v66；Hello 的协议版本是精确匹配，v65 及更早的端会在会话建立时被拒绝。v66 内部仍保留 v1，所以小文件、续传和剪贴板文件的路径与旧实现字节兼容。

## 验证

- `chast-protocol-test` 通过：v1 流头版本、v2 往返、v2 非零偏移拒绝、压缩/原始块头往返、未知 flags/长度越界/尺寸不一致/截断块头拒绝，以及 4 KiB 门槛、已压缩扩展名、大小写与多点文件名选择规则。
- `chast-protocol-fuzz-test` 通过：80 个解析入口，含 `file_block_header` 4000 次变异。
- `chast-file-transfer-test` 与 `chast-host-settings-test` 通过。
- Windows 原生 Release 全量构建通过（CMake “Visual Studio 18 2026”，产物在 `build/Release/`）。
- 真实 QUIC 回环 `chast-quic verify --port 45512 --file-download --file-compression` 通过：主机提供 1 MiB 可压缩 `.txt`，观看端收到完整内容并校验摘要，流被识别为 v2，CFIL 内容仅 **1776 字节**（文件大小 1048576 字节，约 0.17%）。
- 同一探针的普通下载（300 KiB 随机 `.bin`）通过并打印 **307245 wire / 307200 file 字节**：数据不可压缩，5 个块全部回退为原始块，线上只多出 45 字节块头；这证明 v2 帧不会为了压缩而放大随机数据。
- `quic_file_compression`、`quic_file_browse`、`quic_loopback` 三项 ctest 均通过。完整 Release `ctest` 第二轮 70/70 通过（1130.84 秒，本机日志 `build/ctest-v66-full-2.log`）；首轮 69/70，唯一失败为与本改动无关的既有 `quic_merged` 视频解码计数抖动，该测试单独复跑通过。完整结果见 [当前状态与计划](status-and-plan-2026-11-09.md)。

## 边界

- 只优化文件传输与文件下载；剪贴板文本/图片协议不变，剪贴板文件保持原始流。
- 仅 Windows 主机与原生工具已接线；Web、移动端等其它查看器若未实现 v2 解析，必须继续使用 v1 或先升级。
- v2 不支持从文件中途续传；中断后续传会自动退回 v1，已传输的原始字节仍然有效。
- 压缩为单块 zstd level 1，不使用长距离匹配或跨文件字典；对已压缩媒体收益接近零，只多了块头。
- 压缩不改变任何权限、路径沙箱、大小上限或摘要校验；接收端始终以解压后的字节数和摘要为准。
